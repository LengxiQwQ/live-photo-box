## 1. 唯一的产品开关（历史设计）

| 全局开关 | 持久化模式 | 行为 |
|---|---|---|
| 开启（默认） | `rebuilt` | 进入全新的重构分支。当前没有任何厂商协议实现；所有会写入或转换实况照片的操作在调用旧代码前失败。 |
| 关闭 | `legacy` | 进入完整保留的旧版兼容分支，使用当前所有既有协议逻辑。 |

开关默认开启，配置文件不存在、损坏或重置时均为 `rebuilt`。CLI 使用：

```powershell
.\lpb.cmd backend
.\lpb.cmd backend mode rebuilt
.\lpb.cmd backend mode legacy
.\lpb.cmd backend reset
```

GUI 设置页只显示同一个 Toggle。其开启状态必须明确说明“新分支暂未实现协议”；不能用“推荐”“自动”“Native 优先”等表述掩盖此事实。

## 2. 严格隔离规则

```text
                全局开关（默认 ON）
                         │
            ┌────────────┴────────────┐
            │                         │
          rebuilt                    legacy
            │                         │
  ProcessingPipelineRouter     既有兼容实现
  无协议、无 fallback           所有旧协议逻辑
  明确 NotReady 错误            仅在用户关闭开关后运行
```

### Rebuilt 分支

- 当前只建立边界和未来中性媒体管线的落点；不调用厂商协议 reader、writer、cleaner、Native protocol helper 或外部协议工具。
- `merge`、`split`、`cover`、`repair` 等实际处理入口必须先经过唯一的 `ProcessingPipelineRouter`；它在任何输出、临时工作区、复制、删除、ffmpeg/exiftool 或协议 helper 前读取一次模式。
- 当前边界抛出 `RebuiltPipelineNotReadyException`。错误必须包含操作名、说明未调用 Legacy、并告诉用户关闭开关才能使用兼容模式。
- 不能产出半成品，不能在失败后回退 Legacy，不能把 Rebuilt 的执行记录伪装为协议处理成功。
- CLI 的 `--json` 失败对象使用稳定的 `errorCode: "rebuilt_not_ready"`，并以非零退出码结束。

### Legacy 分支

- 旧版当前所有协议行为只作为兼容备份保留；它不是新管线的实现来源，也不向 Rebuilt 分支暴露协议 API。
- 新功能不得继续在 Legacy 协议代码上追加；后续需要对比时，它是行为与真实样本的参考线。
- 本阶段不以“修复旧逻辑”为验收目标；旧方法的行为差异必须对照上述 tag 说明，不能把新 Native 或中性媒体代码偷偷接入 Legacy。
- 物理目录搬迁是后续机械整理任务，不能与本阶段的开关隔离混为一谈，更不能因搬迁改变旧版字节行为。

## 3. 设置契约与迁移

配置的当前 schema 是 v3，只包含一个值：

```json
{
  "schemaVersion": 3,
  "revision": 1,
  "mode": "rebuilt"
}
```

- v1/v2 的按协议设置不再保留为运行时矩阵，也不能自动转换成任意协议的选择。
- 只有旧配置显式为全局 `legacy` 时迁移为 `legacy`；其余历史矩阵迁移为默认 `rebuilt`。这样不会在新架构下悄悄选中某个协议路径。
- 修改必须使用带命名 mutex 的原子写入；UI 变更只刷新状态，操作开始后的运行路径不得因设置变化切换。

## 4. 本阶段不做什么

本阶段明确禁止：

- 为 vivo 或任何协议建立 Native 纵向切片；
- 按协议选择 Legacy/Native，或记录 `(ProtocolKey, ProtocolRole)` 路由计划；
- 实现中性图片/视频、来源协议清理或目标协议写入；
- 修改真实样本、以产品自检代替独立验证，或把 Native 成功当成新管线完成。

这些内容分别属于后续路线，必须在 Rebuilt 分支获得真正的中性媒体能力后再按顺序引入。

## 5. 验收标准

1. 新安装或重置设置后，GUI Toggle 为开启，`lpb backend` 显示 `rebuilt`。
2. 开启时，所有处理入口在任何旧协议调用、Native protocol 调用和输出文件创建前明确失败；没有 fallback。
3. 关闭时，现有 Legacy 工作流保持可用，且不会被 Rebuilt 的未实现逻辑拦截。
4. UI、CLI、Core 只存在一个全局模式；代码、帮助和用户文档中没有每协议开关或 vivo Native preview 的表述。
5. 至少覆盖设置默认值、v1/v2 迁移、并发写入、CLI 命令面以及 Rebuilt fail-fast 边界；再构建 GUI 和 CLI。

## 6. 后续接力顺序

1. 在 `rebuilt` 内实现只输出中性图片/视频的工作区与结果模型。
2. 为中性媒体定义保留策略、真实产物验证和独立 verifier。
3. 只有中性媒体稳定后，才逐协议新增来源解析、清理或目标写入；每一项都必须独立验证，绝不回接到 Legacy。
