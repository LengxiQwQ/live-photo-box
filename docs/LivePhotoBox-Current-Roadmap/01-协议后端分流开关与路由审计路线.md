## 1. 唯一的产品开关

产品仅暴露一个全局开关，不存在每协议、每厂商、每操作或 Native capability 细粒度开关：

| 全局开关 | 持久化模式 | 行为 |
|---|---|---|
| **开启（默认）** | `rebuilt` | 进入全新的 Native-First 重构分支。所有处理入口在调用旧代码前通过 `ProcessingPipelineRouter` 进行路由控制；未完成能力明确抛出 `RebuiltPipelineNotReadyException`，绝不静默回退。 |
| **关闭** | `legacy` | 进入完整保留的旧版兼容分支，使用全部既有协议与处理逻辑。 |

开关默认开启，配置文件不存在、损坏或重置时均为 `rebuilt`。CLI 管理命令：

```powershell
.\lpb.cmd backend
.\lpb.cmd backend mode rebuilt
.\lpb.cmd backend mode legacy
.\lpb.cmd backend reset
```

GUI 设置页显示同一个 Toggle。其开启状态明确说明“新分支暂未实现完整业务管线”；禁止使用“推荐”、“自动”、“Native 优先”等模糊表述。

## 2. 严格隔离规则

```text
                全局开关（默认 ON）
                         │
            ┌────────────┴────────────┐
            │                         │
          rebuilt                    legacy
            │                         │
  ProcessingPipelineRouter     既有兼容实现
  无协议 fallback              所有旧协议逻辑
  明确 NotReady / 异常出口     仅在用户关闭开关后运行
```

### 2.1 Rebuilt 分支

- 生产路径由 `ProcessingPipelineRouter` 统一守卫。在任何输出文件创建、临时工作区建立、复制、删除、外部 CLI 工具调用或协议 helper 执行前，必须先读取一次模式快照。
- 在当前阶段，未就绪的处理管线明确抛出 `RebuiltPipelineNotReadyException`。错误信息包含操作名、说明未调用 Legacy、并提示用户在设置中切换到兼容模式。
- CLI `--json` 返回稳定的错误结构 `{ "errorCode": "rebuilt_not_ready" }` 并以退出码 1 退出。
- 绝不产出半成品文件，绝不在失败后静默回退到 Legacy，绝不将 Rebuilt 的执行记录伪装为协议处理成功。

### 2.2 Legacy 分支

- 旧版全部协议行为作为黄金基线（Golden Reference）保留，用于对比验证与日常兼容兜底。
- 禁止继续在 Legacy 代码上追加新功能或修补新特性。
- 禁止把新 Native 或中性媒体代码隐式接入 Legacy 分支。

## 3. 设置契约与持久化

配置 Schema 锁定为 v3，仅包含单一模式字段：

```json
{
  "schemaVersion": 3,
  "revision": 1,
  "mode": "rebuilt"
}
```

- 废除 v1/v2 的按协议矩阵配置；旧配置迁移时，仅当显式为 `legacy` 时保留 `legacy`，其余历史模式一律迁移为默认 `rebuilt`。
- 持久化采用跨进程命名互斥锁（Mutex）保证原子写入；已启动的处理会话在生命周期内固定使用启动时的设置快照，不随运行时配置更改而中途漂移。

## 4. 实施与验证总结

本路线已于 2026-09-01 完成施工并通过完整门禁验收：
1. `ProcessingPipelineRouter` 与 `ProcessingOperationSession` 成为所有处理入口的唯一路由守卫；
2. GUI 设置页与 CLI `backend` 命令实现了单一模式管理与原子持久化；
3. `ProcessingBackendSettingsTests` 覆盖了默认值、损坏 JSON 容错、v1/v2 迁移以及并发设置读写；
4. 全面撤销了旧 Native 纵向切片与隐式自动 fallback，彻底杜绝了 Rebuilt 分支向 Legacy 的静默回退。
