# 02A - 来源媒体识别、提取与格式转换路线

> 面向 AI Agent 执行。先扫描当前仓库最新 HEAD，复用现有能力并以实际代码为准；不要按本文档中的类名、目录或旧基线机械实现。
>
> 前置条件：Phase 01 的全局 `Rebuilt / Legacy` 路由、fail-fast 和单一开关已经完成。
>
> 02A 的完整职责仍然是：建立可独立复用的 **来源识别 / 媒体定位 / 媒体提取 / 图片转换 / 视频转换** 基础能力。
>
> **当前执行窗口只收尾“媒体格式转换”部分。** 已有 Source Inspector / Extractor 保留并只做必要 bugfix；本轮禁止继续扩展 Apple / Google / OPPO / vivo / Samsung / Huawei 等协议解析、配对、私有 metadata、Cleaner、Writer。协议在本轮唯一允许参与的方式，是提供“目标需要什么图片容器 / 视频容器 / 视频 codec”的媒体格式 requirement。
>
> 本阶段不负责彻底清除来源实况协议，也不实现任何目标协议 Writer。

> **当前实现事实（2026-09-03）**：`rebuilt` 的合成/拆分入口已经接入 `NeutralMediaBundle` 的媒体识别、提取、清理与格式转换链。本阶段当前只验证目标媒体形态（JPEG/HEIC、MP4/MOV、单文件/双文件）和源文件只读性；不把“已生成目标文件”当作来源协议已彻底剥离或目标协议已完成验证。HEIC 目标写入和完整 Native-only Target Protocol Writer 仍是后续适配项。

# 5. 协议在当前 02A 的唯一职责：提供媒体格式 requirement

当前格式转换层可以“理解协议需要什么媒体格式”，但不能理解或修改协议 metadata。

正确职责：

```text
Protocol / operation
        ↓
Media Requirement
        ↓
ImageContainer
VideoContainer
VideoCodec
optional FPS / media constraints
        ↓
Generic Image / Video Converter
```

禁止：

```text
if protocol == Huawei
    在 Converter 内写 Huawei metadata

if protocol == Apple
    在 Converter 内写 ContentIdentifier / mebx

if protocol == Samsung
    在 Converter 内处理 SEF
```

协议只回答：

> “我需要什么媒体文件组合？”

Converter 只回答：

> “把输入媒体转换成这个容器 / codec。”

如果仓库已有 profile / requirement model，直接复用；如果没有，只建立最小 typed requirement，不造大型 Manager / Factory / Strategy 系统。

# 10. 视频转换

统一 API：

```text
VideoConversionRequest
→ VideoConversionResult
```

必须明确拆开：

```text
Probe
Remux
Transcode
Normalize（只有当前确实有业务需求时）
```

## 10.1 Video Probe

Probe 至少应尽可能得到实际媒体事实：

```text
container
video codec
width / height
fps
duration
rotation
audio present / audio tracks
```

不要通过 request 或文件扩展名伪造事实。

## 10.2 Remux 优先

codec 可以保留时优先真正 remux，不重新编码：

```text
MOV / H264 → MP4 / H264
MOV / HEVC → MP4 / HEVC
MP4 / H264 → MOV / H264
MP4 / HEVC → MOV / HEVC
```

真正 remux 应是 container-aware：

```text
demux input
→ create output container
→ copy stream codec parameters
→ read packets / samples
→ timestamp rescale
→ write packets
→ finalize output
```

仅仅：

```text
copy file bytes + patch ftyp brand
```

不能视为完成的 Remux。

## 10.3 Transcode

只有 codec 不符合目标 requirement 时才转码：

```text
H264 → HEVC
HEVC → H264
```

必须是真实 decoder / encoder pipeline；不能在 target codec 不同的情况下最后仍然调用 copy / remux 然后返回成功。

可以使用成熟媒体库 / 系统 API，不自己写 codec。

encoder fallback（例如 hardware → software）是媒体执行策略，不是 Legacy / Rebuilt fallback。

## 10.4 Remux / Transcode 选择

基本原则：

```text
Source codec == Target codec
→ 优先 Remux

Source codec != Target codec
→ Transcode
```

例如：

```text
MOV HEVC → MP4 HEVC
→ Remux

MOV HEVC → MP4 H264
→ Transcode
```

# 11. 转换输出必须重新 Probe

这是当前 02A 的硬规则。

禁止：

```text
request.TargetCodec = H264
→ 直接写 OutputCodec = H264
→ Success = true
```

必须：

```text
Convert / Remux / Transcode
→ Probe actual output file
→ Validate actual container / codec / duration / fps / rotation / audio
→ Build OutputArtifact / ExecutionRecord from actual output facts
```

如果请求：

```text
MP4 + H264
```

实际输出仍是：

```text
MP4 + HEVC
```

必须 fail，不得返回假成功。

> **Output facts come from the actual output file, not from requested values.**

## 18.2 Native 负责

```text

lpb_remux_video
lpb_transcode_video
lpb_convert_image
```

Native / Native 内部媒体 backend 负责：

```text

actual video probe
container-aware remux
actual decode / encode transcode
output media validation helpers
```

## 18.3 Rebuilt 禁止外部 CLI 进程

Rebuilt 核心媒体转换路径不得运行时启动：

```text
ffmpeg.exe
ffprobe.exe
ExifTool.exe
heif-convert.exe
heif-enc.exe
heif-dec.exe
magick.exe
```

允许直接链接 / 进程内使用成熟库或系统 API，例如：

```text
libavformat
libavcodec
libavutil
libswscale
libheif
libjpeg-turbo
WIC
Media Foundation
```

原则：

> **不是为了“全手写 C++”重写 codec，而是取消 Rebuilt 核心路径对子进程 CLI 的依赖。**

Legacy 可以继续保持旧外部工具实现，不回接到 Rebuilt。
