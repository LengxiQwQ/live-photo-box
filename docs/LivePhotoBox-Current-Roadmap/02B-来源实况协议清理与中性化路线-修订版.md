# 02B - 来源实况协议清理与中性化路线

> 面向 AI Agent 执行。先读取当前仓库最新 HEAD 和 02A 的实际产物，不要按本文档中的类名、目录或旧基线机械实现。
>
> 前置条件：02A 已经提供稳定的 `SourceMediaFacts`、来源媒体定位/提取、Artifact、Workspace、图片/视频转换能力。
>
> 本阶段目标：在 `Rebuilt` 分支内精确剥离来源 Live / Motion Photo 协议，保留普通媒体和普通 metadata，最终生成真正的 `NeutralMediaBundle`。
>
> 本阶段不实现任何目标协议 Writer。
>
> **当前状态：Phase 02B 已实现，当前进行 Closeout / validation。** `rebuilt` 的拆分入口当前只执行 Inspect → Extract → Clean → Convert → Inspector，输出协议无关的中性图片与视频；既有 Apple/vivo 等目标 Writer 代码保留在隔离的 Legacy/后续范围内，不从 rebuilt 中性拆分调用。完成本文件门禁后，才单独进入 Target Protocol Writer 阶段。不要在本阶段新增目标协议 Writer。
>
> Closeout 修正已覆盖：JPEG GainMap 在清洗后重新组装回独立中性 JPEG；Samsung HEIC 清洗同步删除 XMP 中的 MotionPhoto 属性/条目并保留 GainMap/HDR 目录；真实样本产物必须通过独立图片/视频解析与解码检查。

# 4. 什么叫“来源协议清理”

目标不是：

```text
remove all vendor metadata
```

目标是：

> 删除使媒体被识别、配对、定位、编辑为 Live / Motion Photo 的来源协议数据。

默认保留：

```text
EXIF
ICC
GPS
Capture Time
Camera Model
普通 XMP
普通 MakerNote
普通 QuickTime metadata
Audio
Rotation
Color Information
非实况厂商 metadata
```

无法证明属于实况协议的私有字段：

```text
默认不删除
```

---

# 5. 禁止盲删

字符串扫描可以用于：

```text
prefilter
diagnostic
candidate detection
```

不能直接驱动 destructive edit。

禁止：

```text
看到 LIVE_ → 截文件
看到 MotionPhoto → 删除全部 XMP
看到 vivo → 删除整个 UserComment
看到 VCamera → 删除整段 XMP
看到 SEF → 删除所有 Samsung private data
```

所有删除都必须基于：

```text
SourceMediaFacts
structured container parsing
validated offsets
validated item/box mapping
validated protocol facts
```

所有清理：

# 7. Google MicroVideo V1

```text

```

02A 已确认 JPEG / MP4 范围。

Cleaner：

1. 使用已确认范围；
2. 从 workspace 图片中移除 appended MP4；
3. 精确移除 V1 实况 XMP 字段；
4. 保留其他 XMP；
5. 保留 EXIF / ICC / MakerNote；
6. 验证最终 JPEG。

# 8. Google Motion Photo V2 / Xiaomi




不能把 downgrade 记录为 preserved。

# 19. Idempotency

每个 Cleaner 必须满足：

```text
Clean(Clean(x)) ≈ Clean(x)
```

第二次执行不能：

- 继续删普通 metadata；
- 改变媒体内容；
- 生成新的 live metadata；
- 损坏结构。


# 24. C# / Native / 媒体库边界

C# 负责：

```text
ProtocolCleanRequest / ProtocolCleanResult
orchestration
workspace lifecycle
preservation plan
execution record presentation
progress
cancellation
```

Native 负责厂商协议清理的实际结构化执行：

```text
structured XMP edit
JPEG segment edit
HEIF item edit
ISO-BMFF box edit
SEF reconstruction
UUID removal
MOV metadata track manipulation
protocol-specific reader / cleaner / writer helper
```

原则：

```text
C# = control plane
Native = protocol / container execution authority
```

不要形成：

```text
GoogleCleaner.cs + google_cleaner.cpp
VivoCleaner.cs + vivo_cleaner.cpp
SamsungCleaner.cs + samsung_cleaner.cpp
```

两套并行厂商实现。

Rebuilt 核心协议处理不得运行时启动：

```text
ExifTool.exe
ffmpeg.exe
ffprobe.exe
heif-* CLI
magick.exe
```

允许 Native 内直接链接成熟库或使用系统 API，例如 libav* / libheif / libjpeg-turbo / WIC / Media Foundation；也允许项目自己的结构化容器实现。Legacy 旧兼容路径可以继续保留现有外部 CLI。

# 32. Agent 完成后的动作

完成实现后：

1. 全仓搜索旧的散落 Cleaner 逻辑；
2. 确认 Rebuilt 新路径统一；
3. 确认 Legacy 行为未改变；
4. 检查 backend bypass / fallback；
5. review git diff；
6. 运行 `scripts/verify.ps1 -Scope Full`；
7. 修复代码层面失败；
8. commit；
9. push；
10. 检查最新 CI；
11. 输出简洁报告：
   - 各协议 Cleaner 状态
   - 新增/复用 Native 能力
   - Preservation / idempotency 状态
   - tests / Full Verify / CI
   - 未实现内容
   - commit hash

> **核心原则：只删除来源实况协议，不破坏普通媒体；Cleaner 不重新识别媒体范围，不重新设计 Backend，不写目标协议。**
