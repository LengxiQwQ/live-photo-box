# 自动化测试脚本与发布验证路线

> **状态**：待执行 / 横跨整个重构过程  
> **审计基线**：`master @ 7e27c62297b6065bdfa82fdf16ae7e0fd2c2b6c0`  
> **目标**：建立一套能证明“全局分支真的隔离、格式转换没有隐形损失、协议清理没有误删、最终协议产物真的正确”的自动化测试体系。当前第一阶段只证明 `rebuilt` 在调用 Legacy 前停止，以及 `legacy` 可由用户明确选择。  
> **原则**：实际产物优先；Execution Record 优先于文本日志；生产代码不能给自己发合格证；Unknown 不能算 Pass
> **当前阶段范围**：先测试单一全局开关、默认 `rebuilt`、设置迁移和 fail-fast；基础 JPEG/HEIC/MP4/MOV 转换、来源协议清理和真实协议产物留到后续阶段。HDR/GainMap 不作为完整保真发布门禁；BestEffort 降级可以允许，但必须在 Preservation Outcome、Execution Record 和验证报告中可见，绝不能显示成完整保留。
>
> **架构基线说明（P0.2）**：当前架构统一为 Rebuilt-only，Legacy Runtime 与全局开关已彻底移除。测试脚本中使用的系统 ffprobe/ExifTool 属于独立的 Verification-only 测试验证依赖，绝非产品运行时依赖；独立 ProtocolVerifier 路线按 P0-P9 阶段有序建设，当前执行以 `00-当前阶段总纲-Rebuilt中性媒体底座收官路线.md` 为最高准则。

# 2. 最终测试层级

```text

L3 Legacy vs Native Differential
L4 Media Conversion / Cleaning
```

# 9. L3：Legacy / Native Differential

已有 differential test 继续保留。

### 9.1 Byte Exact

以下适合 byte-identical：

```text
Huawei 60-byte tail
Samsung deterministic SEF trailer
vivo deterministic metadata rewrite（固定 ID / fixture）
MP4 box strip
HEIF location parser result
JPEG XMP injection（固定输入/固定 XMP）
```

### 9.2 Semantic Equivalent

以下不一定 byte-identical：

- UUID 随机；
- creation time；
- encoder metadata；
- box order允许规范内差异；
- XMP prefix；
- metadata serialization。

比较：

```text
结构
语义字段
资源范围
hash of media payload
外部工具结果
```

而不是整个文件 hash。

### 9.3 每迁一个 Native capability，必须同 PR 增 differential

不能：

```text
先迁实现
以后再补测试
```

# 10. L4：图片转换测试矩阵

本阶段只测试**基础图片格式转换基础设施**。

每个 case 关注：

```text
input
requested output
actual output
media validity
dimensions
orientation
基础 EXIF / ICC（能验证的部分）
```

基础矩阵：

| Input | Output |
|---|---|
| JPEG | JPEG |
| JPEG | HEIC |
| HEIC | JPEG |
| HEIC | HEIC |

### 10.1 Same-format 不允许无意义重编码

例如：

```text
HEIC → HEIC
JPEG → JPEG
```

如果没有改变像素的必要，优先验证：

- 文件仍可读；
- dimensions 正确；
- orientation 正确；
- 基础 metadata 没有明显异常；
- 通用转换器没有强制无意义重编码。

### 10.2 HDR / GainMap 本阶段不是门禁

测试输入如果碰巧带 HDR / GainMap：

```text
现有代码能保留 → 可以继续保留
不能保留 / HDR 转换失败 → 自动走普通 SDR 路径
```

当前测试**不要求**：

- HDR byte/semantic 保真；
- GainMap 必须保留；
- HDR→HDR 互转；
- 用户确认降级；
- HDR loss report。

唯一要验证的是：

> 如果容器中存在 GainMap / auxiliary item，基础解析器不能把它误认为 MotionPhoto 视频，也不能因此算错视频范围。

此外，若 BestEffort 路径将 HDR/GainMap 降级，测试必须断言 `PreservationOutcome == Downgraded` 并保留原因；若请求为 `RequirePreservation`，断言任务失败、源文件和最终输出均不被破坏。

HDR 专项以后再增加完整测试 matrix。

# 15. L6：独立 ProtocolVerifier

完整协议发布验证不能使用生产 writer 自己的 reader 当唯一 oracle。

推荐：

```text
tests/LivePhotoBox.ProtocolVerifier/
```

独立实现最小只读 parser。

不能链接：

```text
LivePhotoBox.Native
LivePhotoBox.Core protocol writer/parser
```

最终交付应是由 Python 调度的独立 C++ 可执行程序（可放在 `tests/ProtocolVerifier/` 源码目录，但不是引用产品程序集的测试项目）。它只实现最小只读 parser 和规则 ID，不进入 GUI/CLI/Native 发布包，不调用生产 Reader/Writer，也不把 ExifTool 当唯一 oracle。

### 15.1 外部工具

```text

```

### 15.2 输出规则


# 17. 样本管理

真实样本永远只读。

建立 inventory：

```json
{
  "id": "samsung-s23-jpeg-01",
  "protocol": "samsung",
  "format": "jpeg",
  "sha256": "...",
  "device": "...",
  "private": true
}
```

测试开始：

```text
verify source hash
→ copy to workspace
→ only modify copy
```

测试结束：

```text
verify original hash unchanged
```

inventory 还要记录每个协议、容器和操作所需的最小真实样本；缺样本、缺工具或缺独立规则必须把该项标为 `NotVerified`，不能因未执行而给绿色。

# 23. 每个 PR 的最低门禁

### 修改 Router / Settings

必须通过：

```text
Static
Settings
Routing
CLI backend
```

还必须覆盖 settings revision snapshot 与 source/target role matrix。

### 修改 Native protocol

必须通过：

```text
Native contract
Differential
Routing
Protocol-specific tests
```

### 修改 Media converter

必须通过：

```text
conversion
basic metadata preservation
container/codec validity
real regression（如适用）
```

HDR/GainMap 当前不作为必过项；已有 HDR regression 可以继续跑，但不能因为 HDR 自动降级阻塞本阶段。

### 修改 Cleaner

必须通过：

```text
clean positive
preservation negative
idempotency
malformed
real sample
```

若 Cleaner 允许 BestEffort HDR/GainMap 降级，额外断言报告准确标识 downgrade；`RequirePreservation` case 不允许把损失伪装为成功。

# 24. 发布门禁

某协议 Native 可以从 disabled 变成用户可选，至少满足：

```text
Routing Pass
+
Native Contract Pass
+
Differential Pass
+
Real Artifact Pass
+
Required ProtocolVerifier Rules Pass
+
Device Verified（若该厂商需要）
```

不能因为：

```text
C++ 函数写完了
```

就开放开关。

Native 开关首次开放前，还必须有该协议所有承诺 role 的 availability contract、无直接 Interop 绕过证明，以及双文件协议的 bundle publication failure test。

# 25. 最终“绿色”必须代表什么

当报告显示：

```text
PASS
```

它至少意味着：

1. 设置确实选择了预期 backend；
2. 没有 hidden fallback；
3. 没有 Legacy/Native 混用；
4. 输入原文件未被修改；
5. 输出媒体结构合法；
6. 格式/codec 符合请求；
7. 重要 metadata 按 policy 保留；
8. 来源实况协议确实被清理；
9. 目标协议产物由独立规则验证；
10. 要求真机的协议已经有对应设备证据。

而不是仅仅：

```text
CLI exit code = 0
```

## 26. 一句话原则

> **测试不是证明“程序没报错”，而是证明“它确实走了指定实现，并且真实产物在字节、媒体、协议和设备层都符合预期”。**
