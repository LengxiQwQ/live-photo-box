# 自动化测试脚本与发布验证路线

> **状态**：进行中 / 横跨整个重构过程  
> **目标**：建立一套能证明“全局分支完全隔离、媒体转换无隐形损失、协议清理无误删、最终实况产物完全符合厂商规范”的自动化测试体系。  
> **原则**：
> - **真实产物优先**：独立解析产物二进制结构，生产代码不能给自己发合格证；
> - **Unknown 不能算 Pass**：无法解析或未验证项保持 Unknown，严禁伪造默认值；
> - **CI 绿不等于全机型通过**：CI 环境排除 `Category=RealSamples`，真机样本与 Release 门禁是不可替代的发布前提。

---

## 1. 架构原则与后端事实

### 1.1 唯一后端模式
产品仅支持两种后端：
- `rebuilt`（默认）：Native-First 新架构，无静默 fallback，能力缺失明确 fail-fast；
- `legacy`：v2.2.1 黄金基线兼容实现。

测试体系严禁引入历史残留的 `Auto` / `Custom` / `PreferNative` / 按协议路由断言。

### 1.2 生产代码与独立验证器隔离
- 生产代码（Product Reader / Writer）严禁给自己生成的实况照片颁发合格证；
- 独立验证器（Protocol Verifier / Integration Script）不链接产品 internal 逻辑，独立通过标准 ISO-BMFF / JPEG 解析及系统外部工具（ExifTool, ffprobe 等）对物理产物进行独立取证。

---

## 2. CI 现状与 Real-Sample 发布门禁

### 2.1 CI 真实边界
在 GitHub Actions CI（`.github/workflows/build.yml`）中：
```powershell
$coreTestFilter = if ($env:CI -eq 'true') { 'Category!=RealSamples' } else { $null }
```
- **公开 CI 环境不包含私有真机实测样本**，因此 CI 中的 `dotnet test` 会自动排除 `[Category=RealSamples]` 专项测试。
- **CI 绿（Green）仅证明基础单元测试与开源合成样本通过，不能单独证明真实 OEM 样本的媒体链路已完全通过**。

### 2.2 Phase 02A 及后续阶段的 Release 门禁
创建任何 Release 标签或判定阶段验收前，必须在本机执行全量 Release 门禁：
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify.ps1 -Scope Release -Configuration Release
```
该门禁必须成功完成：
1. `LivePhotoBox.Native` x64 编译与 ABI Smoke Tests；
2. 包含 `[Category=RealSamples]` 在内的全部 Core 单元测试与真机样本测试；
3. 包含 `[Category=RealSamples]` 在内的全部 CLI 单元测试；
4. 真实机型样本 CLI 全流程集成测试（`scripts/testing/run-cli-integration-test.py`：Merge / Split / Cover / Repair）。

## 3. 媒体转换与协议测试准则

### 3.1 视频转换测试要求（严禁仅测“文件存在”）
视频转换与 Remux 测试必须使用独立 ISOBMFF 解析器或 ffprobe 严格断言：
1. **实际容器格式**：MP4 (`ftyp: mp42/isom`) 或 MOV (`ftyp: qt  `) 与请求完全一致；
2. **实际编码格式**：实际 Codec (`H264` / `HEVC`) 与请求完全一致（`requested == actual`）；
3. **真实时长与分辨率**：视频宽度、高度、时长大于 0 且在误差范围内；
4. **音频轨与旋转角度**：音频流存在性、旋转角度 (`0/90/180/270`) 与源媒体保持一致；
5. **严禁将未转码的 Passthrough 伪装为转码成功**。

### 3.2 图片转换测试要求（严禁仅测“文件存在”）
图片转换测试必须严格断言：
1. **合法文件头部**：JPEG (`FF D8`) 或 HEIC (`ftyp: heic/mif1`)；
2. **尺寸与方向**：图片分辨率与 Orientation 正确保留；
3. **Preservation Report 真实性**：
   - 严禁“转换成功即断言元数据已保留”；
   - 仅对实际测试取证保留的 EXIF / ICC / MakerNote / GainMap 标记为 `Preserved`，其余如实标记 `Downgraded` 或 `Unsupported`。

## 4. 7 层自动化测试架构

```text
┌────────────────────────────────────────────────────────┐
│ L7: 独立协议验证器与真机验证 (Independent Protocol Verifier)│
├────────────────────────────────────────────────────────┤
│ L6: CLI 真机样本全流程集成测试 (run-cli-integration-test.py)  │
├────────────────────────────────────────────────────────┤
│ L5: 来源协议清理与中性语义模型测试 (Phase 02B)            │
├────────────────────────────────────────────────────────┤
│ L4: Native 媒体基础与格式转换测试 (Phase 02A)            │
├────────────────────────────────────────────────────────┤
│ L3: Native ABI 与 Smoke 测试 (build-native.ps1)        │
├────────────────────────────────────────────────────────┤
│ L2: Router 路由与 Rebuilt Fail-Fast 集成测试 (Phase 01) │
├────────────────────────────────────────────────────────┤
│ L1: 设置契约与单元测试 (ProcessingBackendSettingsTests)   │
├────────────────────────────────────────────────────────┤
│ L0: 静态架构与 Interop 隔离规则测试                      │
└────────────────────────────────────────────────────────┘
```

### 4.1 各层职责与测试用例分布

- **L0 静态架构**：
  - 断言业务层不绕过 `ProcessingPipelineRouter`；
  - 断言业务层不直接 P/Invoke 底层协议私有导出。
- **L1 设置与单元测试**：
  - `ProcessingBackendSettingsTests`: Schema v3 解析、默认值 `rebuilt`、损坏 JSON 容错、v1/v2 迁移、跨进程互斥锁并发保存。
- **L2 Router 路由测试**：
  - 断言 `rebuilt` 模式下所有处理入口在触碰输出前抛出 `RebuiltPipelineNotReadyException`；
  - 断言 CLI `--json` 返回 `rebuilt_not_ready` 错误码并退出码为 1；
  - 断言 `legacy` 模式下完整调用保留的 v2.2.1 既有逻辑。
- **L3 Native ABI Smoke 测试**：
  - `NativeRuntimeTests`: C ABI 加载、版本协商、产品版本号匹配、内存分配与句柄释放。
- **L4 媒体基础测试 (Phase 02A)**：
  - `SourceInspectorTests`: 10 大机型实况特征探测与偏移量解析；
  - `SourceExtractorTests`: 只读分块切片提取与源文件 SHA256 不可变性校验；
  - `ImageConverterTests`: WIC 转码与同容器结构复制；
  - `VideoConverterTests`: 视频探测、MP4/MOV Remux 与 H.264/HEVC 转码断言；
  - `MediaWorkspaceTests`: 事务工作区生命周期管理与安全清理。
- **L5 协议清理测试 (Phase 02B)**：
  - 10 大机型实况协议标记清除；
  - 幂等性断言：`Clean(Clean(x)) == Clean(x)`；
  - 恶意/损坏文件输入防御；
  - 非实况普通元数据未误删断言。
- **L6 CLI 真机样本集成测试**：
  - `run-cli-integration-test.py`: 对 `designs/各个机型测试/` 真实样本副本运行完整的 CLI `merge / split / cover / repair` 工作流并生成报告。
- **L7 独立协议验证器 (Protocol Verifier)**：
  - 按 `docs/实况照片协议完整分析报告.md` 的二进制规范对最终产物进行独立逐字节与盒结构核验。

---

## 5. 验收标准

1. **日常构建**：`scripts/verify.ps1 -Scope Fast` 快速通过 Native、GUI、CLI 及单元测试。
2. **完整构建**：`scripts/verify.ps1 -Scope Full` 通过桌面 MSBuild 完整解决方案编译与全部单元测试。
3. **发布门禁**：`scripts/verify.ps1 -Scope Release -Configuration Release` 通过包括真机样本在内的全量集成测试。
4. **视频/图片真实性**：所有媒体测试必须深入音视频/图片内部结构取证，严禁表面断言。
