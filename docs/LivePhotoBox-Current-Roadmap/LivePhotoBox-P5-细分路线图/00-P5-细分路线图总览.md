# Live Photo Box — P5 细分执行路线图总览

> **定位：** `P5 — Converter Reliability` 的二级执行路线图；只细化，不降低上位 Roadmap、Neutral Media Contract 或 Bootstrap。
> **交付平台：** Windows x64。Converter contract 保持 backend-neutral、platform-neutral。
> **进入条件：** P4 已由当前用户在 2026-09-18 明确完成；P5 不重新进行 P4 的 build、dependency 或 video-backend 技术选型。

## 1. P5 的产品边界

P5 把已清理、已验证的中性媒体资产转换成满足 `MediaFormatRequirement` 的媒体能力。它只依赖：

```text
Neutral media facts + requested format requirement
+ approved Media Backend contracts
+ approved Platform/transaction primitives
```

它不把 WIC、Media Foundation、libjpeg-turbo、libheif、lcms2 或 libav* 作为公开产品语义。库只属于 backend implementation；backend identity 只能用于诊断和证据，不能决定协议或 preservation truth。

P5 不做来源协议重解析、不修改 P1–P3 authority/transaction 语义、不让 Target Writer 按来源厂商分支，也不恢复任何 production external media CLI。

## 2. 继承且不可重开的 P4 决策

| 能力 | 已冻结 owner | P5 的责任 |
|---|---|---|
| ISO-BMFF structural truth 与 container remux | LivePhotoBox Native / project-owned parser | 显式选择并验证 remux；不可把语义 authority 交给通用 codec。 |
| JPEG / HEIC 像素 codec | Native libjpeg-turbo / libheif + HEVC codec foundation | 定义转换语义、metadata mapping 与 post-validation。 |
| SDR H.264 / HEVC transcode | Windows Media Foundation，software-forced | 接入、诊断并验证；不是另一次 backend 对比。 |
| HDR / 10-bit video preservation-required transcode | 已冻结 minimal-libav capability | P5 负责明确 dispatch、分发和真实证明；未提供时如实 Unsupported，不得 retry 到其它 backend。 |
| HDR / GainMap | Native Data Plane | 消除 result-affecting C# Magick.NET pixel math；语义/container truth 仍由项目掌握。 |

## 3. 执行轮次与停止点

| 轮次 | 目标 | 结束条件 |
|---|---|---|
| R0 | Contract / Boundary / Acceptance Baseline | 语义词汇、gap/evidence matrix、角色边界与后续验收被文档化；不改 production code。 |
| R1 | Converter Contract + Execution Truth | requests/results/ExecutionRecord 能表达 operation、保真组成、降级、selected capability、fallback/unsupported 与失败类别。 |
| R2 | Ordinary Image Reliability | JPEG/HEIC passthrough、lossless transform、reencode 的 metadata/orientation/ICC 结果由后验验证证明。 |
| R3 | HDR / GainMap Semantic Conversion | JPEG Ultra HDR ↔ HEIC GainMap 的 Native pixel/data path、Strict/BestEffort 与真实语义证据闭环。 |
| R4 | Color / High-Bit-Depth Policy | 区分 ICC copy、metadata map、真实 color transform；绝不只改标签。 |
| R5 | Video Converter Reliability | frozen capability 显式预分派；remux 与 transcode 分离；audio/rotation/timing/color/HDR/diagnostics 逐项验证。 |
| R6 | Converter Integration / Closeout | `MediaFormatRequirement` 到 Neutral consumption 的公开路径矩阵收口，完成 P1–P4 受影响回归。 |
| Audit / Verify / 外部门禁 | 独立审计、可复现验证、当前用户/外部 Gate | 只有明确 ACCEPT 后 P5 才 completed，P6 才 eligible。 |

每个 R 结束后主 Agent 必须停下并报告；不得自动开始下一轮。

## 4. 一致的语义与成功定义

每个公开路径必须落入以下之一：`passthrough`、`container remux`、`lossless transform`、`lossless transcode where meaningful`、`lossy reencode`、`color transform`、`HDR/GainMap conversion`、`degraded output` 或 `unsupported`。

Codec 成功、文件可打开、产品自身 reader 读回 output，都不等于 `Preserved`。保真结果至少要能如实组合表达 metadata、ICC/color、HDR/GainMap、audio、timing、orientation 与 auxiliary ownership；HDR 变 SDR 必须是 `DegradedToSdr`，Strict 必须失败。

## 5. 本地 Agent 边界

| 角色 | 允许 | 禁止 / 输出 |
|---|---|---|
| Implementer | 只在当前 R 的 TASK 范围改生产代码、测试与 evidence；运行 targeted build/test。获授权的子轮可创建或更新自己的 P5 二级路线图、TASK 与 evidence。 | 不得削弱上位 Roadmap 或 Neutral Media Contract，不得把 mock 当 RealSample、不得自称 P5 ACCEPT。输出 implementation handoff。 |
| Fresh Auditor | 默认只读；从当前代码、调用链和真实验证反向取证。 | 不信任实现者摘要；不修 production。输出 `READY FOR VERIFICATION` 或 blocker。 |
| Fresh Verifier | 不改 production；在精确 HEAD 上检查 scope、build、test filter、样本、独立 validator 与 runtime/package evidence。 | 不把 skip、synthetic 或产品 self-read 说成 RealSample / independent validation。 |
| 当前用户 / External Gate | 作最终 ACCEPT / REJECT。 | 本地任何 PASS 都不能替代该权力。 |

## 6. 真实样本与独立验证总规则

`designs/各个机型测试/` 永远只读；使用 `.ai-tmp/cache/samples/` 缓存和 `.ai-tmp/workspace/` 的确定性工作路径。P4-v1 的 17 个 verifier-supplied、hash-locked 文件保持原身份；新增能力需要另建有版本的 P5 corpus extension，不能静默替换。

- JPEG/HEIC preservation：项目结构检查 + 独立 decoder/metadata reader。
- HEIF GainMap：项目 parser 必要但不足；须独立 HEIF graph/metadata/decode 检查，设备语义还需 reference/device evidence。
- JPEG Ultra HDR：独立 JPEG/XMP/MPF/GainMap 结构验证 + decode/render/reference evidence。
- Video：项目 re-probe + 独立 media probe，对比 duration/timing、container/codec、audio、rotation、color、bit depth/HDR。
- 外部 CLI 仅作离线验证/研究，绝不进入 production path。

## 7. 当前已知风险（非 R0 修复项）

1. `StandardHdrConversionService` 仍有 result-affecting Magick.NET pixel math，且 HEIC auxiliary decode/metadata seams 未完成；这是 R3 blocker。
2. frozen minimal-libav HDR/10-bit capability 尚未打包或接入 production dispatch；这是 R5 blocker，不是重开选型的理由。
3. 当前 image/video execution records 尚不能完整表达 P5 语义；这是 R1 work。
4. P4-v1 HEIC primary 是 8-bit；任何真正大于 8-bit still-image claim 需授权的新 RealSample，否则标记 coverage gap。
5. `ImageConversionRequest` 未携带 trusted Neutral media facts/auxiliary semantics，现有 image façade 会重新 inspection；R1 必须划清 semantic authority 与 post-output integrity inspection。
6. `VideoTranscodeService` 的 legacy façade 不能如实表达 operation：`copy` 进入 H.264 string mapping，`RemuxAsync` 又无条件报告 remux；R5 必须修复而 R0 只记录。
