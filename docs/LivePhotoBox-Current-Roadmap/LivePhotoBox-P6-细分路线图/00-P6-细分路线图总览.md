## P6 要交付什么

把来源媒体按下面顺序稳定地产生中性语义结果：

```text
权威 Inspect/plan → Extract → Clean → 仅在格式要求需要时 Convert
→ 对最终媒体 post-clean inspection/probe → NeutralMediaBundle
```

成功 Bundle 必须根据最终媒体语义表达 orientation、timing、color/HDR、auxiliary 关系、artifact manifest、hash 和 preservation outcome。Windows 当前可继续用 path-backed artifacts；Windows HANDLE、COM/WIC/Media Foundation 对象、backend 私有指针、Win32 错误码、源路径含义不能成为 Neutral correctness state。Backend identity 只能用于 diagnostics/ExecutionRecord。

P6 是 source-side 中性管线，不实现 Target Writer、目标协议布局、P7 压力活动或 P8–P10 工作。

## 每个逻辑单元的开工与留证

1. 运行项目根目录的 reconcile 脚本，核对 `.ai/state.json`、active TASK、Roadmap revision；记录当时 HEAD 和完整 `git status --short`。若 TASK/revision 不一致，先停工重新规划，不把旧 TASK 当新方向的授权。
2. 核对 `tests/fixtures/realsamples-manifest.json` 的 SHA-256、P4-v1 17 个样本身份及 route grouping。样本只从 `.ai-tmp/cache/samples/` 读取，累积结果只用固定路径 `.ai-tmp/workspace/P6/`；`designs/各个机型测试/` 永远只读。
3. 查阅本路线图所属 TASK 的范围、对应 N1–N14、对应 acceptance ID，以及 [P6 测试问题与待办账本](01-P6-测试问题与待办账本.md)。本轮记录检查过的账本 revision 和 issue IDs；不适用时写出具体原因。OPEN/BLOCKED 条目不能因为 filter、文件迁移或测试重命名而消失。
4. 一次只完成一个逻辑单元。单元结束运行与改动直接相关的 targeted build/test，确认实际发现并执行了声称覆盖的测试类别；记录真实命令、退出码、发现/执行/通过/失败/跳过数量、输入与输出身份、相关文件和可读执行输出。必须 RealSample 的项目缺失或被跳过就是未完成。
5. 通过当前唯一项目连接器发送执行元数据，让配对 ChatGPT 通过 MCP 读取实时 workspace、diff、相关文件和可读执行输出后独立审查。消息不粘贴代码、diff 或日志。收到修复计划后只改对应范围、重跑受影响检查并再次交审。

## 测试与证据规则

- 每个新 P6 测试名包含 `P6_`，以便 `FullyQualifiedName~P6_` 实际选中。Synthetic、Controlled、RealSamples、IndependentValidation 分开报告。
- Core/test 构建和测试按 active TASK 的 Release x64 命令执行；过滤器必须经 discovery/TRX 核对发现、执行、失败、跳过数量。还要运行 TASK 点名的 `NeutralMediaServiceTests|P5R6_|CleanerBoundaryArchitectureTests` 相关回归，并确认这些类别确实被 filter 覆盖。
- 真实样本复核 frozen SHA 与长度。样本只读；不得下载、复制替代品或改写身份。有效既有 P3/P5 证据只在 source、input、tool、scope 和 verifier 不变时复用。
- 运行证据累计放在 `.ai-tmp/workspace/P6/`。正式关闭时按 TASK 建立不覆盖的 `.ai-tmp/evidence/P6/` 快照。长期决策、未决事项与找回线索必须写在仓库文档，不只存在易失目录。
- 不因保险重复成功且输入与验证器未变的耗时门禁。P0–P10 全项目 suite 仅在用户接受 P10 后执行。

## 完成判定与禁止越界

- 当前 P6 Roadmap、active P6 TASK、Neutral Media Contract N1–N14、所有适用 P6-A1–A16 和真实 route matrix 全部满足，且问题账本没有无解释的 OPEN/BLOCKED 项，才可申请 P6 Audit/Verify。
- Auditor 必须从新鲜独立上下文只读取证；Verifier 不修 production source。每者报告适用账本 revision 与 issue IDs。
- Audit/Verify 本地 PASS、ChatGPT 的本地审查完成、CI 通过，都不能单独写成 P6 complete。只有 designated External Chief Gate 对被审查的精确身份明确 `ACCEPT` 后，才能更新 P6 phase state 和清除 active TASK；随后仍不自动开始 P7。
- 不改 master/P6 Roadmap acceptance、Neutral Contract、protocol fact、manifest/hash、validator/profile/threshold、上游语义或阶段顺序；不做 Target Writer/Validator、P7 压力工作、P8–P10。涉及方向、公开 Contract/ABI/API 或验收改变时停止并请求决策。
