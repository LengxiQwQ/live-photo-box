## 1. 权威与边界

本细分路线图只展开主路线图的 P7「系统高压与回归测试」campaign。适用顺序为当前用户明确指令、主路线图与必要 Contract、本细分路线图、当前 TASK。细分路线图不得改变主路线图、Neutral Media Contract 或全局规则的验收条件。

正式平台为 Windows x64。P7 要证明 Windows production system 稳定，并保持 V4.0 Portable Core/backend boundary。P7 不要求 Linux、macOS 或 Web 产品验收。P7 期间不开始任何后续阶段。

## 2. 不可变的 P7 Exit Criteria

逐项以主路线图 08-P7 文件的原文为准，不增加、删减或放宽：

1. 无已知 silent corruption；
2. malformed 不 crash；
3. ambiguous 不猜；
4. transaction/failure 安全；
5. batch/large file 无明显泄漏；
6. backend fallback 可解释；
7. Portable Core 边界未回退；
8. dependency graph 无未批准扩张；
9. regression corpus 可重复。

验证报告必须对每项关联实际源码、实际运行结果和可复核证据。注释、测试名、历史报告或本产品 Reader 自证不能替代证据。存在未覆盖项时应如实报告，不得把 PARTIAL 写成 PASS。

## 3. P7 有限执行顺序

每个R单元先形成有限计划并按当前用户选择的决策方式执行。LOCAL_OWNER由本地主代理规划与集成；只有用户明确选择CHATGPT_COLLAB才使用ChatGPT协作。Windows-specific或正式产品验证仍由本地执行并保留真实证据。Roadmap要求的独立closure使用未参与候选修改的fresh只读上下文；实现者不得冒充独立审查。审查发现只在当前授权范围内修复并补受影响验证；review通过不自动激活下一单元，原有External Chief Gate保持。此段落实当前用户已明确的本地所有权授权，不改变验收条件。

| 顺序 | 单元 | 目的与边界 |
| --- | --- | --- |
| R0 | 基线、语料与攻击面 | 绑定 P7 起始身份；验证既有 P4-v1 样本身份及 P6 RealSample 回归；盘点攻击面、后端、依赖与 Portable Core 边界；登记覆盖缺口。R0 不修产品缺陷。 |
| R1 | malformed、mutation、collision | 针对截断、冲突/重复元数据、命名空间/协议碰撞、伪标记、重叠范围、非法 box、unsupported HEIF、损坏 SEF、错误配对、尾随垃圾等构建或复用确定性语料；断言 malformed 失败关闭且歧义不猜。 |
| R2 | transaction 与文件系统故障 | 检查任意阶段取消、输出锁定、磁盘耗尽及 temp/publish 故障；区分真实 ACL/share-lock/filesystem 证据与仅能说明状态机的 fault injection。 |
| R3 | backend 执行真实性 | 检查相同语义请求的所选 backend、真实 ExecutionRecord 和有效结果；仅在已有两个 approved backend 且同一语义/保留契约可比时做差分。不得引入 fallback。 |
| R4 | 大文件、批量和持续运行 | 以可重复负载观察批处理内存增长及大文件/长时运行稳定性；不新设性能 SLA，不以短时 mock 替代真实负载。 |
| R5 | Portable Core、依赖与 C ABI 回归 | 检查 Windows.h 泄漏、production 外部 CLI、未固定 runtime dependency、未决 codec 重复、C ABI 类型边界。非 Windows/Emscripten compile smoke 是可选项，不构成产品支持承诺。 |
| R6 | 集成回归与九项标准证据索引 | 固定复现命令和语料身份，整合 R1–R5 的真实证据，逐项说明九项 exit criteria 的结果、限制和证据位置。 |
| R7 | 独立 Audit、Verify、外部 Gate | 在独立 fresh context 中先做只读 Audit，再由另一 fresh context 做只读 Verify；两者均 ready 后向指定外部 Chief Gate 提交绑定相同身份的证据并等待明确 ACCEPT。仅指定外部 Chief Gate 对同一绑定身份给出的明确 ACCEPT 能关闭 P7。 |

各单元的具体样本、命令、目标、筛选范围、断言、失败处理和证据清单须在相应 TASK/单元计划中基于当前源码、测试、manifest 与 Contract 写明。不得因为缺样本、筛选排除、skip 或环境限制而把必需覆盖改为通过。

## 4. 语料和证据规则

P7 campaign 的七类语料固定为 real device、malformed、mutation、collision、large-file、HDR/GainMap、codec/backend。R0 先逐类记录现有来源、身份、预期覆盖、测试入口及缺口。不得虚构样本或用 synthetic/mock 冒充 RealSample。P7 只消费已获批准且已预置在确定性 .ai-tmp/cache/samples/ 下的样本；不得从 designs/各个机型测试/ 复制或写入，不得公开下载、合成、替换或从未批准来源取得。临时工作产物持续放在确定性 .ai-tmp/workspace/P7/；自 `.ai-tmp/evidence/README.md` 生效后，新产生的正式门禁/恢复运行结果按 `.ai-tmp/evidence/P7/<Task>/run-<N>/` create-only 保存。既有临时证据保持原路径和身份。若要求的样本缺失或身份校验失败，状态为 BLOCKED/FAIL。

允许 ffprobe、ExifTool、参考实现、系统解码器、独立 parser 和真实设备作为独立验证证据，但不得将这些 CLI/工具引入 production runtime。报告须明确区分 Mock/Unit、Synthetic、RealSample 和 IndependentValidation；保留 before/after 身份或语义证据，并依据适用 Contract 证明 preservation。

## 5. P7 结束条件

R0–R6 均完成其经审查的 TASK，九项 P7 exit criteria 均有明确、可复核的证据结论；fresh 独立 Audit 与独立 Verify 均完成；指定外部 Chief Gate 对确切 HEAD、工作区 identity、Roadmap revision 和证据明确返回 ACCEPT。外部 ACCEPT 后只关闭 P7、清理 P7 active task 并停止本工作，不定位、规划或启动后续阶段。
