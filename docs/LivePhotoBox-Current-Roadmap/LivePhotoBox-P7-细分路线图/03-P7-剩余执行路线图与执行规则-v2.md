# 2. 执行模型调整

P7 后续工作严格分成三层。

## 2.1 NON-FORMAL / SCRATCH

普通开发、调试和执行通道验证，使用：

- `.ai-tmp/scratch/`
- `.ai-tmp/workspace/P7/`

适用于：

- compile check
- targeted test
- test discovery
- PowerShell / Python / JSON helper 自检
- evidence generator 自检
- BuildId / output identity 检查
- 路径、参数、环境检查
- 普通源码编译错误
- 测试 helper / fixture 修复

这些结果：

- 不算正式 PASS
- 不替代正式 evidence
- 不分配 `run-N`
- 不允许据此声称 R1/P7 完成

目的：

**先让执行通道健康，再消耗正式 run。**

不得因为脚本 typo、参数错误、路径错误、helper bug、普通编译错误而不断制造正式 run。

---

## 2.2 FORMAL RUN

只有 candidate 已完成合理的 scratch validation，并且有真实机会执行到目标产品路径时，才分配：

`.ai-tmp/evidence/P7/<Task>/run-<N>/`

正式运行开始前至少确认：

1. 当前代码完成必要 scratch build；
2. 目标 test discovery 正常；
3. 执行脚本语法和参数已自检；
4. BuildId / output destination 无冲突；
5. evidence destination 不存在；
6. run-N 是 fresh create-only；
7. 本 run 有明确产品验证目标。

正式 run 一旦启动：

- PASS / FAIL / BLOCKED / 中断都永久消费；
- 不覆盖；
- 不删除；
- 不重用；
- 保存真实命令、退出码、discovery/executed/pass/fail/skip/notExecuted 和必要原始证据。

正式 run 用于**验收证据**，不用于调试脚本。
