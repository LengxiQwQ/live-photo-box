## R1 共享 Native 结构与事务

目标：结果字节与协议语义属于 C++20 Portable Core；C# 仅保留 typed 编排、结果、命名/目标地与事务协调。复用已有 JPEG/TIFF/EXIF、XMP、HEIF、ISO-BMFF、SEF structural primitives；先核实际能力，缺什么补什么，不重写第二套二进制引擎。不要为未来平台实现额外 backend。

实施范围：

- 建立目标结构模型，描述合法 parent/child、namespace、item/track、版本/必需字段、pair identity、时间语义、extent/reference、index/size/relocation；输入只来自 Neutral manifest + profile。
- 传递 artifact identity/role、owner protocol、selector、semantic、fingerprint 与实际所需 mutation authority 到真正写入位置。原始 source、外来 temp、不同 asset 的替换与 plan replay 必须在 mutation 前拒绝；旧 utility、公开 service/Native primitive 也不得成为旁路。
- JPEG/XMP 合并只改 target-owned/live 语义，保留合法非 live XML、EXIF、ICC、HDR/GainMap 和未知数据；处理多 packet、extended XMP、命名空间冲突、大小上限。不能全删 XMP 或把旧 packet 原样复制成重复标准 packet。
- HEIF item graph 与 ISO-BMFF track/sample table 按合法结构重建引用/偏移；大小溢出、stco/co64、extended size、重复/shadow、dangling/overlap、非法 hierarchy fail closed。固定格式字段的编码常量可存在，不能拿样本绝对位置作 authority。
- 用 P4 filesystem/temp/flush/publish 原语建立完整 staging 生命周期和必要多文件 transaction/reconciliation；失败、取消、晚到 foreign、输出冲突、部分动作无假成功、无半发布，源和 foreign 不变。先冻结验证与 publish 间身份连续性设计，不能 check 后按 path 换文件。
- ABI 若现行模型无法表达，先提供最小 POD/opaque handle/显式缓冲区/结果码方案与兼容影响，请用户决定后再改；不能默认已有规划等于 ABI 扩展授权。新增生产依赖同理。

验证：Native targeted 结构/越界/relocation/authority 测试；真实工作副本上受影响的 transaction/取消/冲突；需要实际 ACL/share-lock/非可写失败的行真实触发，注入单独标为状态机。共享 foundation 未变部分复用 P7 证据，新 Writer/mutation 路径必须补证。高风险设计先由 fresh 只读 reviewer 查 authority、preservation、ABI、安全和所有可达入口，实施完成后审实际候选。

## R2 独立 Target Validator 与发布门禁

目标：Writer 返回 success 不再是发布依据。Writer 将完整产物写入受控 staging，flush/close；Validator 新开读取实际完整文件/文件组，产生 fresh observed facts，经独立规则判定，再允许 transaction 发布。发布后按 Contract 核对身份和必要重开，不能通过后换字节。

允许复用 trusted read-only parser；必须独立 validation orchestration、observed facts、target rules 和 PASS/FAIL。不得直接信任 Writer 的 DTO、内存模型、输出 hash 声明、metadata 缓存或 Source Inspector 最终 source 分类。Generic decode/probe 辅助证明媒体有效，不能替代目标结构规则。

实施范围：

- Validator 输入为实际产物身份、明确 target/version/profile 和所需期望语义；实际结构从新读取的字节获取，覆盖 artifact group 成员、配对 ID、主图/视频范围、codec/container、时序、direction、HDR/auxiliary ownership。
- 规则与 Writer serializer 分离，正例和 mutation 反例可独立验证；每族之后补该族规则，框架完成不意味着规则全齐。
- 结果至少可区分 structural conformance、generic media validity、preservation、device acceptance 四个维度；设备没测不能由本地 PASS 提升。错误定位 Stage/Capability/Failure category；GUI/CLI/history 保持诚实，不用 Unknown 掩盖已知非法结构。
- 生产发布 gate 覆盖实际服务和 lower-level 可达入口；验证失败不得发布；fresh reopen 失败、wrong target、duplicate identity、pair mismatch、残留 binding、验证后替换、取消及部分组失败必须受控拒绝。

验证：独立构造坏输出、单字段/引用/长度/时间/配对 mutation、直接调用 lower service 的拒绝、文件替换/关闭重开与事务真实结果。RELEASE-004 原输入必须在 R3 修复后生成唯一合法目标；制造出的 duplicate packet 则仍严格失败且不发布。不能把“成功返回再被 Split 拒绝”当作新成功契约。

完成条件：真实生产路径存在 fresh reopen → independent conformance → safe publish gate，独立 Reviewer 确认 Validator 不自证；当前未实现协议仍明确拒绝/隔离。产品行为或 Contract 改变按用户决定实施；不将规划本身视为该授权。
