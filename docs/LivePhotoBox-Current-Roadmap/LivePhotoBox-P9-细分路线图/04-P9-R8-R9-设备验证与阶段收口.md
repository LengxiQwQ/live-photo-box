## 验证分层与执行纪律

1. Unit/Mock/Synthetic：结构模型/规则/状态机、变异反例，单列非真实来源。
2. RealSample：原始17文件按实际路径适用性选择，缓存工作副本、before/after身份；含双文件要记录成员，不把17文件写成17条target成功。
3. IndependentValidation：脱离Writer最终判定的结构解析、离线工具、独立媒体解码/时序/色彩/HDR/metadata保留；工具只离线，不进入生产运行依赖。
4. 真实生产/失败/集成：实际Native/managed路径、CLI子进程和必要GUI，真实ACL/share-lock/非可写等适用失败；mock只能补状态机。
5. RealDevice：上表冻结条件，真实导入/查看/播放，未测如实NOT_RUN。
6. Final bounded aggregate：所有实现完成后的最终候选，只覆盖P9新Writer/Validator与受影响边界，其他有效结果复用；不是全产品suite、P0–P8重验或无理由soak。

准确命令/filter/方法/参数化行和预期数量在实现后先 discovery、runner资格检查，再冻结执行清单；现在不编造未来测试名/通过数。构建沿用 canonical CMake/vcpkg 与 Windows Release x64 managed链，绑定实际加载Native/C ABI。受影响Native先构建测试；SkipNativeBuild仅在明确复用正确binary时使用。必要portable语义/边界检查不是新增Linux产品支持。

每行必须记录官方条款、R/target/variant、NEW/REUSED/AFFECTED_PENDING/NOT_RUN、源码/运行库/输入/输出身份、完整command/filter、直接child exit、TRX total/pass/fail/skip/notExecuted、真实触达阶段、拒绝分类、源/foreign/owned残留、独立结果和复用理由。Required missing/skip/零测试、上游拒绝却声称下游执行都不能PASS。原失败保留；同因两次formal run后先诊断，不盲目消耗run。
