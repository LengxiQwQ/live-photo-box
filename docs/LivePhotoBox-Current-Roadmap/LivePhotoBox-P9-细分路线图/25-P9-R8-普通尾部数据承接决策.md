# P9-R8：普通尾部数据不能随实况清理一起丢弃

状态：已确认缺口；当前用户已明确批准“允许新增兼容接口（推荐）”。旧接口与含义保留，不增加生产依赖，不改变保留标准，不授权删除数据。批准的是兼容承接通道，实际正向支持仍须完成实现和验收。

一加直出与改过封面的两个真实来源在主图、增益图、视频之外还有附加拍摄/编辑数据。当前来源解析只根据两个长度字段之差把视频后的区域标为协议尾部，提取时未承接；改过封面的来源还有一部分同类私有记录处于视频内的 `comm` box，不能把视频长度字段当成整个记录系统的语义分界。尚无证据允许删除这些普通内容，也不能仅凭记录名字或任意字符串命中认定它们是实况绑定。

影响：这两个来源的旧 CLI 成功和局部媒体测试不能证明完整保留，不作为可交付的完整来源支持。保留旧输出、失败和原始样本；在合法承接完成前，生产提取必须明确拒绝未承接的布局，不能继续丢字节后报告成功。其他来源的有限验证不因此自动作废。

建议采用通用、有身份与所有者的普通元数据承接方式。来源侧核对合法记录目录、范围、重叠、重复、偏移基准及覆盖账，精确区分允许清除的实况绑定与必须保留的普通内容。Neutral 之后仅传递普通数据、容器、关系与实际可表示能力，不按来源品牌分流。Writer 和 Validator 必须验证实际载体、hash、关系及目标范围；无法证明可安全承接则拒绝。不得整尾删除、无条件整尾追加、偷偷增加边车文件，或声称其他品牌相册支持原厂编辑功能。

现有 `PreservationCarrier` 只描述源范围和 hash，不是附加写入授权；现有目标请求也没有通用 materialized metadata artifact/placement authority。推荐允许新增兼容的公开 Contract/ABI 通道，旧接口及旧含义保留，不增加生产依赖，不改变保留策略。批准后先冻结字段、版本、大小、所有权及事务条件，再实现和独立验证；这不是授权任意元数据替换或未证实的有损转换。具体二进制、逐样本记录及复现位于 `.ai-tmp/workspace/P9/target-writers/R8/cli-integration/source-boundaries-v1/` 与同工作根 `documentation/`。

完成条件：真实来源完整覆盖账、普通数据与关系在 Neutral/最终成品的可追踪保留、旧 ABI 兼容与 malformed/TOCTOU/回滚验证、正式 CLI 全来源/变体、GUI 和独立复核齐备，并由用户完成适用的设备 A/B 验收。Native 局部 Copy 测试通过不能替代这些条件。
