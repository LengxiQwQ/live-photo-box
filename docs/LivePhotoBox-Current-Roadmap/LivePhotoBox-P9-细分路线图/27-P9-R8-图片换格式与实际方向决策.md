# P9-R8 图片换格式与实际方向决策

2026-10-29，当前用户在兼容图片转换接口确认中明确更新产品要求。本记录是后续图片施工的现行决定，历史运行及其限定证明保持原状，不追溯改成新策略通过。

## 用户决定

允许新增兼容图片转换接口，保留旧接口，不增加生产依赖。能保持原格式、避免无必要重新压缩时优先保持；确需 JPG↔HEIC 或实际方向变换时允许重新生成画面，并诚实记录实际操作和保留结果，原文件不变。

用户特别澄清：转换后的画面本身应当方向正确，不能依赖接收应用读取 rotation 标签才显示正确。按已知真实旋转/镜像关系实际变换图像；最终有效方向为正常方向，不再留下要求应用额外旋转/镜像的有效标记。允许将既有方向字段归正常值并同步 HEIF 方向属性与主图/适用 GainMap/辅助图关系；不能处理了画面却继续保留旧旋转，造成重复旋转。优先用可证明的无损变换；确需像素重编码时明确记录，不能伪报为逐字节保留。未知、冲突或不可证实方向不猜测，继续遵循当前未知方向授权及转换适用性门槛。

用户同时明确：“也不是绝对地说所有信息都要保留。能保留的就保留，保留不了的以及不重要的，具体看情况。”因此不能把“每个 metadata 字节永久不变”当作用户宗旨。应按内容实际用途、可表示性和损失影响判断：画面、声音、观看方向、HDR/色彩和影响观看/编辑的内容优先保障；普通附加信息能保留就保留。确有不可表示项时需要完整识别、记录具体影响及实际保留/损失结果，不能把未知内容自行认定为垃圾，不能因其原厂名称或来源品牌删掉，也不能丢失后伪报完全保留。重要功能、明显数据损失或尚不能判断影响的决定仍按根规则交用户决定；可逆、明确无重要功能影响的常规处理自主执行并事后说明。

## 范围与验证

本次提问的直接上下文为 JPG↔HEIC 图片转换及其兼容证明接口。先落实图片实际方向与 metadata/HDR/auxiliary 证据。视频方向作为 R8 的观看验收继续核对；本记录不冒称已有 Copy 结果已变成像素旋转结果，也不把只读视频矩阵直接当作已转正的画面。

CLI、GUI 共用 Core。证明必须绑定真实来源和阶段产物身份/hash、转换操作、完整适用内容清单和实际前后对应关系。原 ABI/证明类型语义保留；精确新增 POD/事务字段先冻结再施工。既有 kind2/3 XMP 证明不能升级成全图 metadata/像素/颜色保留证明。失败、未验证和不适用项分别记录；安全发布与原文件只读不变。

图片转换后的方向、镜像、主图/增益图对齐与 HDR 重建需要真实独立结构/解码/显示证据，最终仍需完整目标格式包、GUI 和用户设备 A/B。旧 257 项、矩阵 v8、有限 Copy 等结论各自绑定旧候选/策略，不代表本次方向要求已验收。R8 未完成，不进入 P10，不 push/tag/release。
