# P9-R8 未指定方向的显式处理决定

当前用户明确批准：对已查看且画面正向的“小米.jpg”，按当前存储画面直接转换，不旋转，把无效方向标记改为正常方向；原照片不动。其他方向不明照片不会自动套用。此前严格拒绝未知方向的默认行为保留。

## 控制面与结果含义

增加明确的 `UseStoredPixels` 处理选择，默认 `Reject`。正式 CLI 的单任务参数、共享 Core 请求均须显式携带；批量入口不能把这一个样本的选择自动传播给其他任务。不得按品牌、路径、文件名或 hash 自动启用，也不允许转换失败后自动改用此选择。

这是用户选择图像方向，不能报告“原始方向元数据已经证明正确”。执行记录单列原方向未指定、用户选择当前像素方向、实际归一化和输入/输出身份与 hash。后续普通转换使用重新核对的正常方向资产；原始来源的未知方向状态和本次选择仍可追溯。CLI 和 GUI 继续使用同一 Core 服务。

## 有限 Native 能力

先在 Source→Neutral 清理完成后，对独立副本执行有限的同格式 JPEG 方向归一化。不修改用户源文件，不重压缩像素。只接受唯一合法 Exif IFD0 的 Orientation、count1、SHORT或LONG、值0；规范方向1..8、缺字段、未知非零值、重复/别名/损坏结构拒绝。LONG0改为SHORT1，保留原字段长度及所有其他字节；已知普通 XMP 若存在冲突方向值不能忽略。HDR、附加图片、索引及普通信息不因这一步被删除、重排或重新编码。

新增兼容只接受此选择的入口 `lpb_resolve_unspecified_jpeg_orientation_v1`：请求80B/version1，handling1，reserved0，绑定真实源 artifact identity及完整SHA256；旧接口不变，无新生产依赖。沿用240B/version1证明存储布局，但新入口只产生kind3/flags1/operation4（仅元数据归一化），不重新解释旧kind1普通转换、kind2 HDR转换、旧80B XMP证明或operation2无损DCT。proof source_orientation0/output_orientation1；源/目标长度相同，实际Creator identity、完整源/目标hash、Exif预期/实际hash一致。证明仅在全文件除已授权类型/值字段外逐字节保持、主JPEG完整解码通过、源租约及目标无覆盖发布成立后产生。旧运行库缺此符号明确失败。

## 验收与等待

需要正式 CLI 真实来源、源文件不变、显式选择缺失时仍失败、相同格式和后续换格式、完整字节/图片/附加资产独立核对，非法值/结构、错身份、stale/replay、取消、同路径/目标已存在、proof容量及Core拒绝伪造证明等定向回归，fresh独立Review和另一Verify。该步骤不豁免仍未接通的附加图片换格式或任何设备/GUI条件。具体样本字段及运行证据保留在 R8 工作根 `documentation/s2-jpeg-directions-v1.json`，不作为生产分流条件。

当前为已批准、有限实现及验证完成状态。正式 CLI 的三种适用格式、默认拒绝、源不变、独立图片/信息/HDR/视频核对、定向回归及 fresh Review/另一 fresh Verify 已完成；详细回执在 R8 工作根 `cli-integration/stored-direction-unit-receipt.md`。这不代表 GUI、手机或任何完整协议已验收。
