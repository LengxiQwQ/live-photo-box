## 2. 用户已经决定的事（不要再讨论）

1. **实况能用优先。** 第一轮（A 轮）只要求：手机能识别为实况、能完整播放、有声音（来源有声音时）、方向正确、封面画面正确、基本 EXIF 带过去。
2. **新增“兼容档”，A 轮默认使用。** 输出按目标手机原生习惯来（容器、视频编码、音频编码、轨道组成），带不过去的内容不阻止出文件，但必须在结果里逐项列为“未带过去”，不能写成“已保留”。这正是中性媒体契约 N9 已允许的 BestEffort（如实报告损失后继续），不是降低契约。
3. **音轨不追求原样。** 能正常播放、声道数不减少（立体声保持立体声）即可；需要时转成目标常用编码（通常 AAC）。辅助视频轨、元数据轨（mebx/Mett 等）、厂商私有记录在 A 轮不需要带过去。
4. **HDR 在 A 轮不阻塞。** 现有能力能带过去增益图就带；做不到时输出 SDR 主图并记录 `DegradedToSdr`，留到 B 轮。
5. **先转换成功，再整包测试。** 每个目标的**全部来源 × 全部既定格式变体**必须正式 CLI 生成成功且快速自检通过，才放进平铺取件目录。生成/自检失败是电脑端开发问题，先修；修不动就报告阻塞，不交成功子集凑整包、不自行删除失败行或转 B 轮。手机不识别是之后的兼容问题，两者分开记录。
6. **完整单元做完再测，以真实成品为主。** 测试时机、必要边界、收口与复核统一见 [03-测试与复核规则](03-测试与复核规则.md)。没有明确用途的测试不运行；失败后局部修、局部测，不重复完整流程。
7. **不死磕，也不甩给用户测。** 无进展时按根规则 0.2 停止该问题的试错，主动说明原因、尝试、影响和建议。可以做本阶段不受影响的工作，但失败仍阻止整包交付，不能靠提高模型强度或换代理继续耗。
8. **顺序：** 身边设备组 小米/Google → OPPO/一加 → Apple → vivo X200 及更早，全部 A 轮通过后再做商场组（新 vivo X300 起、三星、华为、荣耀）和 Fusion 的 A 轮，最后统一做 B 轮。
9. **完整保留档（原严格模式）保留。** 已经做完的 Mett / SEF / scene / 编辑记录 / HDR 精确证明等成果全部留在完整保留档和 B 轮使用，不删除、不回退。
10. **小米先做完电脑端。** 设备现在在朋友处；取消阶段 0 必交 X0–X5 诊断包的安排，不要求用户提前找设备。电脑整包通过后报告，设备不可用就保持手机未测；经用户继续后可准备下一个目标，不跳过小米的最终真机验收。
11. **转码视频真正转正。** 按实际方向旋转像素，再清除/归零旋转信息；苹果和三星优先覆盖，但不按品牌写特判。具体边界见 01 §1.1。
12. **每段做完停下来。** 阶段 0、每目标电脑整包就绪、每目标 A/B 收口分别停下来报告，等用户继续；不一口气做完整个 R8。商场组也逐目标报告，最后集中交包。汇报不增加测试或审查次数。

## 3. 不变的硬规则

- 架构不变：原始输入 → 来源识别/提取/精确清理 → Neutral → 目标媒体准备 → 结构化 Writer → 重开校验 → 安全发布。
- 目标规则可以按目标协议定；中间通用处理只按实际媒体语义分流，**禁止按来源品牌/型号/文件名/hash 写特判**。
- 交付成品只能由正式 CLI 生成；脚本只能调度 CLI、复制、出清单、做独立检查，不能自己改成品。
- 来源文件永远只读；发布失败不留半成品；双文件不能只发布一半。
- 不能把“没带过去”写成“已保留”；不能用电脑测试代替用户手机结果。
- 不 push / tag / release，不进入 P10；本地 commit 只在一个目标 A 轮收口时做一次。

## 5. 什么时候自己做，什么时候问用户

**自己做：** 常规修复、实现方式选择、兼容档里各目标的媒体参数（以该品牌原生相机直出样本为依据）、测试安排、失败归类、文档维护、本地开发小工具（不进入产品和安装包）。

**先问用户：** 新增生产依赖或改变打包内容、改公开 ABI、扩大或缩小支持的目标/格式范围、删除用户可见功能、不可逆操作、需要用户手机或账号。问的时候用白话说清楚影响和建议。

**不要问：** 已在本文件 §2 决定的事、普通失败、“要不要生成测试包”。
