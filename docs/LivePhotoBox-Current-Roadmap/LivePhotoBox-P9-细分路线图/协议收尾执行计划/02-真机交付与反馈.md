# 真机整包交付与反馈规则（实况优先版）

依据 2026-10-28 用户决定（整包、平铺、命名）和 2026-10-30 最新细调：转换/自检失败先修好，整包电脑通过再交付；小米暂缓手机诊断；只做必要测试。此前“有失败项也交付”的安排已撤销。

## 1. 一个平铺取件文件夹

固定目录：`.ai-tmp/workspace/P9/target-writers/R8/device-delivery/`

- 所有已准备目标的当前成品**直接放在这一个目录里，不建子文件夹**。
- 只放当前有效版本；旧版本、诊断文件、日志、manifest 原件放在取件目录之外的 `documentation/`、`results/` 等内部目录。
- 不压缩，不另外复制到桌面或盘符根目录，不替用户操作手机或上传。
- 整包全部生成并自检通过后主动给路径和测试说明，停下来报告，不问“要不要生成测试包”。小米设备暂不可用时先内部备好，报告“电脑通过、手机未测”，不催用户找设备。

## 2. 整包怎么生成

由一个调度脚本完成（脚本只调度正式 CLI，不自己改成品）：

1. 对当前目标的**每个来源 × 每个格式变体**调用一次正式 CLI（兼容档），按 `coverage.json` 的 targets 清单逐项执行。
2. 每个成功成品自动跑快速自检（[03-测试与复核规则](03-测试与复核规则.md) §2）。
3. 成品先留在内部工作目录；生成/自检失败写内部开发失败清单，定位和修复。**全部既定行通过后**才发布该目标完整取件包，禁止边生成边交成功子集。失败不能由旧版同名成品充数；旧包须能明确识别版本，不得宣称它是新候选整包。
4. 交付生成 `测试清单.csv`、`开始测试.txt`；`失败清单.csv` 留在内部 `results/` 供开发定位，报告阻塞时给白话摘要，不要求用户拿失败项去测。
5. 写内部 manifest：每行的 CLI 命令、退出码、输入/输出 hash、自检结果、`notCarried` 摘要。

**交付前提是该目标全部既定行转换成功且快速自检通过。** 不能转换与手机不兼容是两类问题；前者由开发先解决，后者在完整成品上由手机确认。不得为凑齐整包自动缩减范围。

## 3. 文件命名

格式：`案例ID__源-来源协议-来源格式__到-目标协议版本-目标格式__r修订号.扩展名`

```text
G2-001__源-Apple-HEIC+MOV__到-GoogleV2-JPG+MP4__r1.jpg
AP-014__源-小米V2-JPG+MP4__到-Apple-HEIC+MOV__r1.heic
AP-014__源-小米V2-JPG+MP4__到-Apple-HEIC+MOV__r1.mov
```

- 案例 ID 前缀按目标区分（G2 = Google V2、G1 = Google V1、OP = OPPO、AP = Apple、V2X = 旧 vivo……），编号稳定，修订后只改 `r` 号。
- 双文件同 basename，只差扩展名。
- 名称保持简短、Windows 合法；媒体特征（编码、HDR、降级）写在测试清单里，不塞进文件名。
- 某个设备对导入文件名有实际要求时按设备要求，并在清单里保留对应关系。

## 4. 交付说明与内部失败记录

**`开始测试.txt`**（白话，一屏以内）：这次是哪个目标、第几版、多少个文件、哪些是新修的要重测、在手机上怎么导入、看哪几项、怎么反馈。

**`测试清单.csv`** 列：案例ID、文件名（双文件写两个）、来源、目标及格式、是否原生变体、电脑自检、HDR/降级说明、本次是否需测、手机结果（用户填或 AI 按反馈填）、失败现象。

**内部 `失败清单.csv`** 列：来源、目标格式、失败阶段（提取/媒体转换/写入/校验发布/自检）、一句话原因、已试办法与结果、影响行数、下一步（修复中 / 无进展已报告 / 待必要决定）。转换失败不自动转 B 轮；修复记录和失败证据保留。

## 5. 用户怎么反馈

用户可以直接说“G2-003 不识别，G2-007 没声音，其余正常”，或填测试清单。AI 负责把结果写进 `coverage.json` 和 TODO。

A 轮请用户看：
1. 能否识别为实况；
2. 能否完整播放，有无卡顿/黑屏/截短；
3. 来源有声音的，成品有没有声音；
4. 方向对不对；
5. 封面画面对不对；
6. 照片详情里拍摄时间、机型、GPS 等基本信息在不在。

相册内封面编辑可以顺便看，有问题记入 B 轮，不阻塞 A 轮。

## 6. 修复后交付

- 修复后重新生成受影响的行，替换取件目录中对应文件（`r` 号加一），没变的文件原样保留，`开始测试.txt` 写明只需重测哪些。
- 换版前把旧版成品和 manifest 移到内部历史目录。只移动 manifest 明确属于 AI 生成的文件；发现用户自己放的文件或无法确认来源的文件就停下报告，禁止递归清空目录。
- 一个目标交付后停下来报告；用户继续或明确授权并行准备后，才准备下一个目标。下一个目标也必须整包通过后放进同一平铺目录。

## 7. 商场组

新 vivo、三星、华为、荣耀的整包全部准备好后一次交付，附一张“需要找的品牌/机型/系统版本”清单，方便用户一次出行集中测。现场没有的机型记为未完成，不影响其他已测结果。

## 8. 状态说法

分开记录电脑与手机状态：电脑为“未接通 / 生成中 / 转换失败 / 自检失败 / 整包通过”；手机为“未测（可注明缺设备）/ 测试失败 / A 轮通过”。收口另记“待复核 / A 已收口、B 待做 / 全部完成”。电脑有成品不等于手机通过；一台手机的结果只代表那台手机和相册版本。
