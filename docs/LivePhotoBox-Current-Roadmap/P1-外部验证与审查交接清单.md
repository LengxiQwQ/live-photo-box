# Live Photo Box P1 外部验证与审查交接清单

> **用途：** 交给一个 fresh、独立的外部 AI/Verifier，复验指定 commit 或工作区中的 P1 Source Inspector。
> **分工：** 实现者与独立 Verifier 分离；Verifier 只审查和验证，不修改 production/test。
> **阶段边界：** 只验证 Roadmap P1。不运行全量测试，不修 P2–P10，不用后续功能未实现导致的失败扩张 P1 范围。
> **验收权：** 外部 AI 只能给出 `ACCEPT`/`REJECT` 证据；只有当前用户/维护者可以宣布 P1 completed。

---

## 1. 给外部 AI 的直接提示词

```text
你是 Live Photo Box P1 的 fresh 独立 Verifier/Auditor。不要相信实现者报告、注释、测试名称或历史 ACCEPT。
从 production code 和真实命令结果反向取证。

只审查 Roadmap P1 Source Inspector Reliability。不修改 production code、测试、Roadmap 或样本；
发现失败时停止对源码的任何修复，只记录可复现证据。

协议事实以 docs/实况照片协议分析文档/ 全部文档为准。
这些文档来自真实样本，不重复做协议逆向；
只校验当前文件、容器、metadata owner、range、pairing 和错误合同是否符合已有协议事实。

严格执行本文档第 2–8 节。保存所有命令、exit code、TRX/日志、测试计数、
RealSamples 发现/执行/通过/失败/跳过数和样本前后 SHA-256。
任何 P1 失败、skip、缺样本、没有证据的“理论正确”均为 REJECT。
后续阶段失败只记录到 13-未来工作规划.md，不在 P1 修复。
```

## 2. 验证前锁定身份与范围

在任何编译之前创建证据目录，并记录当前工作区：

```powershell
$EvidenceDir = ".ai-tmp\evidence\P1"
New-Item -ItemType Directory -Force -Path $EvidenceDir | Out-Null
git rev-parse HEAD | Tee-Object "$EvidenceDir\head.txt"
git status --short | Tee-Object "$EvidenceDir\status-before.txt"
git diff --stat | Tee-Object "$EvidenceDir\diff-stat-before.txt"
git diff --name-status | Tee-Object "$EvidenceDir\diff-names-before.txt"
```

范围要求：

- 在开始前明确记录本次被验收的 commit、分支和工作区差异；最终结论只对该身份有效。
- `backup/p1-f20aa88-before-rework` 仅作可恢复备份，不是验收对象，不得整体 merge/cherry-pick 回 P1。
- 验证者不得执行 `reset`/`restore`/`checkout --`，不得 commit/push。

必读权威：

1. `AGENTS.md`
2. `docs/LivePhotoBox-Current-Roadmap/00-重构总纲-唯一执行路线.md`
3. `docs/LivePhotoBox-Current-Roadmap/02-P1-来源检测器可靠性.md`
4. `docs/实况照片协议分析文档/` 全部文档（用户确认、按厂商拆分保存的协议事实）
5. `.ai/tasks/P1-source-inspector-reopen/TASK.md`

只跑 P1 定向验证，不跑完整 Core、全项目或 P2–P10 suite。全项目总验收统一延后到 P10 被当前用户明确 ACCEPT 之后。

## 3. Production code 独立审查矩阵

必须每项从真实调用链取证，不能只看测试名。

| ID | 必须证明的 P1 事实 | ACCEPT 条件 |
|---|---|---|
| P1-A01 | production 协议 authority 只有 Native SourceInspector | `LivePhotoProtocolDetector` 若保留，只能是 Inspector 薄适配；GUI/CLI/Discovery/Cover/Edit/Split/Merge 不得使用 managed byte/XMP/tail/CID 启发式得出协议真相 |
| P1-A02 | XMP namespace URI 兼容且安全 | 只对已知 Google/Container/Item/OPPO/Vivo URI 做受限的空白、包裹引号、`http/https` 兼容；仍然依据实际 namespace scope 解析 prefix，错 URI 或局部 prefix 重绑定不得冒充 |
| P1-A03 | XMP owner 绑定 | protocol attributes 与 `Container:Directory` 必须属于同一个唯一 `rdf:Description` owner；跨 Description 拼接、多 owner、shadow Directory 均 fail closed |
| P1-A04 | 所有标准/扩展/HEIF XMP item 都被处理 | 不存在 first-packet fallback；额外相关声明、duplicate、shadow、conflict 失败，真正无关 XMP 可保留 |
| P1-A05 | vivo X300 semantic gate 完整 | 仅接受 `[Primary, MotionPhoto]` 或 `[Primary, GainMap, MotionPhoto]`；版本、顺序、Semantic、MIME、Length、JPEG/GainMap/MP4 精确 range 均校验；2-item 不生成 GainMap facts |
| P1-A06 | Samsung HEIC `mpvd -> nested sefd` 正确 | candidate 沿合法 box hierarchy 找到 nested `sefd`；`MotionPhoto_Data` entry 精确指向同一视频 range；重复/影子/非法路径失败 |
| P1-A07 | Apple CID 只有正式 owner | JPEG/HEIF 只接受唯一 ExifIFD `0x927C` MakerNote；IFD0、其他 APP1、未引用/重复/影子 MakerNote 失败；MOV 只读正式 QuickTime metadata hierarchy |
| P1-A08 | Apple/Vivo pairing 不依赖文件名 | 改名但 metadata 匹配应成功；同名无关文件不得确认；单一 candidate 的 typed Pairing mismatch 只淘汰该 candidate，malformed/metadata ambiguity/I/O 继续上抛 |
| P1-A09 | JPEG/HEIF/MOV/MP4 primary media 严格校验 | 不用 `ftyp`/`moov`/`mdat` 字节命中代替容器层级和 sample table；所有引用 range 有界、不溢出、不重叠；ISO-BMFF 支持合法 `ctts` 与一致的 absolute/rebased offset mode |
| P1-A10 | 可疑 JPEG 尾部 fail closed | EOI 后非声明数据、矛盾 length、损坏 primary 加合法尾部不得变成 `NonLive` 或 Confirmed |
| P1-A11 | C ABI/C# failure contract 稳定 | Unsupported/Ambiguous/Malformed/InvalidArgument/I/O 及 stage/capability 穿过 C ABI 与 managed mapping，不靠字符串解析，`NonLive` 不吞不确定性 |
| P1-A12 | GainMap/auxiliary facts 有正式关系 | representation/ownership/relationship/range 来自 HEIF item graph、JPEG marker/XMP 关系，不由 magic string 命中冒充，不重复 materialize identity |

## 4. 允许的 P1 编译与定向测试

以下是允许的最大范围。不运行全量 Core suite、UI automation、Cleaner/Extractor/Converter/Writer/Repair 测试或 `scripts/verify.ps1` 的全量 gate。

### 4.1 环境健康检查

Doctor 只检查当前环境和工具是否具备，不验证产品功能。当前 P1 必需的本地工具缺失才是 blocker；未参与 P1 的可选 MCP 或远程文档服务异常只记录，不得单独推翻 P1。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\.ai\doctor.ps1 -ActiveOnly 2>&1 |
  Tee-Object "$EvidenceDir\01-doctor.log"
```

### 4.2 Native Release x64

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\native\build-native.ps1 `
  -Configuration Release -Architecture x64 2>&1 |
  Tee-Object "$EvidenceDir\02-native-release.log"
```

### 4.3 Core P1 定向测试

```powershell
$P1Filter = "FullyQualifiedName~NativeStrictMediaValidationTests|FullyQualifiedName~NativeMediaServiceIoContractTests|FullyQualifiedName~SourceInspectorRoutingRegressionTests|FullyQualifiedName~SourceInspectorTests|FullyQualifiedName~NativeRuntimeTests|FullyQualifiedName~AppleMakerNoteReaderTests.ReadContentIdentifier_|FullyQualifiedName~HeifBoxParserDifferentialTests|FullyQualifiedName~VivoDualFileProtocolDetectionTests"
```

### 4.4 P1 RealSamples 独立结果

```powershell
$SampleRoot = "designs\各个机型测试"
Get-ChildItem -LiteralPath $SampleRoot -Recurse -File |
  Sort-Object FullName |
  Get-FileHash -Algorithm SHA256 |
  Select-Object Path, Hash |
  Export-Csv "$EvidenceDir\real-samples-before.csv" -NoTypeInformation -Encoding UTF8

dotnet test .\tests\LivePhotoBox.Core.Tests\LivePhotoBox.Core.Tests.csproj `
  -c Release -p:Platform=x64 -p:SkipNativeBuild=true `
  --filter "FullyQualifiedName~SourceInspectorTests&Category=RealSamples" `
  --logger "trx;LogFileName=p1-real-samples.trx" `

  Sort-Object FullName |

  Tee-Object "$EvidenceDir\real-samples-hash-diff.txt"
```

ACCEPT 条件：

- `designs/各个机型测试/` 中 P1 所需样本全部存在；
- 至少覆盖 OPPO/OnePlus、vivo X300、vivo legacy dual-file、Samsung JPEG/HEIC、Huawei/Honor、Xiaomi/Redmi Google V1/V2、Apple JPEG/HEIC + MOV；

- 前后 SHA-256 比较无差异；
- 不得把原始样本作为转换、修复或写入目标。如需派生文件，先复制到 `$EvidenceDir` 内。

## 5. 必须被命中的对抗用例

不仅看总体绿灯，在 TRX 中确认以下用例确实被发现和执行：

- XMP 兼容 URI + 任意合法 prefix 成功；错 URI/局部 prefix rebinding 不冒充。
- protocol property 与 Directory 分居不同 Description 时 fail closed。
- 多 HEIF XMP packet 中的相关 shadow/conflict 失败，无关 XMP 不误伤。
- vivo X300 2-item 成功且 GainMap absent；3-item 成功且 GainMap range 正确；4-item/错 MIME/错版本失败。
- Samsung HEIC 真实样本命中 `mpvd -> nested sefd -> MotionPhoto_Data`。
- Apple JPEG IFD0/多 APP1/重复/影子 MakerNote 失败；正式 ExifIFD owner 成功。
- Apple 改名双文件可匹配，同名错配不确认，candidate Pairing mismatch 不中止整批。
- malformed JPEG/HEIF/MOV/MP4、stale chunk offsets、无轨 `moov/mdat`、任意签名字节不得确认协议。
- Native I/O/status/category/stage/capability 在 C# 中可观察，不被统一吞掉。

## 6. 独立文件证据（不重复逆向）

只用 ExifTool/ffprobe/独立 container parser 核对当前样本与 Inspector 输出；不重新推导协议规则，不把这些工具接入 production。

必须保存：

- 工具路径与版本；
- 每个真实样本的 ExifTool JSON；
- 脱离视频和从 Inspector 声明的 exact range 复制出的视频的 ffprobe JSON；
- Inspector protocol/container/range/pairing/facts 与协议文档预期的逐样本对照表；
- 对不支持/无法解析的工具输出明确记录 `Unavailable`，不写成 PASS。

如 ExifTool/ffprobe 缺失，独立证据 gate 为 `BLOCKED/REJECT`，不可 skip 后 ACCEPT。

## 8. 外部 AI 必须返回的报告格式

```text
Verdict: ACCEPT | REJECT | BLOCKED
HEAD: <commit>
Working tree identity: <git diff --stat + name-status>

Commands:
- <exact command> -> exit code <n>

Counts:
- P1 Core: discovered / executed / passed / failed / skipped
- P1 RealSamples: discovered / executed / passed / failed / skipped / missing
- CLI P1: discovered / executed / passed / failed / skipped
- Native/CLI/GUI build: success/failure + error count

Blocker matrix:
- P1-A01 ... P1-A12: PASS/FAIL + production symbol + test/evidence file

Real sample evidence:
- sample name -> expected protocol -> observed facts -> independent evidence -> SHA unchanged

Failures:
- numbered, reproducible, P1-only blockers
- later-phase observations go to backlog and do not broaden P1

Evidence directory: <absolute path>
```

`ACCEPT` 必须同时满足：P1-A01–A12 全 PASS，P1 必需的构建/测试命令 exit code 0，P1/RealSamples/CLI 无 failure/skip/missing，样本 SHA 不变，且独立文件证据完整。Doctor 中与 P1 无关的可选远程服务状态不属于产品验收结论。
