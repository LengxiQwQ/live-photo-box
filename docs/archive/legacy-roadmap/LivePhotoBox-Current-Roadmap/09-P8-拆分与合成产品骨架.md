# P8 — Split / Merge Product Foundation

> **Entry:** P1–P7 credible.  
> **Goal:** 把 GUI / CLI / Core 的 Split 与 Merge 产品骨架切到稳定 Rebuilt contracts，并为 P9 提供清晰 Writer boundary。  
> **Current product platform:** Windows。  
> **Non-goal:** 为了未来 Linux/Web 重写 WinUI 或把 Windows C# Core 强行跨平台化。

---

# 1. P8 定位

P8 负责：

```text
product call graph
typed selections
input discovery/preparation
Neutral preparation
queue/batch/progress/cancel
output naming/destination
error presentation
Writer orchestration boundary
```

P9 负责：

```text
target protocol structure
structured Writer
Target Validator
old Writer replacement
real-device conformance
```

# 6. Platform capability presentation

未来 platform 能力可能不同，因此产品 contract 允许查询：

```text
supported capabilities
supported output profiles
available media backend capability
```

当前 Windows UI 可以展示全部 Windows 能力。

未来 Web 若只支持：

```text
inspect
split
limited merge
```

不要求伪装成桌面完整能力。

### 6.1 精简版系统（缺少 Media Foundation）的自适应显式兜底机制

**当前用户决定（2026-10-23）：** 真实缺少 Media Foundation 的 Windows N/KN/精简系统验证，移至发布前确认事项，届时使用隔离虚拟机或测试机完成，跟踪于 [RELEASE-003](../发布前问题清单.md#release-003)。P8 仍须完成本节功能实现、现有系统上的受影响验证及独立复核；仅该真实环境实测可延后，不阻止其余条件满足后的 P8 技术收尾。该行必须保留为 `NOT_RUN / DEFERRED_BY_CURRENT_USER`，不得写成通过，也不得用模拟代替；发布前必须关闭 RELEASE-003。本决定不授权卸载宿主组件或修改系统 DLL。

- **目标场景**：针对精简版 Windows（如 Windows 10/11 N/KN 版本、Tiny/Lite 精简镜像、缺少 Windows Media Feature Pack 的系统），防止因系统缺少 Media Foundation 编码器导致普通 H.264 视频转码失败。
- **自适应探测**：在输入准备与能力协商阶段，通过 `available media backend capability` 探测系统的 Media Foundation 状态；
- **内置引擎兜底**：当系统 Media Foundation 确实缺失时，**显式且受控地激活内置打包的 `minimal-libav`（基于静态链接的 `libx264`）** 作为 H.264 视频转码的兜底执行端；
- **诚实记录与合规**：
  - 兜底过程必须是受控且可诊断的，在 `ExecutionRecord` / 诊断信息中如实反映 `fallback_occurred = true` 及实际调用的 `minimal-libav/x264` 身份，不搞黑盒隐瞒；
  - 产物质量与元数据保真度（时间戳、MEBX、音频流）仍须满足项目 Contract；
- **UI 呈现**：在 UI 状态展示或诊断信息中提供友好的状态呈现（例如提示“系统多媒体组件未就绪，已启用内置独立编码引擎”），确保精简版 Windows 用户开箱即用。

# 7. Execution / history

产品 history 应记录 semantic outcome，而不是只记录：

```text
"success"
```

适合记录：

```text
operation
OutputProfile
preservation/degradation
backend summary
output artifacts
diagnostic result
```

backend 仅用于 diagnostics，不成为协议 correctness authority。

---

# 8. Exit Criteria

- Split/Merge product flow 走 Rebuilt contracts；
- GUI/CLI 使用 typed Core contract；
- Core 不长期依赖 UI index；
- Windows-specific UI 不污染 Portable Native Core；
- capability query 可支持未来平台能力差异；
- **精简版 Windows / 缺失 Media Foundation 场景具备显式受控兜底（支持切换至内置 minimal-libav/x264），且 ExecutionRecord 真实记录；**
- existing target writers 位于明确 boundary 后；
- P9 可逐个替换 Writer，无需再改产品主架构。

全局执行规则见 `00`。
