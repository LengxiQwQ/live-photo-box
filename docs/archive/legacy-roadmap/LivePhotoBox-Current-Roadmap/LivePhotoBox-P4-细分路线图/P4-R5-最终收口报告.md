## 真实 HEIC 样本盘点

正式设备语料只有三份 HEIC。`谷歌自己合成的.heic` 是 synthetic fixture，测试会明确识别并排除它，绝不将其当作设备兼容性证据。

| 样本 | Primary | HDR/GainMap 表示 | Auxiliary | Native decode |
|---|---:|---|---|---|
| Apple `苹果双文件.HEIC` | item 49，4032×3024，8-bit source / 8-bit signal / 8-bit storage | **HDR：8-bit primary + Apple HDR GainMap** | item 63，2016×1512，8-bit，`urn:com:apple:photo:2020:aux:hdrgainmap` | primary、auxiliary 均通过 |
| Huawei `华为Mate80.heic` | item 15，3072×4096，8 / 8 / 8-bit | 没有 HEIF GainMap auxiliary；不把视频轨 HLG 元数据误作静态 primary HDR | 无 | primary 通过 |
| Samsung `三星.heic` | item 49，3000×4000（方向已应用），8 / 8 / 8-bit | **HDR：8-bit primary + Samsung HDR GainMap** | item 55，750×1000，8-bit，`urn:com:samsung:photo:2024:aux:hdrgainmap` | primary、auxiliary 均通过 |

三份样本的 SHA-256、尺寸、位深和 auxiliary identity 已固定在 `tests/LivePhotoBox.Core.Tests/RealSampleManifest.json`，同名但内容不同的本地文件会使测试失败。

## 核心结论

此前“没有 10-bit primary，所以没有 HDR RealSample 证明”的判断过于僵化。真实 Apple/Samsung HDR 图片采用的是：

```text
8-bit SDR primary + embedded HDR GainMap auxiliary = HDR image
```

因此，primary 为 8-bit 并不意味着该图片不是 HDR。本轮已证明：项目自有 HEIF parser 能发现 GainMap 结构和语义；Native 能按项目提供的 item ID 解码对应 auxiliary；共享的 `ImageConversionEligibility` 在 `ImageConverter`、Neutral pipeline 与 CLI 进入普通 primary-only codec 前拒绝 GainMap HEIC→JPEG。`ImageConverter` 会在实际调用 codec 前自行重新检查源容器，调用方错误标注 image container 也不能绕过该规则。未完成 P5 语义转换时路径会 fail closed，不能把 HDR 输入静默变成 SDR JPEG 成功结果。

当前样本语料没有 >8-bit primary。这只意味着不能声称已取得“真实设备 >8-bit primary 覆盖”；不构成当前 GainMap HDR 路径的 blocker。`pixel_surface.signal_bit_depth` / `storage_bit_depth` 和 >8-bit 使用 16-bit storage 的架构仍被保留。

## 本轮补齐内容

1. 新增 `lpb_decode_heic_primary_image`：只读获取 primary 实际 decode 后的尺寸、source/signal/storage bit depth、ICC/nclx 等 POD facts。
2. 新增 C# interop 与 ABI v7 的 Native/managed layout 防护；所有 HEIC ABI struct 都有 size/offset 检查。
3. Apple、Huawei、Samsung 统一改为真实 primary pixel decode 测试，不再以 inspect 冒充 decode。
4. Apple、Samsung 真实 GainMap auxiliary 以项目结构 parser 的 item identity 解码，并校验精确 item、尺寸和位深。
5. 新增正式样本 inventory test 和可追踪 manifest。
6. 保留且验证 auxiliary codec encode foundation：Native 可写入两个不同的 HEVC image items；项目层仍独占 `auxC`、`auxl`、vendor/GainMap 语义和 item-reference 决策权。
