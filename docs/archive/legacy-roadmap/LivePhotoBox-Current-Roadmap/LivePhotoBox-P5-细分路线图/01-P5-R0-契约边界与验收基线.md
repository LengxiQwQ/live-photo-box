# P5-R0 — Converter 契约、边界与验收基线

> **性质：** 文档与验收基线轮；不改 Converter、Native、依赖、打包或 P4 后端归属。
> **完成后：** 停止，等待当前用户确认再启动 P5-R1。

## 1. 目标与非目标

R0 要让后续每一条公开 conversion path 都有可检验的语义、证据责任和失败条件。它不把“现有代码能跑”升级成 P5 capability，也不为 blocker 写临时 fallback。

本轮不允许：修改 production source、C ABI、vcpkg/CMake、runtime package、codec/video owner，或将 Magick.NET 转换路径合法化。

## 2. P5 语义矩阵

| 类别 | 允许的真实含义 | 禁止的虚假表述 | 最低证据 |
|---|---|---|---|
| Passthrough | bytes/container 适配确实无需转换 | 把重新编码叫 passthrough | input/output identity 或结构对应证据。 |
| Container remux | 只重组 container，codec payload 不变 | 把 transcode 当 remux | project ISO-BMFF 结构 + 独立 media probe。 |
| Lossless transform | 可证明的无损 pixel/container transform | “视觉相近”即 lossless | codec/structure proof + metadata/orientation evidence。 |
| Lossless transcode | 仅在 codec/container 的实际能力有证据时声明为无损转码 | 把“未量化质量损失的转码”称为 lossless | codec/profile proof + independent decode/metadata evidence。 |
| Lossy reencode | 明确 lossy encode 的 codec/profile/result | 把 codec success 或视觉相近叫 Preserved | output decode + preservation component outcomes。 |
| Color transform | 实际像素 transform 由 approved backend 执行 | Display P3 只改成 sRGB tag | profile/pixel transform evidence。 |
| HDR / GainMap | Native pixel primitive + project-owned semantic/container mapping | HDR failure 后悄悄输出 SDR | independent structural/render evidence；Strict/BestEffort outcome。 |
| Degraded | 明示 `DegradedToSdr` 等实际损失 | 以 successful output 隐藏 loss | reason、policy、post-validation。 |
| Unsupported | selected capability 不可用或不可表示时 fail closed | 自动 retry 另一个 backend | selected-backend diagnostic 与无半发布 output。 |

## 3. 公开路径、当前状态与后续 owner matrix

这里的“目标语义”是 R1–R6 必须兑现或如实拒绝的 contract，不是声称当前实现已经满足。每个失败/unsupported row 都要求 no partial output。

| 公共路径 / façade | 目标语义 | 当前事实 | owner | policy 与不完整输出 |
|---|---|---|---|---|
| JPEG→JPEG | passthrough 或 proven lossless transform；必要时明确 lossy reencode | Native JPEG 基础存在，但 component-level metadata/ICC truth 未记录。 | R1/R2 | Strict 只在全部 required components 证明时成功；否则 fail closed。 |
| HEIC→HEIC | passthrough、lossless transform 或明确 reencode | HEIF graph/project truth 有基础；完整 preservation 仍未形成 P5 record。 | R1/R2 | 不得因 decoder success 称 Preserved；失败不发布。 |
| ordinary JPEG→HEIC | 明确 lossy reencode / metadata map | 已有 conversion surface；Strict 目前粗粒度拒绝 cross-container。 | R1/R2 | BestEffort 仅在显式 partial outcome；AllowDiscard 逐 component 授权。 |
| ordinary HEIC→JPEG | 明确 lossy reencode / metadata map | 已有 conversion surface；同样缺 explicit representability matrix。 | R1/R2 | Strict fail closed；任何 output 必须有结果 record。 |
| JPEG GainMap / Ultra HDR→HEIC | HDR/GainMap semantic conversion | `StandardHdrConversionService` 尚未完成 Native seam，不能宣称可用。 | R3 | Strict Unsupported/fail；BestEffort 只能显式 `DegradedToSdr`，不得 silent plain HEIC。 |
| HEIC GainMap→JPEG | HDR/GainMap semantic conversion | Native auxiliary decode/metadata seam 未完成，现有路径 fail closed。 | R3 | Strict Unsupported/fail；BestEffort 的降级须有 post-validation。 |
| MOV↔MP4, codec Copy | container remux，codec payload 不变 | project-owned remux 基础存在；legacy façade 的 `WasRemux` truth 不可靠。 | R1/R5 | selected remux must report exact operation; failure no partial output. |
| H.264↔HEVC transcode | explicit lossy reencode or proven lossless transcode where meaningful | SDR backend frozen；P5 record/dispatch evidence未完成。 | R1/R5 | capability selected before execution；无 retry tree。 |
| TargetFps request | Unsupported，直至显式 capability/semantic 被实现 | `VideoConverter` 现 fail closed。 | R5 | 不发布 output；record unsupported reason。 |
| `HeicConverterService` / `VideoTranscodeService` legacy façade | 映射到 canonical converter contract，不能自创 operation truth | 仍有 façade 语义与 canonical record 脱节。 | R1/R2/R5 | P5 完成前不把 façade success 当 P5 acceptance evidence。 |

## 4. policy baseline

| Policy | P5 规则 |
|---|---|
| Strict | 每个 contract-required preservation component 都必须经可追踪证据满足；不满足则 fail closed、无 output。 |
| BestEffort | 只能在 record 声明实际 preserved/partial/degraded component 后成功；从 HDR 到 SDR 必须 `DegradedToSdr`。 |
| AllowDiscard | 只可丢弃 requirement 明确授权且不适用的 component；不是通用 metadata/HDR 清除开关。 |
| Fallback | 必须预先允许、记录 selected/actual capability 与原因，且重新验证实际结果；不可改变未声明的 quality/HDR/preservation contract。 |
| Unsupported | selected capability 不可用、不可表示或不安全时 fail closed；不自动尝试另一个 backend。 |

## 5. 后续 ExecutionRecord 的 contract（R1 实现）

每次 result-affecting conversion 必须可诊断地表达：

```text
input container/codec + requested output + operation kind
selected backend/capability (+ useful version) + hardware/software
codec/profile + passthrough/remux/reencode status
metadata mapping + ICC/color + HDR/GainMap + audio + timing/orientation result
fallback decision/reason + preservation outcome + degradation + unsupported/failure category
```

这些字段是产品语义，不能以 `MediaFoundation`、`libheif` 等库专有类型作公开 contract；backend name 是诊断证据，不是 Writer correctness 输入。

## 7. RealSample 与 independent-validator matrix

| claim class | hash-locked P4-v1 input | independent validation route | coverage rule |
|---|---|---|---|
| ordinary HEIC conversion | `华为Mate80.heic` | independent HEIC decoder/metadata reader + project structural inspection | 不以 product self-read 单独证明 preservation。 |
| HEIF GainMap / auxiliary | `苹果双文件.HEIC`、`三星.heic` | independent HEIF graph/metadata/decode check；设备语义加 reference/device evidence | generic tool 不足时明确 device-evidence blocker。 |
| JPEG GainMap / Ultra HDR | `vivo.jpg`、`荣耀.jpg`（按实际 capability 选用） | independent JPEG/XMP/MPF/GainMap validation + decode/render/reference evidence | output 的 gain-map identity 与 representation 必须可追踪。 |
| ordinary video / remux / SDR transcode | `苹果双文件.MOV`、`vivo双文件.mp4` | independent media probe，比较 duration/timing、codec/container、audio、rotation、color tags | project re-probe 是附加证据。 |
| HDR/10-bit video | hash-locked P4-v1 `华为-Mate80.jpg`；其 canonical extraction 可产生 Huawei Main10, BT.2020/HLG MP4 | 建立 extracted artifact 的 identity/provenance，使用实际 P5-wired frozen minimal-libav capability，并独立验证 bit depth、transfer/color metadata、timing、audio、rotation 与 output behavior | P4 R6 research 是先前证据而非 P5 acceptance；若 canonical extraction/actual capability 不足，再显式建立 P5 corpus extension。 |
| >8-bit still-image conversion | none in P4-v1 sufficient | authorized P5 corpus extension + independent decode/bit-depth evidence | 未补样本即 coverage blocker。 |

## 8. 验收矩阵与 blocker 策略

后续 R 的 TASK 必须逐 conversion class 列出：目标语义、Strict/BestEffort 行为、目标测试 filter、所用 hash-locked RealSample、独立 validator、preservation claim、失败时不发布的检查。

不存在样本、独立验证器或 frozen capability 时，必须记录为 blocker/coverage gap。尤其：

- P4-v1 中 Apple/Samsung HDR 是 GainMap auxiliary，不能替代真实 >8-bit still image sample。
- minimal-libav 尚为 research-only；未接入前 HDR/10-bit 视频必须如实 Unsupported，不准自动转 Media Foundation。
- `Preserved` 需要 before/after 可追踪证据；产品自身 reader 只能是附加证据。

## 9. R0 Acceptance

R0 仅在下列全部清晰时可 `READY FOR VERIFICATION`：

1. 所有公开 conversion classes 均在 §3 映射到一个声明的 semantic operation/outcome、current status、owner、policy 与 no-partial-output expectation；
2. semantic success 与 codec/backend success 分开；
3. Strict、BestEffort、degraded、unsupported 和 fallback 的行为可审计；
4. P4 backend ownership 原样继承，backend identity 不成为 semantic authority；
5. result-affecting managed pixel work 被标为迁移债务；
6. 每项 preservation/HDR/color/audio/timing claim 均有 RealSample + independent validation route，或明确 blocker；
7. R0 不产生 production、dependency 或 package 变化。
