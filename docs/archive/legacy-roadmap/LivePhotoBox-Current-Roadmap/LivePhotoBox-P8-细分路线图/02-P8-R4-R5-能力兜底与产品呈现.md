# P8 R4–R5：能力、受控兜底与产品呈现

## R4 先冻结局部设计，再实现

前置：严格按00的顺序，R0–R3各自完成所需覆盖/复用核查与真实缺口处理并登记结论后，才能开始R4实现；不能只声称满足局部依赖就跳过未完成单元。只读Native/环境调查可提前并行，不能提前改产品代码。

设计输入：现有 NativeRuntime capability、MF初始化/软件encoder探测、Native DLL普通/延迟导入及加载链、严格source-profile dispatch、已打包 minimal-libav/x264身份/能力、managed VideoConverter与ExecutionRecord。

设计必须先答清：
1. 系统缺MF DLL、MF启动失败、没有H264 encoder、参数不支持、source malformed、转码中失败分别如何分类。只有可证的MF缺失/相应能力缺失触发官方受控兜底；普通未知/执行错误不自动重试。
2. Native在真实缺组件环境是否能加载，能力探测是否会因硬导入在入口前崩溃。若需平台加载调整，保持C ABI与Portable Core边界，遵循源码/构建的一致路径。
3. 对可用性、未知状态、请求适用性、profile支持和sidecar完整性的查询如何表达。静态列出了某选项，不等于当前机器可执行。
4. fallback只影响符合条件的H264请求，不改变已有HEVC/HDR/Copy的默认路由。音频/时间轴/方向、CICP、MEBX与其他metadata遵守既有Contract，不为了产出而跳验证。
5. 从选中、候选生成到最终成功/失败，实际backend/encoder/profile/fallback原因如何完整记录；失败也不能丢掉真正执行过的身份。

实现to-do：
- typed实际capability/query与产品input preparation协商；无能力应明确拒绝。
- 复用现有最小sidecar，先核现有x264启用/打包/身份验证；不默许新增生产依赖、放大codec feature set或改公开ABI。确需该类变更时准备具体可审方案再询问用户。
- Native平台加载/探测和受控路由；真实执行结果继续走原独占staging、metadata/preservation validation与publishgate。
- ExecutionRecord与GUI/CLI诊断：实际minimal-libav/x264、fallback_occurred=true、具体MF缺失原因；直接因source-profile选择libav的正常路线仍不称fallback。

必须覆盖的验证矩阵：

| 条件 | 期望结果 | 证据性质 |
|---|---|---|
| MF正常、原来选择MF的普通SDR H264请求 | 保持原路线/结果、fallback=false | 真实Windows；未影响结果可复用 |
| 真实缺MF/相应H264能力，满足兜底profile且sidecar有效 | 加载成功、选择x264、fallback=true、有效产物及保留证据 | 真实隔离环境；用户2026-10-23明确延至RELEASE-003发布前实测，不是inject |
| MF缺失且sidecar缺失/身份不符/codec不支持 | 受控BackendUnavailable/Unsupported，无假success或半发布 | 可做隔离真实文件状态；不破坏系统DLL |
| malformed/未知profile/MF普通执行错误 | 不借兜底绕过严格拒绝 | Unit/Synthetic + 必要真实失败，各自标注 |
| 原HEVC/HDR/Copy、MEBX/音频/方向等保留场景 | 路由与语义不退化；变化影响的部分补测 | 适用旧证据+最小新独立媒体检查 |
| cancel/failure during fallback | owned staging清理/回滚、失败身份真实 | 状态机与真实文件系统证据区分 |

真实环境原则：优先利用现有、获授权的隔离Windows N/KN/缺Feature Pack系统/VM。不能为取证卸载宿主MF、改系统DLL、降低系统安全或改用户数据。当前用户2026-10-23明确将该实测移至发布前，届时使用虚拟机；此行保持NOT_RUN / DEFERRED_BY_CURRENT_USER，由RELEASE-003跟踪，不阻止其余P8条件完成后的技术收尾。实现/本机验证/复核仍须完成，不把模拟测试改名为真实缺MF。

完成：实际capability真实、受控路由与ExecutionRecord有正反证据、真实缺MF行按当前用户决定明确移交RELEASE-003发布前确认、fresh只读高风险复核无其他blocker。R4失败普通工程问题自主修复；不改acceptance换绿灯。
