# P8 R6–R7：验证矩阵与独立收尾

## R6 验证如何安排

每个实现单元完成一个逻辑块后运行最小受影响build/test，不把build/test作为每次编辑hook。已有通过且仍适用的结果只做适用性核对，不再次执行。当前44Core/18CLI、四variant真实CLI、独立视频probe、Native复用桥与review均保留原始身份。

验证分四层：
1. **Unit/状态机**：typed映射、未知/不支持选择、capability分类、队列pause/cancel/计数、结果序列化。只证明所测层，不冒充真实MF缺失或文件系统故障。
2. **真实产品路径**：CLI进程、GUI实际交互、Core真实Neutral/Writer/export/publish；使用只读原始样本或缓存工作副本。需转换/发布的测试不能只跑dry-run。
3. **独立正确性/保留**：受新修改影响的container/media/profile/时间轴、音频、MEBX/metadata和preservation；复用仍有效的原独立证据，新增产物在必要范围用独立工具核验，不让产品Reader独自给Writer认证。
4. **最终P8有界aggregate**：最终候选完成全部实现后，只选择实际受P8修改影响的主线和新能力集成，一轮覆盖接口交界。禁止全产品suite/P0–P7整阶段重跑/无理由30minsoak。未影响分支用复用表补齐整阶段矩阵，不能为了凑统一计数重跑已完成所有测试。

### 执行前冻结命令与覆盖

准确command/filter/count必须以最终实现和实际discovery为准，在 `.ai-tmp/workspace/P8/product-foundation/R6/` 冻结执行清单；不能现在编造尚不存在的测试名或未来PASS数量。现有可复用入口包括P8ProductSelectionTests、P8MergeWorkspaceOwnershipTests、P5R6NeutralConsumptionIntegrationTests、AppleSplitRegressionTests和P7R2MergeTransactionTests.Runner，按覆盖/影响选择，不默认整类重跑。

构建以现有Core/CLI/WinUI Release x64命令为准；Native有修改时先用canonical CMake/vcpkg增量构建和必要Native targeted tests，再验证产品所加载的确为该binary。SkipNativeBuild只能用于确实复用已绑定Native的managed检查。移植smoke不替代Windows产品验证。

runner先在workspace资格检查：真实子进程退出码、filter/discovery实际包含所声称方法/数据行、样本存在/身份正确、没有skip、输出/日志可留存、对失败不吞异常。随后才分配正式create-only run；不因脚本bug盲目消耗正式run。

### 每行证据字段

case id；所属R/官方exit；NEW/REUSED/NOT_RUN；source/runtime/input/profile identity；准确命令与filter/data rows；直接child exit；TRX total/passed/failed/skipped/notExecuted；预期成功或失败stage/category；实际output/源/foreign before-after；独立保留结论与范围；owned leftovers/rollback；原始证据位置；适用性理由与失效条件。

缺样本、缺真实环境、skip、filter排除、零测试、仅上游拒绝却声称下游执行均不能算必需行PASS。真实缺MF实测仅按用户2026-10-23决定移至RELEASE-003发布前确认，标记NOT_RUN / DEFERRED_BY_CURRENT_USER，不计作P8已通过测试。真实实现不支持且官方允许的场景，可以用明确Unsupported结论，但不能把官方要求的缺MF正向改为Unsupported。

## R7 独立收尾流程

顺序固定：最终候选与索引冻结 → fresh只读Review → 修复真实in-scope finding并补受影响验证/更新最终有界aggregate → fresh只读Review通过 → 独立fresh Verify检查身份/覆盖/原始证据 → 主代理登记阶段完成并停止。

Reviewer检查实现、所有产品可达旁路、八项标准、保真/权限/事务与scope；Verifier以只读核验身份、日志/TRX/输入输出、独立工具和复用适用性为主，不自动重跑已完成测试。只有证据缺失/不可信/受修改影响时提出准确最小补证，不让Verifier再执行一遍全阶段。

Review/Verify必须绑定同一HEAD/branch/workspace dirty source manifest、运行库、Roadmap revision与evidence index。后续产品修改使相关结论失效；文档纯登记变化要明确区别，不能自动要求重验产品。

没有参与候选修改的fresh上下文才可独立。实现者可以修复和自查，不能替Reviewer/Verifier签通过；普通测试worker按冻结手册执行，也不冒充独立语义审计。使用不同模型不自动产生独立性。

## 最终检查清单与判定

- 八项官方exit与正文产品范围逐项有结论，R0–R6必需项完成，无in-scope blocker。
- 所有当期必需RealSample与独立保留证据存在且可复核；复用和新跑明确区分。真实缺MF实测按用户决定保持NOT_RUN并移交RELEASE-003，关闭条件完整，不影响其余条件完成后的P8技术收尾。
- 最终P8限定aggregate通过；scope/discovery/count一致、零必需skip。
- freshReview和独立Verify通过；若真实外部/user gate另有适用要求则先取得，不能代签，也不凭P7历史人为加gate。
- doctor ActiveOnly及AI配置sync/verify/reconcile通过；optional远程服务不作为无关产品blocker。
- docs写回做了什么、验证范围、限制、未完成问题归属和关闭条件；state/TASK依据真实结论更新，sealed历史不重写。
- 全部满足后P8=complete，清理active TASK，保留P9/发布遗留。未满足则明确in_progress或真实阻塞，不宣称完成；不自动进入P9、不发布Git、不声称整产品可发布。
