# P9 R2：独立验证器与强制发布门禁

2026-10-26。状态：**R2 COMPLETE / PASS_FOR_FINITE_R2_CLOSEOUT**。实际候选 Review 和另一 fresh Verify 均通过，无当前 R2 范围内 blocker。R2 的边界是独立验证与真实发布闭环，完整厂商施工、产品切换及设备验收继续属于后续 R。

这次把“写入器返回成功就可以发布”改成了新目标链上的强制检查：写入流必须 flush 并关闭，发布器保留保护文件身份的句柄，再新开只读视图，从实际完整字节读出目标字段、图片与视频范围、编码、时间和媒体表。独立规则通过后才能发布；发布前后仍核对同一对象和同一份字节。调用方不能提供“验证成功”回调，也不能关闭验证。

为了真正证明这条链能工作，R2 接入了最小 Google V2 Native 写入器，实际生成并发布文件；没有用全 Unsupported 的空框架代替完成。完整 Google V1/V2、OPPO、小米兼容与更多变体仍交 R3，这次没有顺手做完整 R3。现有 GUI/CLI 的 ExistingTargetWriterAdapter 尚未切换，也没有缩减现有产品选项。

## 改了什么

- 新增配套 ABI14：只读随机读取 reader、语义期望 request、独立 observed result，分别为48/64/176字节。既有 POD 布局不变，不让 Windows HANDLE、C++对象或异常穿过 ABI。
- JPEG 复用同一个完整 marker/entropy 遍历；XMP 用独立事实接口及严格目标 namespace/XML 检查，保留 SourceInspector 原有兼容行为。验证器不借 Writer 的内存模型、hash 声明或 SourceInspector 最终厂商分类证明自己。
- MP4/MOV 从真实 box、mdat 和 sample table 读取，核对视频与音频、跨轨重叠、同步样本引用、时序和偏移；大媒体使用64位随机读取，不把整个视频载入内存。
- Google V2 最小写入器在 Native 生成结构，合并单一合法普通 XMP，完整复制视频。C# 只编排、搬运分块字节和协调事务。Native stage 仍是未发布对象，只有强制验证过的发布器能返回已提交结果。
- 结构、通用媒体结构、保留、设备四个结果分开。当前验证器只能给出结构通过和媒体容器结构有效；preservation 保持 NotEvaluated，device 保持 NotRun。完整解码和有限字节保留证明作为独立证据记录。

## 保留的限制和后续归属

当前新 Writer 是实验子集：普通SDR、无辅助图的 JPEG + MP4/MOV，图片32MiB、视频256MiB快照限制仍在。HEIF、HDR/GainMap、辅助资产、Extended XMP、更多元数据和其他目标族尚未激活，明确拒绝；不能把这些限制套到现有用户流程。当前正向输出声明限于已执行的 H264/AAC；其他 codec/variant 要在后续逐行补证。多成员/配对输出未在当前合成范围启用，不能声称已验证双文件配对。

验证器使用64位流式读取；本轮实际证明了超过4GiB的co64结构读取和大输入流式取消，没有宣称完成一次全4GiB公开验证或大文件Writer输出。原始手机实测仍为未测，Windows本地结构通过不提升为设备兼容。RELEASE-004未按全范围关闭，完整厂商生命周期和逐目标产品切换仍由R3以后及R8完成。

本轮未安装开发工具、未增加生产依赖。离线 Python/FFmpeg只用于输入资格和独立验证。Fusion继续延期；Apple/旧vivo双文件仍属于独立拆分后续；未进入P10，也不宣称P9或整产品可发布。
