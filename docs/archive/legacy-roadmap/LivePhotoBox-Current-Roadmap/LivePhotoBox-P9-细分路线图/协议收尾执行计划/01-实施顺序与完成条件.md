# P9 剩余施工顺序与完成条件（实况优先版）

## 2026-11-01 当前用户更新：A/B/C 分级

唯一分级见 [中性媒体契约第 0 节与 N9](../../12-中性媒体契约.md)。本文件不再要求默认全信息保留、统一丢弃辅助内容或强制 B 轮。2026-10-31 阶段 1 安全修复及 70 行要求是旧授权背景，现有代码、测试、失败与候选证据留存于 R8 `stage1-safety-repair/`，不被本次文档修改升级为通过。本次不恢复施工。

## 1. 两个输出档

| | 兼容档（正常转换主线） | 既有严格档（用户显式选择） |
|---|---|---|
| 目标 | A 级正确；B 级现成可靠能力正常保留；C 级不要求跨协议承接 | 仅描述已有 Strict 的精确适用范围，不承诺所有信息都能原样保存 |
| 对应契约 | N9：如实记录重编码、未承接及降级，不能放宽 A | 旧拒绝/证明语义保留，不改代码/测试，不作为默认或 P9 门槛 |
| CLI/GUI | 规划上的正常转换档；本次不修改程序默认值 | 显式能力留存，不继续扩建 C 级能力 |
| 现状 | 既有阶段 0/1 候选保留，运行状态见 TODO/TASK | 已有保留单元可复用，但不派发强制 B 轮 |

### 1.1 兼容档必须做到（A 轮硬要求）

- **实况结构正确：** 目标协议要求的识别标记、XMP/私有字段、偏移/长度、双文件配对标识全部正确；写法以该目标品牌原生相机直出样本为准。
- **主图：** 完整可解码、画面无明显失真或严重偏色，方向/镜像正确。复用已实现转正；目标正确支持的标准方向表示可用，不为统一物理转正另立任务。未知方向不得按单个样本推广或伪称已验证；已有显式按存储像素处理能力保留，实际不明/冲突影响正确性时如实报告。
- **视频：** 主视频完整、时长正确、可播放；根据实际编码、容器和目标能力直接复制/重封装或转码。无关私有辅助/定时轨和占位轨属 C，不要求承接；但不能仅凭轨名删除，承担声音、封面、颜色或播放等 A 语义的内容须正确处理。B 级 HDR 使用现成可靠能力。
- **视频方向：** 需要转码时，按解析出的实际显示方向将像素真正转正（包括适用的镜像），成功后清除/归零 rotation 和实际承载方向的显示矩阵，保证只旋转一次。不能只删标签、也不能像素转正后继续带旧旋转矩阵。直接复制路径若方向可被目标正确表示且自检通过，可保留原方向表达；否则转码转正，不能把已转码视频的方向问题推到 B 轮。无旋转的输入不额外处理。苹果/三星是用户反馈的重点来源，其他来源目前反馈正常，不据此认定只有这两家会有问题。用户反馈旧版 2.2.1 会物理转正，可作对照线索，尚未在本次重新核验旧实现；新链不能调用旧运行时兜底。
- 来源绑定按授权精确清理；目标协议必需的配对/封面轨由 Writer 重新生成，例如 Apple 封面元数据，不能一律剥掉。
- **音频：** 来源有声音，成品必须有声音且同步；声道数不减少；目标容器不接受来源编码（如 LPCM 进 MP4）时转为 AAC。
- **封面：** 封面、时间点和视频内容正确对应。来源越界/冲突须查时间基准及通用映射；不能只夹到合法范围就声称对应正确，也不以原始私有时间字段逐字节保留为目标。
- **基础颜色/拍摄信息：** 不因实现错误造成明显丢失或严重偏色；常见 EXIF/标准 ICC 归 B，现成可靠路径正常承接，不要求所有字段逐项完全一致才通过。
- **HDR：** B 级现成路径可靠则保留，否则可正确转 SDR 并记录 `DegradedToSdr`；不是自动待办，不以主图是否 10-bit 单独判断 HDR。
- **如实报告：** 复用已有变更报告/`notCarried`，记录已知未承接和降级，不能标 `Preserved`；不为 C 数据新增完整清点、版本化 ABI 或保留系统。
- **安全不变：** 来源只读、发布事务、双文件成套、失败不留半成品、无旧实现 fallback、无来源品牌特判。

### 1.2 非 A 内容不自动派发任务

B 级按契约现成能力承接；C 级退出跨协议开发范围，不转 B 轮或 P10。原始音频编码/字节一致、正确显示前提下统一物理转正、原厂编辑历史/恢复原图、无关附图、水印资产及历史容器填充均非基础验收门槛。当前主图上实际可见内容仍属 A，不能因名称为水印/附图就删除。已有实现和有效测试不删，普通转换不得因缺少完整保留证明就自动扩建。

**到约定边界停下报告：** 每目标有效测试批次电脑就绪、基础验收收口时报告，用户继续后再推进。阶段 0 已有成果不重做；本次停在文档调整。停点不触发额外复核；缺设备只延后对应真机验收，不阻止已授权的不受影响工作，不写成通过。

既有 `documentation/coverage.json` 的 14 组来源 × 22 个目标格式 = 308 行保留为回归清单。日常只测实际受影响范围，阶段收口补必要全面验证；不为 B 级补齐跨品牌矩阵，不删行隐藏失败。支持目标/格式范围变更仍由用户决定；保留等级变化不等于组合已转换成功。

## 3. 一个目标的 A 轮流程

1. 用正式 CLI（兼容档）生成受影响的真实样本，检查每份成品并逐行记录结果。
2. 失败先定位具体层和通用能力，再按 A/B/C 判断。A/安全缺陷修复并保留失败证据；B/C 不因缺少完整承接继续扩建。检查器不适用也如实记明，不能伪造通过。
3. 已通过电脑检查的完整有效样本可先平铺交付，说明本批范围、失败/未覆盖及手机未测，不等待其他来源。双文件须成套，失败成品不得混入。批次就绪停下来报告；小米缺设备保持手机未测。
4. 按反馈修复：先找共同原因（同一批文件都失败，一般是目标规则问题，不是逐文件问题），修完重新生成受影响的行，交完整更新包。
5. **基础验收通过条件：** 声明范围内 A 级电脑检查和对应设备识别/显示/完整播放/声音/同步/方向/封面正确，CLI/GUI 实际可用；B 如实记录，C 不设保留门槛。局部样本通过不等于所有来源或整个目标完成，未覆盖、A 失败、缺设备的范围继续保持未完成。非原生格式的设备限制单列，不能掩盖软件转换缺陷或自行缩减支持范围。
6. 按 03 汇总有效证据，收口仅补必要缺口及规定节点的独立复核；不逐小修改审查、不自动 commit。手机未测不称目标收口。

## 5. 原 B 轮要求的处理（取消强制清空）

旧 S2/B 清单不再整批搬到以后：

- 主图/有效视频音频、正确方向与封面、基础颜色、目标结构及安全的实际通用缺陷仍属 A，局部修复。三星样本旧封面时间越界事实保留；目标封面须正确对应，不要求完整保存无效原字段，也不为单样本写通道。
- 常见 EXIF、标准 ICC、HDR 图片/视频/Gain Map 归 B：现成可靠能力正常保留；简单通用处理可在既有授权内完善，复杂接口/长期研究不做。不自动创建任务或新矩阵，HDR 专项须用户明确决定。
- 私有编辑/拍摄历史、历史 Original、无关附图/水印资产、辅助/定时/占位轨、填充及原容器布局归 C，退出跨协议范围，不转 P10。名称不决定等级，若实际影响当前主图或 A 功能须处理其语义。
- 正确显示前提下统一物理转正、原始音频编码逐字节一致、原厂相册编辑/恢复历史不作为 P9 保留验收要求。既有实现、有效测试和证明含义保留。

**协议完成 = 声明范围内 A 级成品及设备验收 + CLI/GUI 实测 + 必要收口复核。** 不再附加 B 待办清空或 C 完整保留；未覆盖/失败/未真机验证仍不能宣称通过。

## 6. 防止死磕

- 按根规则 0.2 的两次无进展/约 30 分钟未缩小范围提醒线，停止该问题的继续试错并主动报告，不静默攒着、不自动加模型/代理。说明要做什么、失败在哪、已试什么、影响多少行、建议下一步。
- 先判断是否影响 A、是否为通用缺陷、是否确需改架构、现有编解码/容器能力能否解决。A 失败阻止对应成品交付，不阻止其他已检查有效样本先试机；B/C 保留缺口不长时间死磕，也不因完整性/覆盖率/证明不足自建保留系统。
- 来源被改、半成品发布、虚报保留：立即停止受影响的生成/交付并报告；几乎整包手机不识别时先查共同原因，不让用户逐个重复试。安全问题也不豁免无进展汇报。
- 普通问题自主解决；需要用户决定时提前问。用户不必提供技术解法，AI 应给清楚的选项、影响和建议。
