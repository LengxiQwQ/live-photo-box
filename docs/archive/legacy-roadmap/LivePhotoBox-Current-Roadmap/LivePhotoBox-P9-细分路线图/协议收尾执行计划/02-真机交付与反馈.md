# 真机整包交付与反馈规则（实况优先版）

依据 2026-11-01 用户决定：允许先交已通过电脑检查的完整有效样本进行设备测试，不等待所有来源/变体；失败成品不交，失败和未覆盖仍如实记录，不冒称完整矩阵通过。媒体按 [A/B/C 契约](../../12-中性媒体契约.md) 验收；保留平铺和命名规则，不再以整包齐全阻止试机。

## 1. 一个平铺取件文件夹

固定目录：`.ai-tmp/workspace/P9/target-writers/R8/device-delivery/`

- 所有已准备目标的当前成品**直接放在这一个目录里，不建子文件夹**。
- 只放当前有效版本；旧版本、诊断文件、日志、manifest 原件放在取件目录之外的 `documentation/`、`results/` 等内部目录。
- 不压缩，不另外复制到桌面或盘符根目录，不替用户操作手机或上传。
- 本批交付样本各自完整有效且电脑检查通过后给路径和范围说明，停下来报告；可以是明确标注覆盖范围的成功子集，不称全来源整包。设备不可用时报告“本批电脑通过、手机未测”，不催用户找设备。

## 2. 整包怎么生成

由一个调度脚本完成（脚本只调度正式 CLI，不自己改成品）：

1. 按已授权目标和本次风险选择真实样本/格式，正式 CLI（兼容档）生成；308 行清单保留，不每次全跑。
2. 每个拟交付成品按 A 级做电脑检查（[03-测试与复核规则](03-测试与复核规则.md) §2），B 的已知状态如实记录。
3. 生成/检查失败留内部清单并按 A/B/C 分类，不把坏文件交用户。已检查的完整样本可先发布本批测试集；双文件成套。其他组合未完成照实保留；不得用旧版同名成品充数或把部分交付称为全范围通过。
4. 交付生成 `测试清单.csv`、`开始测试.txt`；`失败清单.csv` 留在内部 `results/` 供开发定位，报告阻塞时给白话摘要，不要求用户拿失败项去测。
5. 写内部 manifest：每行的 CLI 命令、退出码、输入/输出 hash、自检结果、`notCarried` 摘要。

**交付前提是每份交付样本完整有效且已通过电脑检查，不是该目标所有组合均通过。** 不能转换与设备不兼容分开记录；A 失败由开发处理，不以设备限制掩盖。部分样本先试机不等于缩减范围，未覆盖/失败/未测清单须随批次说明。

## 3. 文件命名

格式：`案例ID__源-来源协议-来源格式__到-目标协议版本-目标格式__r修订号.扩展名`

```text
G2-001__源-Apple-HEIC+MOV__到-GoogleV2-JPG+MP4__r1.jpg
AP-014__源-小米V2-JPG+MP4__到-Apple-HEIC+MOV__r1.heic
AP-014__源-小米V2-JPG+MP4__到-Apple-HEIC+MOV__r1.mov
```

- 案例 ID 前缀按目标区分（G2 = Google V2、G1 = Google V1、OP = OPPO、AP = Apple、V2X = 旧 vivo……），编号稳定，修订后只改 `r` 号。
- 双文件同 basename，只差扩展名。
- 名称保持简短、Windows 合法；媒体特征（编码、HDR、降级）写在测试清单里，不塞进文件名。
- 某个设备对导入文件名有实际要求时按设备要求，并在清单里保留对应关系。

## 4. 交付说明与内部失败记录

**`开始测试.txt`**（白话，一屏以内）：这次是哪个目标、第几版、多少个文件、哪些是新修的要重测、在手机上怎么导入、看哪几项、怎么反馈。

**`测试清单.csv`** 列：案例ID、文件名（双文件写两个）、来源、目标及格式、是否原生变体、电脑自检、HDR/降级说明、本次是否需测、手机结果（用户填或 AI 按反馈填）、失败现象。

**内部 `失败清单.csv`** 列：来源、目标格式、失败阶段（提取/媒体转换/写入/校验发布/自检）、一句话原因、已试办法与结果、影响行数、下一步（A 通用修复 / B 现成能力或如实降级 / C 退出保留要求 / 未明确影响待判断）。按等级处理而非全部转 B；旧失败不因退出保留要求就改为成功，修复记录和证据保留。

## 5. 用户怎么反馈

用户可以直接说“G2-003 不识别，G2-007 没声音，其余正常”，或填测试清单。AI 负责把结果写进 `coverage.json` 和 TODO。

A 轮请用户看：
1. 能否识别为实况；
2. 能否完整播放，有无卡顿/黑屏/截短；
3. 来源有声音的，成品有没有声音；
4. 方向对不对；
5. 封面画面对不对；
6. 音画是否同步、照片是否明显失真或严重偏色。

常见 EXIF/ICC 与 HDR 的现成保留效果可以顺便记录，缺失不自动立项或判 A 失败；确由通用转换错误造成明显损失仍需定位。原厂封面编辑/恢复历史不是跨协议保留要求，不自动记入 B 待办。

## 6. 修复后交付

- 修复后重新生成受影响的行，替换取件目录中对应文件（`r` 号加一），没变的文件原样保留，`开始测试.txt` 写明只需重测哪些。
- 换版前把旧版成品和 manifest 移到内部历史目录。只移动 manifest 明确属于 AI 生成的文件；发现用户自己放的文件或无法确认来源的文件就停下报告，禁止递归清空目录。
- 一个目标交付后停下来报告；用户继续或明确授权并行准备后，才准备下一个目标。下一个目标也可先提供通过检查的完整样本，范围如实标注。

## 7. 商场组

新 vivo、三星、华为、荣耀可集中交付已检查的有效样本，附所需品牌/机型/系统版本清单，方便一次出行；不要求所有来源或所有目标齐全才开始试机。现场没有的机型与未准备组合记为未完成，不影响其他已测结果。

## 8. 状态说法

分开记录电脑“未执行 / 生成失败 / 检查失败 / 本批通过 / 全范围通过”和手机“未测（可注明缺设备）/ 失败 / 已测范围通过”，同时列明覆盖范围。收口另记“待验收 / A 基础验收收口 / 范围未完成”；不再有强制“B 待做”。电脑成品不等于手机通过，一台手机的结果只代表该机型/系统/相册及实际文件。
