## 2. 本轮代码修复

生产修改限于 `LivePhotoBox.Native/src/containers/heif.cpp`、`heif_internal.h` 与 `src/media/media_inspector.cpp`。新增三类复用回归，并给既有真实 OnePlus 改封面用例增加两条精确时间断言；保留其他已有工作区修改。

1. **HEIF 分类不再依赖英文字符串**：在图解析实际检测位置产生内部 `heif_graph_error`；重复身份/循环为 Ambiguous，未知引用/截断/非法范围为 Malformed，不支持布局/容量限制为 Unsupported。五个生产来源检查路径统一接入；公开 C ABI、导出签名、facts 布局和依赖不变。
2. **HEIF 边界与资源约束**：`iloc` reader 限制在本 box 内，声明 count 分配前核对物理可用字节，递归下降前限制深度；分配失败有 typed 分类，失败不泄漏部分 graph 或旧 context 状态。
3. **统一 XMP 相关声明识别**：各生产路径复用 namespace URI + local-name 的字段表；HEIF 全 item 选择识别 Google V1/V2、OPPO、vivo 的部分声明及正式 MotionPhoto semantic，额外相关 packet 不再因字段列表遗漏被当作无关内容。真正无关 packet、正常局部 prefix 重绑定有正对照。
4. **时间戳遵守唯一 owner 和严格数值语义**：选定协议的可选时间字段参与同一 `rdf:Description` 检查；跨 owner、重复属性/元素与冲突拒绝，空值、小数和溢出拒绝。V2 同 owner 中过时 V1 时间按已确认协议语义忽略，保留正对照。
5. **修正 OPPO/OnePlus 当前封面事实**：当前封面使用 `GCamera:MotionPhotoPresentationTimestampUs`；原始拍摄帧使用 `OpCamera:MotionPhotoPrimaryPresentationTimestampUs`，仅缺当前值时回退原始值。真实改封面样本分别核对 **2762000 / 1280253 μs**。这是按现有协议修正可观察事实，不是改变产品语义或验收标准。
6. **畸形与超大声明防御**：畸形 XML 的 partial live 标记仍触发失败；JPEG 标准 XMP 保持既有 Ambiguous/Metadata 对外分类与原断言；Extended XMP 在按声明总长分配前验证实际 chunk 字节总数相等，拒绝短 APP1 声明 0xFFFFFFFF 的资源攻击，原有重复/重叠检查保留。

新回归共 **81 项**：HEIF status/context 15、XMP scope/packet 25、XMP timing/owner 41。全部经生产 Native DLL 的 Inspector 路径执行；不以 mock 或 harness 代替生产识别证据。正常源文件字节不变，不增加支持格式，不放宽成功条件。

## 5. 架构裁决与后续可行动事项

### HEIF 错误字符串探测

本轮已经修复；内部 typed error 与集中映射取代文案判断，无公开 ABI 扩张。该项不再作为留给未来阶段的 P1 blocker。

### Apple 托管 / Native 双重写入

P1 的 `TryReadContentIdentifierFromImage` 已调用 Native inspection facts 并校验容器所有权与 UUID，不以托管全文件搜索作事实依据。当前调用搜索中，大部分托管字节修改方法只有测试调用；生产引用 `TryNormalizeExifItem` 位于 `HeicConverterService.ConvertToHeicAsync` 内，该转换入口本轮未找到调用方。这不等于整个公开修改面已安全，也不等于证明发生过生产损坏。

保留为 **P8/P9 的开放技术债，不阻止 P1 只读识别职责关闭**：

- 影响：托管 TIFF/HEIF 修改和直接覆写方法仍存在；新增或恢复产品调用可能绕过统一事务/authority。
- P8 下一步：在实际产品接线前重新核对调用图，只允许现有合法 Writer 经明确 adapter 使用；任何修改必须有适用授权、对象身份与事务。不能通过恢复这些 helper 形成生产旁路。
- P9 下一步：单一 Native structured Writer + 独立 Target Validator；将特殊补丁转成具体结构需求和回归，不保留自动托管 fallback。
- Native 现有注入 primitive 在生产下受 cleanup-plan authority 门禁，test harness 不同；不能简单从 C# 换调该函数、关闭门禁或借 Cleaner 授权冒充 Writer 授权。
- 完成条件：适用 Writer authority、保留约束、失败事务、fresh reopen validator、外部参考和真机验证完成，再切换并移除过时实现。公开接口变更另行评审。
- 阶段归属遵循现行路线：P3 Cleaner、P4 Native/后端基础、P6 中性流水线、P9 Writer；不采用原报告“P4 Writer / P6 Cleaner”的错误归属。
