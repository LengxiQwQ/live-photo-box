# P5 视频元数据保留接口扩展

2026-10-20，当前用户批准在本次 P5 复审内扩展 Contract/ABI，完整解决后再收口。
依据是实际 Strict 转码成功返回却丢失合法顶层 UUID box，且既有静态元数据
映射仅覆盖 movie/video track，未覆盖 audio track。本决定不降低既有验收条件。

Native ABI 升至 11，新增版本化视频转码请求与逐项保留事实。旧转码入口仍须执行
相同保留门槛，不能成为绕过入口。策略必须传至 Native 真正发布前的验证点。
有损视频重编码仍可按明确请求成功，不能因此把整体结果标为无损保留。

新增支持范围：顶层、movie、video/audio track 的 UUID opaque byte asset，按
合法 box hierarchy、scope、16 字节 user type 和完整 box 字节绑定；保证此资产
的字节保留，不推断私有 payload 的厂商语义或外部引用。相同 scope/user type
重复、短 UUID、非法边界及无法映射的 track 关系必须拒绝。已知携带容器引用的
结构不因具有未知 payload 而被视为安全 opaque asset。audio track 的既有
offset-free meta/udta 规则与 video/movie 一致，映射要求唯一且可验证。

事实来自持有源文件租约时的源字节以及发布前实际 staged output 的合法结构解析
与逐项精确比较，不能由“已尝试复制”、backend 返回成功或产品再次读出替代。
结果必须说明策略、覆盖数量、opaque/audio 数量及实际验证状态。Strict 和
BestEffort 均不得默许未授权的非 live metadata 丢失；不能安全表达的引用图继续
Unsupported。详细命令、失败复现、逐项清单和产物位于
`.ai-tmp/workspace/P5/P5-audit-closeout/`，最终结论写入 P5 审查与修复报告。

映射细化：视频 sample entry 的 clap/pasp/渐进式 fiel 在编码尺寸不变的前提下
逐字节搬运和验证；不把 interlaced fiel 贴到渐进编码输出上。edts 仅接受经过
结构检查、正常速率的 elst；codec sample entry 的 data_reference_index 必须
绑定唯一的 self-contained url/QuickTime alis 条目。A/V 内层未知资产或引用图
没有映射时在编码前 Unsupported，不因外层容器已知而忽略内部未知内容。

stsd、sample/chunk/timing 表是 codec/timeline 结构，不是 opaque static asset。
只允许已理解且当前 backend 契约可重建的结构：HEVC sync sample grouping 必须
有合法描述、索引和覆盖所有 sample 的 run；未知 grouping type、未支持的优先级
或 shadow 表均拒绝。源/输出的实际视频样本数及逐帧呈现区间仍执行既定 Native
验证，音频仍执行既定独立解码/packet 证据。scoped metadata receipt 不能替代
这些证据，也不能把 Audio/Timing 从 NotEvaluated 凭空提升为 Preserved。

Copy/remux 的保留验证只读 moov/UUID 和真实 mdat 的范围，不把占位 mdat 当作
payload 证据。MEBX 的 sample description、mdhd、tref/cdsc、sample/chunk 表须
针对真实源/输出范围合法；发布前只归一化实际重定位的 chunk offset，比较完整
轨道，并用有界缓冲区比较实际对应的 MEBX payload。纯 Copy 因此仍保持流式
处理 A/V payload，不为 metadata receipt 分配整个视频大小的内存。

事实尺寸明确为 visual sample entry 的编码像素尺寸，不能使用 tkhd 显示尺寸。
例如 1920×1440、pasp=4:3 的 MP4 可使用 2560×1440 的 tkhd 显示尺寸；它没有
把编码分辨率放大。tkhd v0/v1 的旋转矩阵按各自合法布局读取，只支持当前模型能
表达的标准四方向旋转；未映射的 affine/perspective/translation 不报作普通旋转。
当前 sidecar 的 PCM 音频是 packet copy，MOV 的 sowt/默认 mono-stereo chan
和 MP4 的 ipcm/pcmC 属于已理解的 codec/container 描述；严格检查描述长度、
配置和引用，仍拒绝未知声道描述/bitmap，而不据此宣告音频无损证据已完成。

复审补充映射（本次已批准范围内，仍待实际验证）：

- OPPO movie/lpex 仅接受实际样本观察到的闭合 inline grammar：
  LivePhotoExtension、非负有限 coverFramePts、固定 desc、matrixCount=0、version=0、
  videoOrientation=0。完整字节计入 scoped receipt；未知字段、重复 box、矩阵及
  其他版本均拒绝。不能把任意未知 box 当作无引用资产。
- Huawei HEVC sample-entry/cuvv 仅接受冻结真实样本的 22-byte configuration，
  逐字节迁移并复读；未知配置和非 HEVC association 拒绝。它不替代实际 HDR
  bitstream/精度/色彩独立验证，也不授权 H.264 静默降级。
- 外部 probe 发现 vivo HE-AAC stereo 在 MF 转码后变 mono。压缩媒体类型可能
  只描述 AAC core；改用软件 decoder 的自然 PCM 布局，再做原有采样率归一化。
  该缺口未因旧 validator 只核对音频流数/时长而获得豁免，必须独立解码重验。

Header metadata completion (META-08):

`mvhd` / A-V `tkhd` / `mdhd` source creation/modification times, flags, non-timeline
attributes, language and complete `mdia`/optional `minf` handler boxes are mapped.
Timed headers use v1 encoding to retain 64-bit values. Only actual target track IDs,
timebase/duration and movie next-track-ID are regenerated. Receipt scopes 5..13
cover canonical v1 projections with precisely those target-owned fields zeroed;
all other bytes are compared from actual before/after structures. Box counts also
include each present header projection. Existing scopes0..4 remain exact assets.
QuickTime movie preview/poster/selection/current-time fields (ISO pre_defined6words)
require separate timescale mapping when nonzero; these are rejected at preflight,
not copied and mislabeled preserved. Frozen mandatory samples have all six zero.

META-10：handler name 不能只复制原始字节。权威 `ftyp` major brand 决定
QuickTime Pascal length-prefix 或 ISO trailing-NUL 表达；在相同 byte length 内
转换，完整保留其余 handler prefix/vendor/flags。重复/缺失 ftyp、长度不符、
内嵌 NUL、缺少 ISO terminator、超过当前有界表达的名称均拒绝。receipt 的
handler projection 使用 canonical ISO NUL 表达；MEBX 比较只归一化该名称表达，
仍核对完整轨道、引用、时间线和实际 payload。Copy 在 owned staging moov 内
同长更新并复读后验证，不修改 A/V packet。当前事实证明名称 bytes 的容器表达
正确，不宣称任意厂商字符集到 Unicode 的转码能力。

当前候选的 metadata-v11 50/50、独立 derived-real routes 8/8 和 Huawei 原始
MEBX local-zero 两路线均通过；完整最终结论与身份见 P5 审查与修复报告。
P5R5 验证器 E2/E3/E4 是离线路径/诊断投影/真实缺包构造纠错，保留冻结
profile 原始文件和所有 route、failure、阈值、owner、skip 条件。UTF8 Exif
argument-file launcher 仅供离线验证，官方二进制、stdout/stderr 与 exit 原样保留；
未增加生产运行或打包依赖。
