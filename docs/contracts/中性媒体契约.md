# Neutral Media Contract — Live Photo Box 中性媒体宪法 V4.0

> **Document role:** Cross-phase architectural contract\
> **Applies to:** 当前合成、拆分与共用媒体流程\
> **Authority:** 当前用户指令与现行工程规则。旧施工路线图已封存，不再调度任务。\
> **Change rule:** 产品策略由当前用户明确决定；技术模型变化须有真实协议/媒体/设备依据，不能为了某个 Writer、平台或 library 图方便而放宽安全与正确性。
> **现行策略：2026-11-01 用户确认的 A/B/C 分级。** 本文第 0 节与 N9 取代旧“未知内容全部保留否则拒绝”“目标能承载就必须补实现”及强制 A/B 两轮保留收口要求。历史证据和已实现 ABI/证明的精确含义不追溯更改。

---

# 0. 产品目标与三级媒体保留策略（唯一分级定义）

Live Photo Box 将不同品牌、不同格式的实况照片转换为目标设备能正常识别、显示和播放的实况照片；不是媒体无损归档工具，不以完整迁移厂商私有数据、编辑历史、全部辅助轨或原始字节为目标。允许正常重新编码、容器变化及合理位深转换；优先复用 P5/P6 已有通用转换和中性流水线，避免无必要重编码，不重新打开整个媒体工程。

## A 级：必须正确的基础内容

- 主图片完整、可解码，画面无明显失真或严重偏色。
- 主视频完整、可解码、可播放，时长正确；来源有有效音频时保留正常声音及音画同步。
- 图片、视频的方向、旋转和镜像正确；实况封面、封面时间和视频内容正确对应。
- 目标协议必需的配对信息、标记、索引、偏移及必要元数据正确生成。
- 文件结构合法，来源文件不损坏、不被修改，输出安全发布。
- 正常处理基础颜色信息和常见拍摄信息，不因转换实现错误造成明显数据丢失。

可按目标要求进行通用图片转换、视频/音频转码、容器重封装及合理位深转换。A 级检查内容和最终功能，不要求每个原始字段、轨道、编码或字节原样保存。基础颜色解释若影响正常画面属于 A；常见拍摄字段不再逐字段一票否决，不能据此忽略已确认的通用映射错误。

## B 级：有现成能力就保留的重要信息

包括常见 EXIF、标准 ICC 和其他常见可兼容图片元数据，以及 HDR 图片、HDR 视频和 Gain Map。

1. 现有工具、库和通用流水线能可靠保留的，正常保留；简单、明确、通用且不影响主线的处理可在已授权范围内完善。
2. 不为 B 级另设计大型接口、特殊数据格式、复杂保留协议或长期研究；不以“目标可承载但实现缺失”为由强制补齐。
3. HDR 有画面价值，但低于 A 级。兼容模式不能保留时可正确转 SDR，画面须正常并记录 `DegradedToSdr`，不得宣称 HDR 已保留；不能因此阻塞已满足 A 的普通转换。
4. **这不是全部必须实现的待办清单，不自动生成新任务或跨品牌测试矩阵。** HDR 专项增强仅由用户明确决定后启动。
5. HDR 不等于主图必为 10-bit。曾观察到样本可能为 8-bit HEIC 主图配高位深 Gain Map，仍待核实；不得推广为所有 HEIC/HDR 的事实，也不因此启动研究。

## C 级：不作为跨协议保留目标

- 来源厂商私有拍摄记录、编辑历史、相册状态、缓存、调试与专用处理记录。
- 与正常播放无关的私有辅助视频轨、定时元数据轨，以及没有实际媒体内容的占位轨。
- 历史 Original 文件、编辑前版本及与当前主图/实况播放无关的额外辅助资产。
- 原始 JPEG 填充、历史容器布局和无实际功能意义的原始字节。
- 来源协议绑定标记、配对 ID 等不需传给目标协议的数据；目标要求的信息重新生成。

C 级退出跨品牌开发范围，不移交 P10、不另建 B 轮，不为其新增 metadata 承接通道、私有 UUID/APP 封装、Native ABI、Writer 或复杂完整保留证明。已有正常实现和有效测试保留，不因本策略立即删除，但不作为默认转换要求或继续扩建。

**按实际语义而非字段名称分类。** 私有数据若承载必要封面时间、颜色解释、播放信息等 A 级功能，必须提取该语义，交由通用模型/转换器或目标 Writer 正确处理。清除来源协议不等于盲删正常媒体；不能把尚不明确、可能影响 A 的数据直接当 C，也不能因“未知”强制完整搬运所有字节。

## 执行边界

- 流程：Source Inspector / Extractor / Cleaner → Neutral Media → 通用媒体转换 → Target Writer / Validator → 安全发布。来源侧识别协议、提取有效媒体和清理绑定；Neutral 表达通用内容；转换器只按图片格式、视频编码、容器、音频、方向及目标能力选择处理；Writer 重新生成目标协议。
- 两端合理的来源解析/目标写入差异允许存在。中间禁止按单张照片、文件名、来源型号、品牌或样本 hash 增设专用通道；失败须定位可复用的通用能力缺陷。
- 阻塞先问：是否影响 A、是否为通用缺陷、是否真需改架构、现有编解码/容器能力能否解决。B/C 不得长时间死磕，不以保留完整性、覆盖率或严格证明不足自行扩建系统。
- 如实记录已知操作、未承接和降级；不要求为每项 C 数据新建逐字节清点/证明系统。`Preserved` 等已有结果只能在实际证明范围内使用。
- 既有 Strict 可保留为显式选项，其实现、测试和精确证明语义不因文档更改而改松；Strict 的额外拒绝不是默认转换或 P9 的新增保留门槛。本次只改文档，不宣称运行时已符合新策略。
- 日常按功能单元定向测试；合成、拆分及全部目标协议完成后，进行整体电脑验收，再集中真机实测。旧308行矩阵仅作历史线索，当前范围按实际承诺能力确定；失败、未覆盖、未真机验证分别记录，不代签。

# 1. NeutralMediaBundle 的定义

NeutralMediaBundle 代表：

> **已经从来源厂商 Live/Motion Photo 协议中解耦、媒体语义明确、保真状态可追踪，并可被任意合法 Target Writer 消费的一组中性语义资产。**

概念结构：

```text
NeutralMediaBundle
├─ PrimaryImage
├─ MotionVideo?
├─ GainMap? / Auxiliary?
├─ Timing
├─ Orientation
├─ Media properties
├─ Color/HDR facts
├─ Preservation outcomes
├─ Artifact manifest / hashes
├─ SourceProvenance          # diagnostics/history/evidence only
└─ RemovedProtocolFacts      # evidence only
```

Neutral 不是：

```text
“一张图片 + 一个视频”
```

也不是：

```text
“统一转换成 JPEG + MP4”
```

# 2. 永久不变量

## N1 — No source live binding

Neutral artifact 不继续携带会让 Source Inspector 判定为原来源 Live/Motion Photo 的 source binding。

---

## N2 — Independent media validity

```text
PrimaryImage
MotionVideo
GainMap / Auxiliary
```

必须在各自语义下结构有效。

---

## N3 — SourceProvenance is not target authority

Target Writer 不得根据：

```text
bundle.SourceProvenance.Protocol
```

决定目标协议布局。

允许用于：

```text
diagnostics
history
debug
evidence
```

---

## N4 — Target consumes semantics, not source quirks

Target Writer 消费：

```text
image
video
timing
orientation
HDR/color facts
auxiliary semantics
OutputProfile
```

而不是：

```text
“因为来源是 Huawei 所以……”
```

---

## N5 — Preservation must be truthful

至少能诚实表达：

```text
Preserved
TranscodedLossless
Reencoded
PartiallyPreserved
DegradedToSdr
DiscardedNotApplicable
Unsupported
```

“文件还能打开”不能称为 Preserved。

---

## N6 — No unnecessary re-encode

目标允许 passthrough/remux 时，不无理由 decode → encode。

---

## N7 — Orientation has one semantic

无论来源表示为：

```text
EXIF orientation
HEIF transform/property
video matrix
track metadata
```

Neutral 都应表达统一的视觉/媒体语义。

Target Writer 不回头猜来源表示。

---

## N8 — Timing has one semantic

cover/key timestamp、duration、frame/timing 等目标 Writer 需要的时间语义统一表达。

---

## N9 — 按 A/B/C 语义保留，不以未知字节完整承接为默认门槛

统一执行第 0 节：A 必须正确；B 现成可靠能力正常保留、必要时如实降级；C 不作为跨协议目标。未知名称不是删除授权，也不是必须新建承接系统的理由；先判断其是否影响基础媒体、封面、颜色或目标协议。

同容器提取/清理优先不动无关内容，Cleaner 仍只执行明确授权的来源绑定清理；跨容器/编码转换可以按本分级重建内容，不必搬运所有记录、轨道和原始布局。B/C 的未承接不单独阻止满足 A 的普通转换；实际结构损坏、范围/身份歧义或无法保证 A/安全时仍应拒绝并说明具体问题。不能以“未知数据可能没全带过去”代替风险判断。

既有 Strict 的拒绝及完整保留证明只描述其显式范围，不推导默认转换必须修好所有保留能力；BestEffort 也不能放宽 A。已知降级与损失按 N5 如实表达，不伪报 `Preserved`。

---

## N10 — Neutral success is verifiable

Neutral success 必须有：

```text
post-clean Source Inspector result
+
artifact structural/media validity
+
manifest/evidence
```

---

## N11 — Auxiliary/HDR representation is unambiguous

GainMap/Auxiliary 是 semantic asset，不等于“有一个文件就应该 append”。

必须区分：

```text
Embedded
Detached
Embedded + detached working representation of same asset
```

Target Writer 不得因为：

```text
bundle.GainMap != null
```

就自动再次写入。

同一 semantic GainMap 不得重复。

---

## N12 — Platform-neutral semantics

NeutralMediaBundle 的 correctness 不依赖：

```text
Windows
Linux
macOS
browser
Win32 HANDLE
COM
WIC
Media Foundation
POSIX fd
Emscripten virtual path
```

当前 Windows implementation 可以使用 path-backed artifacts，但 Neutral semantic model 不能要求：

```text
artifact must be a Windows file path
```

长期 artifact contract 应能被：

```text
Windows file
POSIX file
memory/blob
WASM/browser-backed data
```

承载。

---

## N13 — Backend-neutral semantics

NeutralMediaBundle 不因：

```text
libjpeg-turbo
libheif
Media Foundation
libav*
WIC
lcms2
```

不同而改变其语义定义。

Backend identity 可以进入：

```text
ExecutionRecord
diagnostics
evidence
```

不能成为：

```text
Writer correctness input
preservation shortcut
protocol authority
```

---

## N14 — Media backend success is not semantic success

例如：

```text
libheif encode success
≠ HEIC target protocol correct

MF transcode success
≠ timing/color/preservation automatically correct

JPEG decoder opens file
≠ metadata preserved
```

所有 semantic outcome 必须由 LivePhotoBox contract 判定。

---

# 3. Neutral Pipeline 禁止事项

禁止：

```text
Target Writer parses original source again
Target Writer branches on source vendor
Cleaner blindly deletes data that may carry A-level semantics
Converter silently degrades HDR
Extractor guesses range
Neutral keeps source protocol residue “反正 writer 不看”
Target Writer treats detached auxiliary artifact as append instruction
Neutral stores Windows/backend-private objects as semantic authority
Neutral chooses protocol layout based on codec backend
```

---

# 4. Neutral 与媒体格式

合法 Neutral 可以是：

```text
JPEG + MP4
HEIC + MOV
HEIC + MP4
JPEG + MOV
...
```

实际媒体准备由：

```text
MediaFormatRequirement
```

决定。

目标组合：

```text
OutputProfile
= TargetProtocol
+ MediaFormatRequirement
+ target-specific options
```

Neutral 的核心：

> **协议解耦 + 媒体有效 + 语义明确 + preservation 可追踪。**

---

# 5. HDR / GainMap

GainMap 不是 Live Photo 协议本身。

Cleaner 不因删除 MotionPhoto binding 而误删 HDR 所需 GainMap。

HDR / GainMap 属 B 级；现成可靠路径正常使用，不要求为了跨品牌完整保留扩建接口或研究项目。无法可靠保留 HDR 时，兼容模式可正确输出 SDR，必须保证正常画面并：

```text
must report degradation
```

不得 silent SDR。

实际承接 GainMap 时必须表达：

```text
semantic identity
embedded/detached state
relationship to PrimaryImage
metadata model/headroom facts where required
```

---

# 6. Color

Neutral 应区分：

```text
ICC/profile preserved
color transform performed
color metadata mapped
color information lost
```

不能用：

```text
“codec backend 成功”
```

替代 color correctness。

---

# 7. Manifest

正式 artifact manifest 至少能表达：

```text
role
stable artifact identity
byte length
hash
container
codec where applicable
semantic representation
preservation outcome
auxiliary ownership/relationship
```

`path` 可以存在，但不能是唯一 artifact identity/semantic representation。

---

# 8. Architecture Guards

应防止：

```text
if (SourceProvenance.Protocol == ...)
```

重新进入 Target Writer correctness。

也防止：

```text
if (backend == MediaFoundation) ...
```

改变 target protocol semantics。

也防止：

```text
GainMap artifact present
→ unconditional append
```

---

# 9. 修改本 Contract 的条件

当前用户明确的产品策略更新可以修改本契约（本次为 2026-11-01 A/B/C 决定）。技术模型调整仍应依据：

```text
真实协议样本
真实设备行为
媒体标准事实
当前模型无法表达的真实 requirement
```

不能因为：

```text
某个 library API 比较方便
Windows 路径这样写更快
某个 Writer 想少传几个字段
```

就放松。

全局执行规则见 `00`。
