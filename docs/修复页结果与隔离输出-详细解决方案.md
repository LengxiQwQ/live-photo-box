# 修复页结果与隔离输出：详细解决方案

日期：2026-11-06。状态：M2 实现与定向电脑检查完成；GUI 实操待用户。最新结果以总体实施计划的 M2／M3 执行记录为准。

后续范围说明：本文件是结果、显示及输出记录的专项方案，不是媒体能力补齐方案。当前总体顺序以[华为实况修复与 HDR Vivid 实施计划](华为实况修复与HDR-Vivid实施计划.md)为准，本文件用于其中 M2；其原“本专项不新增视频烘焙”边界不能用于阻止总体计划 M1 的后端施工。此前问题现状仍按原报告保留。

## 1. 交付目标与边界

每个文件处理结束后，直接回答五个问题：**修了什么、没修什么、为什么没修、有没有成品、成品在哪里。** 颜色只能概括结果，不能替代这些事实。

- 范围覆盖修复页、共用 Repair 服务、实际输出定位、汇总／通知、CLI 对应结果和修复终态日志；按共享问题统一处理 Apple、Samsung、Huawei、旧 vivo 及现有普通媒体分支。
- 默认仍仅处理 Apple／Samsung；不扩大默认设备范围。
- 保留现有媒体安全、发布、身份、原件保护与逐项继续规则。普通未知私有数据能保留就保留，不因不认识就整项拒绝，也不为绿灯猜配或删除未知数据。
- 不恢复两项 HDR Vivid→H.264，也不把本次结果改造扩成新增华为视频方向烘焙、所有品牌／所有机型兼容工程。
- 不新建一套错误界面、隔离管理器、撤销导出系统或数据库。继续使用队列、详情提示、现有发布器和日志位置。

## 2. 先修结果模型，不能只换一句文案

在共用服务建立一份轻量、有明确类型的逐项结果。现有 `Status`、`Image`、`Video` 等字段保留为兼容投影；新增字段作为界面、CLI、汇总和日志共同使用的事实来源。

| 结果内容 | 必须包含的事实 |
|---|---|
| 整体完成情况 | 已完成、无需修复、部分完成、未完成、跳过、失败、取消 |
| 用户选择 | 本次实际选择的照片方向、缩略图、HEIC 对齐、视频方向动作；区分禁用与尚未实现 |
| 各动作结果 | 未选择、检查后无需修复、完成并验证、未完成、失败；有未完成项必须附原因码及中文说明 |
| 已发布输出清单 | 文件角色、真实绝对路径、普通输出／隔离输出／原样副本；只记录已通过现有发布流程的最终成品 |
| 隔离或待确认原因 | 可关联到图片、视频或整组；不能仅有笼统的“未验证” |
| 技术诊断 | 保留 Native 原文和内部信息用于日志；用户详情首先显示经过解释的中文 |

完成动作以实际成品为准。仅在暂存文件中做过修改、但最终发布失败，不能计为用户已获得修复成品；暂存过程只保留在技术诊断中。无需修复与原样复制不进入“已修复”数量。

不通过解析英文消息、文件名或路径中是否含 `_isolated` 来猜结果。服务在决定动作及发布时直接填写事实。现有 Native 已提供的动作位、未完成位、方向和输出凭据继续复用，本阶段不为界面显示新增 Native ABI。

## 3. 状态、颜色与输出的明确规则

| 实际结果 | 颜色／显示 | 是否有输出 |
|---|---|---|
| 所选检查完成，原文件无需修复 | 绿色：检查完成，无需修复 | 默认无输出；用户选择复制时另列原样副本 |
| 所选修复全部完成、验证及发布成功 | 绿色：已修复，已导出 | 有实际普通输出路径 |
| 完成部分修复，仍有相关动作未完成 | 黄色：部分修复，隔离导出 | 有实际隔离成品，并列出剩余动作 |
| 动作已完成，但有关成品语义仍有明确未确认项 | 黄色：修复动作完成，仍需确认；隔离导出 | 有实际隔离成品，明确待确认内容 |
| 未完成所选动作，未生成副本 | 黄色：未完成，未导出 | 明确显示“无”，绝不能出现“已隔离” |
| 用户选择了复制，但该文件仍有未完成项 | 黄色：原样复制至隔离目录，未修复 | 有实际隔离副本，不能计入已修复 |
| 来源确实损坏、完全不支持或安全发布失败 | 红色：处理失败，未导出 | 不列不存在的成品；仍继续其他独立文件 |
| 按用户选项或默认设备范围跳过 | 沿用中性跳过状态，并给具体原因 | 无本次成品 |
| 用户取消 | 已取消，说明本项是否已发布 | 已完成的其他文件结果保留，不能整批重写成取消 |

### 不可违反的约束

1. **没有已发布输出，就不能显示、统计或记录“已隔离导出”。**
2. 每份隔离输出必须有明确原因、真实路径及角色；若同时有图片和视频，逐份列出。
3. 未知普通私有字段本身不构成隔离理由。只有它实际影响当前动作、基础媒体语义或有关验证时，才记录相应限制。
4. 某个成员动作完成，但整组输出被隔离，行内应显示“照片已修复，整组隔离（视频尚未完成）”，不能把照片说成没修，也不能掩盖视频限制。
5. 输出后来被用户移动／删除时，显示“当时已导出，当前路径找不到”；不能重建空文件夹掩盖，也不能把历史成功自动改成来源损坏。

## 4. 原因必须说到具体动作

服务各分支把当前自由文字归纳为稳定的原因码，至少涵盖：内嵌视频方向未实现、配对缺失／歧义、JPEG 完美无损变换不可用、元数据动作未能安全执行、视频元数据保留未完整验证、来源发生变化、发布失败、用户未选择。

同一个原因码必须附本次上下文，例如是哪份配对文件缺失、视频带什么显示方向、哪个动作没做、哪些字节保留。不能只写“格式特殊”“不安全”“未知数据”“已隔离”。

以下为 M1 实施前的历史华为情况；M1 已实现现有两份样本的视频修复，受限变体继续采用这些未完成状态规则：

- 说明“照片检查完成，未发现需修复项；视频带 90° 显示旋转，本次没有执行画面转正；原视频保留”。
- 不把显示矩阵本身称为视频损坏，不把“保留 HDR 原字节”说成 HDR 已修复。
- 未实际修复且未复制时，输出明确为“无”；绝不显示隔离目录。
- 内嵌视频方向尚未实现是能力边界，不能用界面改字掩盖，也不能擅自开始此前暂停的 HDR 工程。

普通复合 JPEG、旧 vivo、Apple 与 Samsung 的相应分支采用同样原则；内部错误保留诊断并正常结束受影响项，不伪装成文件坏了。

## 5. 界面怎样展示

队列状态保留短文字，详情复用现有提示组件，统一按以下顺序组织：

1. 本项结论：全部完成／部分完成／未完成／无需修复。
2. 已完成的检查与已完成的实际修复，分别列出。
3. 未完成动作及原因；用户未选的动作单独标明，不冒充失败。
4. 输出情况及可复制的完整绝对路径；无输出明确写“本次未生成文件”。
5. 原件处理情况；只有实际确认的行为才能写“原件保留”。

示例一：只有检查，没有成品。

```text
结果：未完成，未导出
照片检查：完成，未发现需要修复的项目
视频：未执行画面转正
原因：内嵌视频带 90° 显示旋转，当前华为照片修复路径尚未执行该动作
输出：无，本次未生成文件
原件：保留
```

示例二：有部分修复成品。

```text
结果：部分修复，隔离导出
已修复：清理了独立预览图
未完成：内嵌视频画面转正，视频保持原字节
隔离原因：所选视频动作尚未完成，不能将整份实况照片标为全部修复
输出文件：〔实际发布文件的完整绝对路径〕
原件：保留
```

不把技术堆栈和大段英文放在第一层；技术原文继续进入既有日志。没有添加新的媒体处理动作时，不能仅因改文案而把黄色升级成绿色。

## 6. 修复选项统计与执行对齐

- 以动作事实统计，停止用“HEIC 文件＋NeedsRebuild”代替“需要 HEIC 对齐”等具体判断。
- 内嵌主视频、三星自动播放视频、配对视频及独立视频，分别按实际检查结果计入视频动作数量。
- `Limited` 项不能在选项统计中消失；明确其中哪些动作可完成、哪些暂未支持。
- “用户未选择”与“目前不支持”分开。暂未支持的动作可以显示能力限制，但不能显示 0 个后灰色隐藏，同时在后台保留默认 true 并制造意外结果。
- 原本可选择的动作允许用户关闭。关闭的视频动作不计入本次未完成项；详情仍可说明视频原样保留，不声称它已被转正。
- 本次不增加四类现有修复选项以外的大型能力菜单。照片范围的实际修复仍按已授权动作处理。

## 7. 输出位置必须来自实际发布记录

- 队列每项保存 `PublishedOutputs`，详情列出真实图片／视频路径，使用实际命名避让后的名字。
- 复用现有文件定位能力，为有实际成品的项提供“打开所在位置”；隔离项定位实际 `_isolated` 成品所在目录，不让用户猜子目录。
- 批次输出按钮依据本次实际输出集合启用。没有成品时禁用并说明“本次没有导出文件”；不通过创建空目录制造“有输出”的表象。
- 输入目录浏览仍保留。配置输出位置与本次成品位置要明确区分；即使配置目录有旧文件，也不能计为本次输出。
- 原样复制、隔离副本和真正修复副本都保留其独立事实。路径消失时给普通提示，不自动移动、重建或覆盖用户文件。

## 8. 汇总、通知、CLI 与日志统一

### 汇总与通知

文件总数仍按文件计，文件对／任务数另列，不能混加。至少分别统计：已修复、检查正常、部分修复并隔离导出、未完成且未导出、原样复制、跳过、失败、取消。分组隔离信息不能因成员状态是 success／copied 而丢失。

所有显示位置使用同一个结果汇总函数。通知如果有未完成或待确认项，必须明确说“仍有 X 项未完成／待确认”，不能仅凭 failed=0 暗示整批全部修好。

### CLI

保留现有命令、参数、旧 JSON 字段及当前退出码约定；本轮不擅自把 warning 的退出码从 0 改为其他值。增加动作结果、输出类型、隔离原因和真实输出清单，普通文本也明确说明是否导出。文档说明退出码 0 不等于所有项都完成修复，调用方需要查看逐项完成情况。

### 持久记录

在现有日志目录中增加 Repair 专用逐项终态记录，例如 `LPB_REPAIR_OUTCOME_V1` 标记，复用现有日志文件与保存机制，不建新数据库，不扫描全盘寻找成品。

记录来源路径、本次选项、完成／未完成动作、原因码、结果分类、最终输出清单、发布类型和时间。已经有的身份／输出凭据复用，不为记录日志重新解码或重复计算整套媒体指纹。

现有 Split／Merge 历史格式和验证规则保持原状，不能强行把无输出的 Repair warning 塞进必须带隔离输出的旧结构。Repair 日志写入失败只提示记录缺失，不撤销已经成功发布的媒体，也不伪造修复失败或成功。

## 9. 实施顺序

1. 建立轻量动作／输出结果类型，逐个适配普通图片、配对视频、单视频、Huawei、Samsung 服务分支；媒体字节算法及既有发布保护不做无关改动。
2. 统一结果投影、队列文字、详情、成员与整组关系、汇总和通知，首先消除无输出却显示已隔离的问题。
3. 接通真实成品定位和选项计数，确保界面所选动作与执行一致。
4. 增加逐项终态日志和 CLI 增量字段。旧运行缺失的事实仍标未知，不能靠新模型回填成“当时已导出”。
5. 完成下面的定向验证，按实际结果汇报；不重复整个合成／拆分电脑验收，不恢复 HDR 转码施工。

## 10. 验证与验收条件

| 场景 | 必须验证的结果 |
|---|---|
| Huawei 现有两份原图、全选、照片无需修改 | 实际视频完成，完整实况导出成功；照片不伪称已改动 |
| Huawei 受限变体，没有实际完成动作 | 黄色“未完成，未导出”；没有隔离字样、路径或隔离数量；说明具体未完成动作 |
| Huawei 只选可完成的照片检查 | 检查完成、无需修复；未选择的视频动作不计失败 |
| 派生 HEIC 方向冲突、只修照片 | 实际照片动作完成、普通成品存在、路径准确、内嵌视频不变 |
| 同一派生文件仍有视频动作未完成 | 部分完成、实际隔离成品存在、原因和路径完整 |
| 派生 JPEG 清理＋完美无损方向修复 | 动作和成品检查一致；不认识的普通字段保留；不裁切、不偷偷有损重编码 |
| 普通复合 JPEG 或旧 vivo 只有部分动作可完成 | 对已做和未做动作分别说明；能输出的安全副本隔离，无动作则不伪称已修复 |
| Apple 成对输出、照片完成而视频保留 | 成员动作与整组限制分别显示，汇总不遗漏整组隔离原因 |
| Samsung 照片部分受限、视频有已完成动作 | 显示具体成员结果，保留原照片的事实清楚，不只显示笼统“已处理” |
| 原样复制正常／受限文件 | 不计入已修复；正常复制与隔离原样副本可区分 |
| 零输出批次、输出目录已有旧文件 | 不能显示本次已隔离；本次输出数量不受旧文件影响，不创建空目录冒充成品 |
| 输出命名冲突、多输出、后续文件被移走 | 显示真实避让路径；逐份可定位；找不到时正常提示，不自动覆盖或重建 |
| 内嵌视频＋独立视频＋Limited 混批选项 | 计数与动作一致，支持的动作可关闭，未支持动作说明明确，禁用选项不被偷偷执行 |
| 损坏项／取消／发布失败与正常项混批 | 各项结果准确，独立正常项继续；没有半成品、虚假成功或未处理异常 |
| 应用关闭后查日志 | 每项仍能读出动作、原因与最终路径；日志保存失败不改变已经发布的媒体结果 |

先以轻量模型测试验证文案、计数、零输出和成员关系；以缓存真实样本／明确标注的派生样本运行正式 CLI，在隔离测试目录生成成品，并做必要独立验读。原始 `designs/` 样本不作为写入位置。

既有有效媒体证据在没有受到算法变化影响时复用。只对结果、路径和新增覆盖缺口补测；不以编译成功、退出码 0 或测试总数代替用户界面事实。

GUI 完成编译及模型检查后，由用户核对少量实际行为：未导出项的文字、真实隔离项的路径、成品定位、内嵌视频动作计数和混批汇总。代理不擅自接管桌面；需要实际 GUI 自动化时另按项目规则取得明确同意。

## 11. 完成标准与停止条件

只有服务结果、实际文件、队列、详情、汇总、CLI 和终态日志对同一项的解释一致，才算这次修复完成。至少满足：

- 不再有无输出却写“已隔离”的情况。
- 每个部分完成项都说得清修了什么、剩什么、原因是什么。
- 有成品必有真实路径，无成品明确为无；不能靠用户翻日志猜。
- 不因未知普通数据扩大拒绝，不因用户未选某动作伪造未完成项。
- 原件不被误处理，黄色不冒充完整成功，失败不终止其他独立项。

用户随后已授权跨阶段连续执行，不再逐阶段停止请示；按总体计划继续，只有真实用户输入／决定或设备观察成为前提时提出。仍不提交、推送、打包或发布。
