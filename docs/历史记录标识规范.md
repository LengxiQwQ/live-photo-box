## 1. 统一标识总览

| 操作 | 注入位置 | 数据格式 | 说明 |
|------|---------|---------|------|
| Merge / Split / Repair / Cover | `rdf:Description` 命名空间属性 + `XMP-dc:Subject` | 属性 + 历史条目 | 统一入口 `XmpMarkerService` |

**统一格式（v2.2.1 起，Plan A）**：

- 命名空间属性：`xmlns:LivePhotoBox` + `LivePhotoBox:Version`（3 段）+ `LivePhotoBox:Timestamp`
- **不再写 `LivePhotoBox:Action` / `LivePhotoBox:Protocol` 属性**（旧文件的这两个属性在重写时会迁移进 dc:subject 历史后删除）
- 历史条目：`LivePhotoBox:{action}@{timestamp}@v{version}@{Key=Value;Key=Value...}`，追加去重，默认开启详细记录

写入不影响任何平台对实况照片的识别：XMP 解析器静默忽略未知命名空间属性；`dc:subject` 是标准关键词字段。

## 2. 命名空间属性

### 注入内容（示例）

```xml
<rdf:Description rdf:about=""
    xmlns:LivePhotoBox="https://github.com/LengxiQwQ/live-photo-box"
    LivePhotoBox:Version="2.2.1"
    LivePhotoBox:Timestamp="2026-08-22T12:59:55+07:00"
    ...>
```

### 字段说明

| 属性 | 值示例 | 说明 |
|------|--------|------|
| `xmlns:LivePhotoBox` | `https://github.com/LengxiQwQ/live-photo-box` | 命名空间声明，识别文件是否由本工具处理的关键 |
| `LivePhotoBox:Version` | `2.2.1` | 最近一次操作时的应用版本（3 段；唯一来源 `Package.appxmanifest`） |
| `LivePhotoBox:Timestamp` | `2026-08-22T12:59:55+07:00` | 最近一次操作时间（ISO 8601 带时区） |

> Version/Timestamp 记录"最近一次操作"。每次重写都会刷新为当前值，历史操作的时间与版本在 dc:subject 条目里逐条保留。

## 3. dc:subject 历史条目

### 条目格式

```
LivePhotoBox:{action}@{timestamp}@v{version}@{details}
```

| 段 | 说明 | 示例 |
|----|------|------|
| `LivePhotoBox:` | 固定前缀 | - |
| `{action}` | `Merge` / `Split` / `Repair` / `Cover` | `Merge` |
| `{timestamp}` | ISO 8601 带时区 | `2026-08-22T12:59:52+07:00` |
| `v{version}` | 3 段版本号 | `v2.2.1` |
| `{details}` | `Key=Value;Key=Value...`，空值字段跳过 | `Source=Apple;Target=MotionPhotoV2;Format=JPG+MP4;KeyPhoto=1.5;VideoCodec=H.264` |

规则：
- 详情字段用 `;` 分隔，`Key=Value`；字段顺序固定（按构造顺序），新字段往后追加（可扩展）
- 值中不允许出现 `;` 或 `=`（`BuildDetails` 会跳过这类值）
- 条目按操作时间追加到 `rdf:Seq`，同一条目不重复
- 源文件已有历史（如之前的 Merge/Split）会在新写入时**继承迁移**，不做丢弃

### 轻量模式

设置项"详细操作记录"（`IsDetailedHistoryEnabled`，**默认开启**）关闭时写轻量条目：

```
LivePhotoBox:Merge@@v2.2.1@
```

（无时间戳、无详情；命名空间属性仍会写入。）

## 4. 各操作详情字段

### Merge（合成）

```
Source={源协议Key};Target={目标协议Key};Format={输出格式};KeyPhoto={封面秒};VideoCodec={编码}
```

- `Source`：源文件的协议（在 runner 层对**原始图片+视频**检测；Apple 双文件通过图片/视频 ContentIdentifier UUID 一致识别）
- `Target`：合成协议 Key
- `Format`：`JPG+MP4` / `JPG+MOV` / `HEIC+MP4` / `HEIC+MOV` / `HEIC+MP4(H.265)`
- `KeyPhoto`：封面在视频中的秒数（如 `1.5`）
- `VideoCodec`：`H.264` / `H.265`

示例：
```
LivePhotoBox:Merge@2026-08-22T12:59:52+07:00@v2.2.1@Source=Apple;Target=MotionPhotoV2;Format=JPG+MP4;KeyPhoto=1.5;VideoCodec=H.264
```

### Split（拆分）

```
Source={源协议Key};Target={目标协议Key};Image={图片格式};Video={视频容器};KeyPhoto={封面秒}
```

示例：
```
LivePhotoBox:Split@2026-08-22T12:59:55+07:00@v2.2.1@Source=OppoLivePhoto;Target=None;Image=JPG;Video=MP4;KeyPhoto=1.47
```

拆分输出的**图片和视频各写一条**（同一操作，各自文件内）。

### Repair（修复）

```
Source={协议Key};Target={协议Key};Fix={修复项}
```

- `Fix`：`Rotation` / `Thumbnail` / `Rotation+Thumbnail`（用 `+` 连接多个）
- 修复单文件没有配对视频，Source/Target 取文件内容检测结果

示例：
```
LivePhotoBox:Repair@2026-08-22T13:21:30+07:00@v2.2.1@Source=OppoLivePhoto;Target=OppoLivePhoto;Fix=Thumbnail
```

### Cover（封面编辑）

```
Source={协议Key};Target={协议Key};Format={格式};KeyPhoto={封面秒}
```

## 5. 协议检测

### 检测原则

文件内容标记（XMP / 二进制尾标）**优先于**配对方式（ContentIdentifier）。因为 XMP 与尾标是协议作者写入的身份标识，ContentIdentifier 只是配对 UUID。

### 识别特征（文件内容）

| 协议 | 特征 |
|------|------|
| HUAWEI | 文件尾 `LIVE_` 标记（JPEG/HEIC 单文件）；HEIC meta 为 iloc 在 iinf 之前的非标准布局 |
| Samsung / Fusion | 文件尾 `SEFH`+`SEFT`+`MotionPhoto_Data`；Fusion 另有 `LivePhotoBox:Protocol="MotionPhotoFusion"` 或历史 `Target=MotionPhotoFusion` |
| OPPO | XMP `OpCamera` 命名空间 / `oplus_` EXIF UserComment / 历史 `Target=OppoLivePhoto` |
| vivo | XMP `VCamera` 命名空间 / 历史 `Target=VivoLivePhoto`；双文件还有 JPEG 尾 JSON + MP4 uuid box |
| Google V1 | XMP `GCamera:MicroVideo` 且无 `Container:Directory` / 历史 `Target=MicroVideoV1` |
| Google V2 | XMP `Container:Directory` 中**实际含 MotionPhoto 项**（`Item:Semantic="MotionPhoto"`）/ `GCamera:MotionPhoto` / 历史 `Target=MotionPhotoV2` |
| Apple | 双文件：图片与视频的 `ContentIdentifier` UUID 一致（Apple MakerNote / MOV Keys） |

> 注意：纯 GainMap（Ultra HDR）容器没有 MotionPhoto 项，**不算** Google V2——避免把 Apple HEIC 转出的 HDR JPEG 误判成实况照片。

### 优先级

```
LIVE_ 尾标 → Samsung/Fusion 尾标 → 本工具历史 Target= / 旧 Protocol 属性
→ OPPO → vivo → Google V1 → Google V2 → （双文件时）Apple ContentIdentifier 配对
```

## 6. 解析方法

### 方法一：History 页面（本工具内置）

选择文件夹扫描，自动展示时间线。识别"本工具生成"用**三信号**：

1. 旧 `LivePhotoBox:Action` / `Version` / `Timestamp` 属性（旧文件）
2. `xmlns:LivePhotoBox` 命名空间声明（新文件）
3. `dc:subject` 中有 `LivePhotoBox:` 历史条目

详情解析：`details` 段按 `;` 拆成 `Key=Value` 字典（大小写不敏感），按字段生成中文描述（如 `Source/Target` → "从 X 转 Y"）。

### 方法二：ExifTool 命令行

```bash
# 读取历史条目
exiftool -json -XMP-dc:Subject photo.jpg

# 读取完整 XMP（含命名空间属性）
exiftool -xmp -b photo.jpg
```

> **华为合并型 HEIC 例外**：exiftool 解析不了华为 meta（iloc 在 iinf 前），读不到其中的 XMP。
> 需要字节级读取（解析 meta 内 Adobe XMP uuid box），历史页对华为 HEIC 已实现字节级读取（见 8.5）。

### 方法三：条目解析伪代码

```
输入: "LivePhotoBox:Split@2026-08-22T12:59:55+07:00@v2.2.1@Source=OppoLivePhoto;Target=None;Image=JPG;Video=MP4"

1. 去前缀 → "Split@2026-08-22T12:59:55+07:00@v2.2.1@Source=...;Target=...;Image=JPG;Video=MP4"
2. 按 @ 分割 → action / timestamp / v{version} / details
3. details 按 ; 拆 Key=Value 对
4. 兼容：无时间戳的轻量条目（"Split@@v2.2.1.0@"，旧 4 段版本）也能解析
```

一张照片经历 Merge → Split → Repair 后：

**命名空间属性：**
```
xmlns:LivePhotoBox="https://github.com/LengxiQwQ/live-photo-box"
LivePhotoBox:Version="2.2.1"
LivePhotoBox:Timestamp="2026-08-22T13:21:30+07:00"
```

**dc:subject 条目（按时间排序）：**
```
LivePhotoBox:Merge@2026-08-22T12:59:52+07:00@v2.2.1@Source=Apple;Target=MotionPhotoV2;Format=JPG+MP4;KeyPhoto=1.5;VideoCodec=H.264
LivePhotoBox:Split@2026-08-22T12:59:55+07:00@v2.2.1@Source=MotionPhotoV2;Target=None;Image=JPG;Video=MP4;KeyPhoto=1.5
```

**时间线显示：**
```
🟢 Merge · 从 Apple 转 MotionPhotoV2 · 输出 JPG+MP4 · v2.2.1
🔵 Split · 从 MotionPhotoV2 转 None · 输出 JPG + MP4 · v2.2.1
🟠 Repair · 修复 Thumbnail · v2.2.1
```

## 8. 已知问题与注意事项

### 8.1 格式支持矩阵（实测）

| 格式 | 写入 XMP | 说明 |
|------|---------|------|
| JPEG（含华为/荣耀尾标文件） | ✅ | 华为 JPEG 加 XMP 安全，`LIVE_` 尾标保留 |
| 独立 HEIC（苹果双文件 .HEIC） | ✅ | exiftool 可追加/替换 XMP |
| 华为合并型 HEIC（内嵌 MP4） | ✅ | exiftool 无法重写（`Terminator found in Meta`），用字节级注入器 `HeicXmpInjector`（已在 20+ 真机样本验证） |
| MP4 / MOV | ✅ | exiftool 写入 XMP uuid box |

### 8.2 华为 HEIC 字节级注入器（HeicXmpInjector）

- **结构识别**：meta 内 iloc 位于 iinf 之前 → 华为相机布局 → 优先字节注入；其他布局走 exiftool
- 注入方式：iinf 注册 `application/rdf+xml` item（infe 带空 item_name + content_type）、iloc 登记绝对偏移、XMP 数据放 meta 末尾 Adobe XMP uuid box；同步修正 iloc extent 与内嵌 MP4 的 stco/co64 偏移
- **注入前规范化**：heif-enc 产物（JPEG→HEIC）的 iloc 是 v0 且 extent 偏移全为 0，先转成 v1 + 绝对偏移再注入，避免解码报 `Unexpected end of file`；iloc 条目按 v0 / v1/v2 分别计算布局（construction_method 仅存在于 v1/v2）
- **孤儿 XMP 清理**：旧 XMP mime 条目被移除后，mdat 里残留的数据会清零（带重叠安全校验），保证产物只有一份 XMP
- **写后验证**：字节级检查 uuid box 内 XMP 内容完整落盘（**不能**用 exiftool 读回——exiftool 对华为 meta 本身报错，会误判回滚）
- 已验证：华为真机源合成产物 heif-dec 可解码、iinf/iloc item 数一致、无注入引入的 Truncated 警告（华为源尾部的 `Unknown trailer with truncated 'XX 20 20'` 是华为结构固有，非注入问题）
- **嵌入视频重封装**：华为合成前用 ffmpeg `-c copy` 无条件重封装嵌入视频——部分源视频（如 vivo）的 moov 用 64 位 co64 块偏移，libheif 嵌入后识别不了会导致 heif-dec 解码失败；重封装后为标准 stco（32 位）+ 标准 track 结构

### 8.3 旧格式兼容

- 历史页兼容旧数据：`LivePhotoBox:Split@@v2.2.1.0@`（无时间戳、4 段版本）可正常显示；旧 `Action="Combo"` 仍识别为本工具生成
- 旧 `LivePhotoBox:Action/Protocol` 属性在文件被本工具再次处理时迁移进历史条目后删除
- 检测器同时认旧 `LivePhotoBox:Protocol` 属性与新历史 `Target=` 字段

### 8.4 XML 注释的教训

**不要把 XML 注释放在 `rdf:RDF` 内部**——Windows 11 Motion Photo XMP 解析器遇到注释会中止识别，导致 V1/V2/OPPO 失效。移动端相册不受影响。

### 8.5 华为 HEIC 历史页读取（已实现）

exiftool 读不回华为 meta 内 XMP，History 页对华为 HEIC 使用**字节级读取**（注入器的反向操作）：

- `HeicXmpInjector.TryReadXmpTextAsync`：解析 meta 内 Adobe XMP uuid box 内容
- `XmpMarkerService.ReadXmpTextAsync`：HEIC 优先字节级读取，读不到再退回 exiftool
- `HistoryViewModel` 对 HEIC 文件直接走字节级读取（`HeicXmpInjector.TryReadXmpTextAsync`）
- 回归测试：`HuaweiHeicHistoryReadTests`（拆分 → 再合成 → 读回 Merge 历史；真机源无 XMP 不误读）

### 8.6 ExifTool 依赖

标识写入依赖 ExifTool。不可用时：拆分/修复标记写入静默跳过；合成 HEIC 报错（本就需要 exiftool）；JPEG 合成 XMP 由代码直接拼装不依赖 exiftool。

### 8.7 详细记录开关

`IsDetailedHistoryEnabled`（设置页"详细操作记录"）默认开启；关闭时写轻量条目（`LivePhotoBox:Merge@@v2.2.1@`）。**标识符（命名空间）与版本号始终写入**，仅控制详细程度，不影响本软件标识。

### 8.8 完全关闭本软件 XMP 命名空间写入（调试开关）

`IsLpbNamespaceWriteEnabled`（设置页调试工具区"写入本软件 XMP 命名空间"，**默认开启**）。关闭后：

- 合并 / 拆分 / 修复 / 封面**一律不写** `xmlns:LivePhotoBox`、`LivePhotoBox:Version`、`LivePhotoBox:Timestamp` 与 `dc:subject` 历史条目
- 协议自身要求的 XMP（如 Google Motion Photo 的 `GCamera` / `GContainer` 标记）**保留**，产物仍是合法实况照片
- 华为合并型 HEIC 完全不注入 XMP，保留源图原始结构（无 XMP 是预期行为）
- 输出自检跳过"缺少 LivePhotoBox 标识"与单份 XMP 检查（协议标记检查照常），不会误报自检失败
- 文件不再包含本软件标记 → 本软件历史页无法追溯该文件的操作记录

实现入口：`XmpMarkerService`（统一标识 / `EmbedMergeHistoryAsync` / `TryWriteUnifiedMarkerAsync`）、`LivePhotoProtocol.WrapXmp`（协议 XMP 不再注入命名空间）、`LivePhotoMergeService.WriteHuaweiNativeAsync`（华为路径跳过 XMP 构建与注入）。
