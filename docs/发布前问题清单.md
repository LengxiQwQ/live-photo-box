### 实测结构与独立验证

所有区间均为从零开始的字节偏移，采用 `[起点, 终点)`。

| 部分 | 区间 | 长度 | 结果 |
|---|---|---|---|
| Primary JPEG | `[0, 88465)` | `88465` | 合法 JPEG marker/scan 结构，图片为 `1919 × 895` |
| 内嵌 MP4 | `[88465, 211167)` | `122702` | 顶层 box 连续、无越界，存在 ftyp/moov/mdat |
| 实况尾部 | `[211167, 211227)` | `60` | `v2_f00`、`0:1000`、`LIVE_122722`；`122722 = 122702 + 20` |

内嵌 MP4 的顶层布局为 `ftyp → moov → free → mdat`：

| Box | 源文件偏移 | MP4 相对偏移 | 长度 |
|---|---:|---:|---:|
| ftyp | 88465 | 0 | 28 |
| moov | 88493 | 28 | 5091 |
| free | 93584 | 5119 | 8 |
| mdat | 93592 | 5127 | 117575 |

- MP4 brand：`isom`；compatible brands：`isomiso2mp41`。
- 视频：HEVC/H.265 `hvc1`、`1238 × 576`、30 fps、124 帧、约 `4.133333` 秒。
- 音频：HE-AACv2、44100 Hz、双声道。
- 工具：ExifTool 13.55、Python JPEG marker/scan 与 MP4 box 长度检查、ffprobe、FFmpeg。
- `ffprobe -v error -count_frames -show_format -show_streams -of json embedded-video.mp4`：退出码 `0`，读到 124 个视频帧。
- `ffmpeg -hide_banner -v error -i embedded-video.mp4 -map 0:v:0 -map 0:a:0 -f null -`：退出码 `0`，stderr 为空，完整视频与音频解码成功。
- ExifTool 和 ffprobe 直接读取原 JPG 时只报告了 JPEG 封面，不能据此判断没有视频。ffprobe 对单张 JPEG 报告的 MJPEG `video` stream 也不是实况视频存在的证据。

### 源码定位与截断模拟

- 调用入口：[`LightboxItemSource.DetectSingleFileVideo`](../LivePhotoBox/Services/LightboxItemSource.cs)，XMP 未取得长度后，通过尾部 LIVE_ 检查调用下面的 helper。
- 范围定位：[`LivePhotoSplitService.GetHuaweiEmbeddedVideoRange`](../LivePhotoBox.Core/Services/LivePhotoSplitService.cs)。
- 问题分支：只要在文件末尾 `256 * 1024` 字节内搜到 `moov`，便选取 `videoEnd = moovEnd`，把搜索窗口位置当作 box 排列顺序的依据。
- 该样本整份文件小于 256 KB，且 moov 在 mdat 前面。上述逻辑选出的范围为 `[88465, 93584)`，只有 `5119` 字节，完整遗漏 free/mdat；正确视频范围应为 `[88465, 211167)`。
- 按此源码逻辑模拟截取 `5119` 字节后，FFmpeg stderr 报告 `stream 0, offset 0x140f: partial file` 和 `stream 1, offset 0x1422: partial file`。**该命令退出码仍为 0，不能以退出码判断截断视频成功。**
- 这是源码推导与独立工具模拟，不是已安装软件的真实端到端复现，也不代表 Rebuilt Native Inspector 或所有拆分路径均存在同一问题。
