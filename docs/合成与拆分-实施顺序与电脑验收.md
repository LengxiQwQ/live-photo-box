## 对现状调查报告的复核

报告 `合成与拆分功能现状调查报告.md` 可作为缺口线索，不能直接作为全部实现已正确的权威证明。本次为静态抽查与既有证据核对，未重新执行其全部动态实验。

已从当前代码核对：

- `LivePhotoMergeScanService.Scan` 调用元数据匹配，没有实现其调用方所声称的普通同名配对。`MergeCommand.MergeBatchAsync` 却把返回结果标作 filename pairs；GUI 的默认配对方式也没有普通同名流程。
- `ProductSelectionAdapter.Split` 拒绝非 none 协议；`LivePhotoSplitService` 传入 `secondaryPath: null`，GUI 拆分扫描过滤 DualFile。因此双文件输入与 Apple/旧 vivo 目标输出确有入口或实现缺口。
- 当前结构化合成支持六个协议族；Apple、旧 vivo 双文件输出及 Fusion 需要补齐，不能因为枚举、旧包装器或参数存在就宣称可用。

需要纠正或限制的报告结论：

- 单对 `--dry-run` 在调用实际合成前返回，只证明参数与规划路径，不证明写入、解码、画面或声音正确。
- Matcher 的 Container 异常确会向外传播，但 GUI `MergeViewModel.ScanDirectoryAsync` 有 SourceInspectionException/Exception 捕获。可确认扫描中断风险，不能从底层抛出直接断言整个 GUI 进程崩溃。报告未提供可定位的运行日志、候选身份与退出码；其“已完全复现”尚待证据核验。
- “完全支持”“最稳定”“小米/Google 兼容度最高”“特定华为机型原生 HEVC”等表述缺少报告内充分证据。本地 Writer 或自身 Validator 通过不能推导设备支持。
- Apple 输出按实际容器与元数据语义构造，不能硬编码“Track 4”或要求复制来源私有 mebx 历史。Native 承担媒体字节写入，Core 承担编排。
- 原建议漏掉旧 vivo Writer、Fusion 和完整电脑媒体质量验收。高级码率等参数开放、无调用旧文件删除，不作为完成主功能的前置。

## 电脑端如何检查

电脑端应检查正式产品生成的真实文件，而不只是 mock 状态或 Writer 回执。离线独立工具仅用于验证，不进入产品运行依赖。

1. **结构**：从合法 JPEG marker / HEIF item graph / MP4 hierarchy 检查主图、视频实际范围、引用、长度、偏移、目标标记、版本、配对 ID、封面时间和容器边界；不能依赖全文关键字命中或只用自家 Reader 验自家 Writer。
2. **完整解码**：解码实际主图和完整视频、完整音频。HEIF 主图不能误取 tile 或缩略图；完整枚举视频帧及解码错误，不能只 ffprobe 成功或只解码第一帧。
3. **画面与颜色**：来源与输出使用正确方向、镜像、裁切、像素比例及一致的颜色管理比较；对齐视频时间取样，比较尺寸、画面内容及适当误差指标，并导出对照图/接触表人工查看偏绿、偏紫、偏色、黑帧、裁切和二次旋转。必要时对整个短片逐帧检查，不能只依赖平均分数。HDR/SDR 先转换到可比显示条件；允许正常有损转换，不要求像素哈希一致。
4. **播放与时间**：检查帧时间单调性、帧数、时长、起止范围和封面对应，实际在 Windows 播放器抽查。来源有声则验证输出实际音轨、完整解码、声道与音频内容/对齐/漂移；来源无声不伪造声音。
5. **安全与入口**：来源哈希/身份保护、已有目标保护、取消、真实占用/权限/空间失败及批量部分成功报告；GUI 实际操作和 CLI 真执行分别记录。坏文件不能拖垮其他独立任务。
6. **输入构成**：真实相机样本覆盖实际协议和媒体差异；合成的彩条、灰阶、方向/镜像标记、运动和音频脉冲用于定位颜色/时序错误，损坏输入用于失败路径。人工构造样本不替代真实来源覆盖。

A 级内容/声音/同步/方向/封面/结构/安全必须通过。B 使用现成可靠能力并如实记录，C 不扩建完整保留体系。交付表分别标记实现、入口、电脑检查、真机状态，不用单一“支持”混淆。
