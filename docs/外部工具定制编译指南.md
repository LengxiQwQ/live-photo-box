## 1. FFmpeg 功能清单

> 将 gyan.dev full_build 从 **97 MB** 瘦身至 **5.8 MB**（缩减 94%），精确保留项目实际所需的全部功能。

**当前版本**: n8.0.1  
**编译日期**: 2026-07-03

以下按 C# 服务文件逐一列出每个 ffmpeg 参数及其对应的编译组件。

### 1.1 ThumbnailService.cs — 视频缩略图提取

**文件**: `Live Photo Box/Services/ThumbnailService.cs`

```bash
ffmpeg [-hwaccel cuda|qsv|d3d11va|vaapi] -i "{video}" -vframes 1 \
  -vf "scale=80:-1:force_original_aspect_ratio=decrease" \
  -q:v 2 "{thumb.jpg}" -y -loglevel error
```

| 参数 | 功能 | 编译要求 |
|------|------|---------|
| `-hwaccel cuda/qsv/d3d11va/vaapi` | GPU 硬件解码加速 | 对应 hwaccel |
| `scale=...` | 缩放到 80px 宽 | `--enable-filter=scale` |
| `-q:v 2` | JPEG 质量参数 | `--enable-encoder=mjpeg` |
| `.jpg` 输出 | 输出为 JPEG | `--enable-muxer=image2` |

### 1.2 VideoTranscodeService.cs — 视频转码 & Remux

**文件**: `Live Photo Box/Services/VideoTranscodeService.cs`

#### Remux 模式（流拷贝）

```bash
ffmpeg -y -i "{input}" -c copy -map 0:V:0 -map 0:a:0? \
  -map_metadata 0 [-movflags +faststart] "{output}"
```

#### 转码模式

```bash
ffmpeg -apply_cropping 0 -y -i "{input}" \
  -map 0:V:0 -map 0:a:0? -map_metadata 0 \
  -threads {N} -vf "{filter}" -pix_fmt yuv420p \
  -c:v {encoder} {params} {audio_args} \
  -movflags +faststart "{output}"
```

**项目支持的 8 种视频编码器**：

| 编码器 | 类型 | 编译要求 |
|--------|------|---------|
| `libx264` | CPU H.264 | `--enable-libx264` |
| `libx265` | CPU HEVC | `--enable-libx265` |
| `h264_amf` / `hevc_amf` | AMD GPU | `--enable-amf` |
| `h264_nvenc` / `hevc_nvenc` | NVIDIA GPU | `--enable-nvenc` + ffnvcodec |
| `h264_qsv` / `hevc_qsv` | Intel GPU | `--enable-libvpl` |

### 1.3 LivePhotoRepairService.cs — 视频修复

**文件**: `Live Photo Box/Services/LivePhotoRepairService.cs`

```bash
ffmpeg -apply_cropping 0 -y -i "{source}" \
  -map 0:v:0 -map 0:a:0? -map_metadata 0 \
  -threads {N} -vf "{transform_filter},setsar=1" \
  -c:v {encoder} -pix_fmt yuv420p \
  -fflags +genpts -c:a aac -b:a 192k \
```

**视频变换滤镜**：`transpose`（旋转）、`hflip`、`vflip` → `--enable-filter`

## 3. FFmpeg 故障排查

### libvpl 检测失败

```
ERROR: libvpl >= 2.6 not found
```

原因：libvpl 是 C++ 库，configure 测试链接时缺少 C++ 标准库。  
解决：添加 `--extra-libs="-lstdc++"` 到 configure 命令。

### x264 检测失败

```
ERROR: x264 not found using pkg-config
```

原因：配置静态链接时 pkg-config 默认返回动态库参数。  
解决：添加 `--pkg-config-flags="--static"`。

### 编译产物过大

- 检查 configure 输出中的 `External libraries` 列表
- 确保 `--disable-everything` 后没有连带多余组件
- UPX 压缩是最后的瘦身手段

## 5. libheif 编译流程

### 5.1 设计原则

MSYS2 预编译的 `mingw-w64-x86_64-libheif` 包虽然提供了 `heif-enc.exe` / `heif-dec.exe`，但硬链接了全部编解码器（AV1 ×4、VVC ×2、JPEG2000 ×2……），产生 **64 MB 的 DLL 依赖**（33 个文件）。

本编译方案采用以下策略实现最小化：

1. **仅启用 HEVC**：x265 编码 + libde265 解码，禁用所有其他编解码器
2. **仅保留 JPEG 图像 I/O**：heif-enc 只需读 JPEG，heif-dec 只需写 JPEG
3. **全静态链接**：x265、libde265、libjpeg 全部编译进 .exe
4. **UPX 极限压缩**：27 MB → 3 MB

### 5.2 安装 libheif 编译依赖

```bash
# libheif 编译所需的静态库和头文件
pacman -S --needed --noconfirm \
    mingw-w64-x86_64-x265 \
    mingw-w64-x86_64-libde265
```

> **注意**：`mingw-w64-x86_64-libde265` 需要额外处理。MSYS2 的 libde265 头文件默认标记函数为 `__declspec(dllimport)`，静态链接时必须定义 `LIBDE265_STATIC_BUILD` 宏（见下文 cmake 配置）。

### 5.3 克隆 & 编译

```bash

cd libheif-src

cmake -B build -G "Ninja" \
    -DCMAKE_BUILD_TYPE=Release \
    -DBUILD_SHARED_LIBS=OFF \
    -DWITH_EXAMPLES=ON \
    -DENABLE_PLUGIN_LOADING=OFF \
    -DWITH_LIBDE265=ON \
    -DWITH_X265=ON \
    -DWITH_AOM_DECODER=OFF -DWITH_AOM_ENCODER=OFF \
    -DWITH_DAV1D=OFF -DWITH_RAV1E=OFF \
    -DWITH_OPENH264=OFF -DWITH_OpenH264_DECODER=OFF \
    -DWITH_KVAZAAR=OFF -DWITH_OPENJPH_ENCODER=OFF \
    -DWITH_SvtEnc=OFF -DWITH_X264=OFF \
    -DWITH_UNCOMPRESSED_CODEC=OFF \
    -DWITH_JPEG_DECODER=OFF -DWITH_JPEG_ENCODER=OFF \
    -DWITH_HEADER_COMPRESSION=OFF \
    -DWITH_GDK_PIXBUF=OFF \
    -DWITH_LIBSHARPYUV=OFF \
    -DWITH_WEBP=OFF -DWITH_WebP=OFF \
    -DWEBPMUX_LIBRARY="" -DWEBPMUX_INCLUDE_DIR="" \
    -DWEBP_LIBRARY="" -DWEBP_INCLUDE_DIR="" \
    -DWEBPMUX_FOUND=FALSE -DWebP_FOUND=FALSE \
    -DJPEG_LIBRARY=/c/msys64/mingw64/lib/libjpeg.a \
    -DJPEG_LIBRARY_RELEASE=/c/msys64/mingw64/lib/libjpeg.a \
    -DJPEG_INCLUDE_DIR=/c/msys64/mingw64/include \
    -DLIBDE265_LIBRARY=/c/msys64/mingw64/lib/libde265.a \
    -DLIBDE265_INCLUDE_DIR=/c/msys64/mingw64/include \
    -DX265_LIBRARY=/c/msys64/mingw64/lib/libx265.a \
    -DX265_INCLUDE_DIR=/c/msys64/mingw64/include \
    -DCMAKE_C_FLAGS="-static -O2 -DLIBDE265_STATIC_BUILD" \
    -DCMAKE_CXX_FLAGS="-static -O2 -DLIBDE265_STATIC_BUILD" \
    -DCMAKE_EXE_LINKER_FLAGS="-static -s" \
    -DPKG_CONFIG_EXECUTABLE=/c/msys64/mingw64/bin/pkg-config.exe

# 编译（仅构建需要的两个目标）
ninja -j20 heif-enc heif-dec
```

**关键 cmake 参数说明**：

| 参数 | 说明 |
|------|------|
| `-DWITH_X265=ON` | 仅启用 x265 HEVC 编码器 |
| `-DWITH_LIBDE265=ON` | 仅启用 libde265 HEVC 解码器 |
| `-DWITH_*_DECODER/ENCODER=OFF` | 禁用 AV1、VVC、JPEG2000 等所有其他编解码器 |
| `-DWITH_WEBP=OFF` + 空 WEBP 变量 | 禁用 WebP 支持（避免引入 libwebp/libwebpmux DLL） |
| `-DJEG_LIBRARY=...libjpeg.a` | 强制使用静态 JPEG 库 |
| `-DLIBDE265_STATIC_BUILD` | **必需**：防止 libde265 头文件产生 `__imp_` DLL 导入符号 |
| `-DCMAKE_EXE_LINKER_FLAGS="-static -s"` | 静态链接 + 去除符号 |

## 6. libheif 故障排查

### libde265 静态链接报 `undefined reference to __imp_de265_*`

原因：MSYS2 的 libde265 头文件默认标记为 `__declspec(dllimport)`，静态链接时产生未定义的导入符号。

解决：在 `CMAKE_C_FLAGS` 和 `CMAKE_CXX_FLAGS` 中加入 `-DLIBDE265_STATIC_BUILD`。

### JPEG 仍然动态链接（`libjpeg-8.dll` 依赖）

原因：cmake 的 FindJPEG 模块默认优先使用 `.dll.a` 导入库，即使 `JPEG_LIBRARY` 指向 `.a` 静态库，`JPEG_LIBRARY_RELEASE` 仍可能被覆盖为 `.dll.a`。

解决：同时设置 `-DJPEG_LIBRARY` 和 `-DJPEG_LIBRARY_RELEASE` 指向同一个 `.a` 文件。

### WebP 自动检测导致 DLL 依赖

原因：libheif 的 cmake 脚本会自动探测系统中已安装的 WebP 库。

解决：强制设置 `-DWEBP_LIBRARY=""`、`-DWEBPMUX_LIBRARY=""`、`-DWebP_FOUND=FALSE` 并将所有 WebP 相关 cmake 变量置空。

### 编译产物过大（>30 MB）

- 检查是否误链入了 libx265 的 10bit/12bit 变体（MSYS2 x265 包默认包含 multi-bit）
- 确认 `-DCMAKE_BUILD_TYPE=Release` 已设置
- `-s` 链接标志是否生效（`strip` 命令再次去除符号做双重保险）

# 附录

## A. UPX 压缩

所有工具编译后均使用 UPX 进行极限压缩。

```bash
# 安装 UPX
pacman -S --needed mingw-w64-x86_64-upx

# 极限压缩
upx --lzma --best <tool>.exe
```

**各工具压缩效果**：

| 工具 | 未压缩 | UPX 后 | 压缩率 |
|------|--------|--------|--------|
| ffmpeg.exe | ~36 MB | **5.8 MB** | 84% |
| heif-enc.exe | 27 MB | **3.1 MB** | 89% |
| heif-dec.exe | 26 MB | **3.0 MB** | 88% |

> **注意**：部分杀毒软件可能误报 UPX 压缩的可执行文件，可在 Windows Defender 中添加排除项。启动时约 0.1 秒解压延迟，用户无感知。
