## 3. 具体产品行为

| 页面/选项 | 候选选择 | 保留要求 |
|---|---|---|
| 合成/文件名 | 同目录同主文件名，图片和视频各唯一 | 普通媒体允许组合；已有绑定冲突明确说明，不冒充原始配对 |
| 合成/Apple | 按 Apple 内部编号 | 改名也可找回；编号重复不选第一个 |
| 合成/vivo | 按 vivo 内部编号 | 建查找表后只确认唯一对应组合 |
| 合成/严格 | 同目录同名并有原始实况关系证明 | 普通媒体不冒充已有实况 |
| 拆分/全部或某协议 | 按实际协议识别单文件/双文件实况 | 某协议选择尽早限制不相关配对阶段；单文件仍检查真实结构 |
| 拆分/文件名 | 只找同目录同名双文件实况 | 保留源关系证明，文案解释它不是普通媒体合成 |
| 修复 | 使用真实协议关系组织组合，单文件独立诊断 | 默认 Apple/Samsung 范围不变，不被两页选项或隐藏的历史开关暗中改变 |

两页设置互相独立，开始扫描捕获选项。沿用旧索引；未知索引回到既有默认。不迁移旧修复严格键为合成/拆分选项，因为历史实际控制对象不同。

## 4. 执行单元

### S1：同次扫描复用、vivo 查找与协议筛选

1. 建立仅属于当前操作的只读检查会话；缓存文件检查和配对提示，固定来源对象，防止复用期间被写入或替换。操作结束释放所有句柄，不跨扫描长期复用。
2. 合成和拆分多个阶段共享会话；Native 组合检查仍保留，正式执行不使用缓存作为改文件授权。
3. vivo 先按协议、编号和角色分组，重复编号整体冲突，只对唯一图+视频执行组合检查；没有对应编号不遍历所有视频。
4. 拆分按用户选择跳过无关双文件配对阶段，共用已取得的单文件信息。进度包含扫描阶段，配对未完成前不报100%。
5. 统计使用累计计数；诊断按路径索引查询，避免逐项重数整个列表。
6. 本单元不改变 Native 公共接口；保留现有完整检查。真正按范围读取的轻量发现如需公共接口改变，先写明方案和影响，由用户决定，不能静默改变哈希字段含义。

完成条件：原有配对/冲突/锁定/坏文件/取消测试通过；新增真实多 vivo 与重复编号案例；可核对单次文件检查次数和组合次数，不再随图×视频增长；既有真实合成/拆分结果仍可用。

### S2：修复扫描统一与取消收尾

1. 删除固定一秒等待；进入扫描后的所有步骤都由同一取消/失败/结束清理保护。
2. 目录枚举复用逐目录容错，包含 `.heif`；读不了的目录记录原因，其他目录继续，不能等同空目录。
3. 将前置配对和后续诊断共享当前会话，移除重复设备预扫；保留默认 Apple/Samsung 过滤和单文件错误隔离。
4. 修复页使用真实 Native 配对结果，不再依赖固定返回空的 `MatchFromAnalysis`；移除旧严格键在修复扫描中的隐式二次控制。已确认关系仍完整校验。
5. 界面投递包含本次扫描身份和取消状态；取消/新扫描后旧结果不能回填；完成汇总须等待最终界面提交完成。

完成条件：真实 Apple/vivo 改名配对、孤立文件、默认范围、HEIC 开关与逐文件状态仍正确；启动立刻取消不会遗留扫描状态；坏文件不影响正常项。不改修复字节写入或隔离输出规则。

### S3：匹配入口、进度与结果准备

1. 保留两页已有选项，补充清晰中英文解释：拆分的协议匹配本身要求真实源关系，不再另造一个行为完全相同的“严格”选项，不修改旧索引。

3. 进度在后台合并，界面每次只消费最新快照；终态可靠提交，并检查扫描身份。
4. 合成拍摄日期读取在后台完成；去重使用查找表。减少显示列表整表重建，批量更新保持当前排序、筛选和自动滚动行为。
5. 不修改任何缩略图代码，也不把缩略图耗时纳入本次修复成果。

完成条件：GUI 构建通过，资源/绑定一致；两页旧选择含义不变、不同选择各自保留；进度不提前完成，旧会话结果不污染新会话。界面实际滚动和流畅度仍需用户确认。

## 5. 安全和代码约束

### 后续深度优化的具体接口提案（2026-11-07 用户已明确同意，Native ABI 17→18）

新增只读 `lpb_discover_media_candidate_v1(context, path, out_candidate)`，保留全部现有接口及语义。输出字段：结构大小/版本、实际文件类型、候选协议、图片或视频角色、可选配对编号、可选内嵌视频范围、文件身份、文件大小、识别结果与未完成检查标记。它不返回“已完整验证”、清理计划、写入权限或成功保留证明，也不提供未计算的伪造哈希。实现时按现有版本规则更新 ABI 和布局检查。

实现内容：在 Native 中按合法 JPEG 段、HEIF/MP4 容器目录和相关尾结构按需读取；先查询文件长度，所有偏移/长度检查溢出和越界；有读取上限和取消检查，复杂或不确定的结构标记“需完整检查”，不能按未知文件当普通媒体继续。不得用任意位置的字符串命中证明协议。

调用方式：GUI/CLI 扫描仅用它收集和索引候选，必要候选才做既有完整检查；开始实际合成/拆分/修复时，重新使用现有完整检查、身份、权限和事务流程。原有 `lpb_discover_pairing_hint_v1` 中哈希和身份语义保持不变，不能为了快就把哈希清空。

兼容影响：不删除旧能力、不改现有写入接口，不增加运行依赖；需同时更新 Native、C# 声明、ABI 版本/布局检查和定向测试，旧 DLL 与新托管程序必须按现有版本检查拒绝不匹配。协议无法轻读时保留完整检查路径。用户已明确同意本提案，按此范围实施。首版快速提取 JPEG 的 Apple/vivo 配对候选和 MOV/MP4 的合法元数据；HEIF 和复杂结构继续完整检查，不冒充已覆盖所有快速路径。
