# 文档与测试产物管理规范

## 按用途分类

本规范落实当前用户决定；是否为文本不是分类依据。长期要维护的知识留在文档，某次测试的工作资料跟测试产物放在一起。

| 内容 | 位置 | Git |
|---|---|---|
| 项目总纲、正式路线图、Contract、验收条件 | docs/ 对应主题目录 | 提交 |
| 架构与依赖决策、阶段结论、通用开发/测试环境指南 | docs/ 对应主题目录 | 提交 |
| 未完成问题与待办摘要 | docs/发布前问题清单.md 或所属阶段的进度总览 | 提交 |
| 逐样本/逐文件说明、该轮执行计划和覆盖明细、复现步骤 | .ai-tmp/workspace/<Phase>/<Task>/documentation/，与输入/输出为同一任务 | 不提交 |
| 测试生成的图片、视频、截图、二进制、日志、TRX、指标与完整报告 | 当前任务的 .ai-tmp/workspace/；正式封存时进入 .ai-tmp/evidence/<Phase>/<Task>/run-<N>/ | 不提交 |
| 多轮复用的样本与 AI 实验缓存 | .ai-tmp/cache/；阶段实验构建缓存归入 .ai-tmp/workspace/<Phase>/，不得成为正式产品构建的前提 | 不提交 |
| 正式产品的依赖缓存、编译中间文件与构建身份 | artifacts/cache/、artifacts/deps/、artifacts/build/；全部由正式构建流程恢复和生成 | 不提交 |
| 正式 Native 运行库 | artifacts/native/，保持既有配置、架构及生产/测试隔离 | 不提交 |
| 一次性脚本、调试 dump、废弃探针 | .ai-tmp/scratch/ 对应主题目录 | 不提交 |
| 长期复用测试代码、工具、脚本与固定源码 fixture | tests/、tools/、scripts/ 等正规源码目录 | 正常审查后提交 |

## 文档要保留什么

阶段结论应简明交代改了什么、为什么、实际验证范围、结果、限制与未完成项，并指向本地详细记录；不复制整轮命令、逐文件检查表、stack trace或临时环境转储。阶段通过不等于整产品可发布。

未完成问题必须保留影响、已确认事实与未验证部分、下一步和关闭条件。不能因详细证据移到临时目录而把未解决问题丢掉，也不能把历史失败或未运行项写成通过。原始证据不是项目长期设计资产；用户可以清理临时产物，清理后不得继续声称这些原始证据仍可复核。

原始 designs 样本、已确认的厂商协议事实、正式路线图验收条件和源码 fixture 均不是可随意搬走的测试垃圾。路线图里详细但必要的验收条件仍保留在正式文档；某一轮如何逐文件执行及其结果才归临时目录。

控制面的 `.ai/state.json` 与 `.ai/tasks/.../TASK.md` 保留当前状态、范围、约束和资料入口；不要在TASK里长期堆叠整轮日志与恢复流水。已完成任务的完整执行历史可归到同任务临时资料，控制面保留简洁指针。

## 测试任务目录

同一任务的 documentation/、inputs/、outputs/、logs/、results/、metrics/可按实际需要建立，不要求每次凑齐空目录。文件名应描述用途，目录使用稳定阶段/任务名称；不要每条提示词新建时间戳目录。阶段正式封存使用 create-only run-<N>，失败或中断编号不回收。

有明确阶段归属的任务必须先按阶段集中：例如 workspace/P4/R5/、workspace/P5/R4/、evidence/P5/R4/，不得将 P4-R5、P5-R4 等任务平铺在分区根目录。非阶段工作按 CLI/、diagnostics/、environment/、maintenance/ 等用途集中；共享 cache/ 按资源用途分类，不强行归属某一阶段。

迁移后的唯一现行位置是 `<partition>/<Phase>/<Task>`（workspace、evidence、scratch 均如此）。旧平铺位置和隐藏 junction 兼容入口已全部移除，不再保留别名；新建、迁移、引用和索引一律写规范位置。已封存记录中的旧路径字符串只作历史解释，不能据此认为旧位置仍存在；已封存内容与 CMake 缓存不改写，依赖旧绝对路径的构建缓存应重新配置或重新生成，不得通过恢复 junction 继续使用。迁移映射保留在本地 maintenance/ 整理记录中，仅用于解释历史。源码 fixture 与正常生产构建的 artifacts/native/ 保持既有构建契约，AI测试输出不能因此散落在 artifacts/test-results 或项目根目录。

## 整理与规则判断

正式构建由仓库内源码、固定依赖声明与明确的开发工具恢复，不读取 AI 历史工作目录。`.ai-tmp` 不存在时，正常编译必须成立。私有样本及真实设备验证仍按测试任务规范管理，不能为了干净构建而省略必需的真实样本验收。

先盘点用途和引用，再迁移。迁移保留原始文件及 run 编号，记录旧新路径与身份/哈希核查；已封存索引是历史记录，不能为了新路径重写。旧记录中的原路径由迁移映射解释；迁移映射只是历史解释，不代表旧位置仍存在。通过后的缓存和原始产物不必变成永久项目资产；除非用户明确要求清理，不在一次整理中擅自删除。

Agent应判断旧规则是否仍符合当前目标。发现过时状态、互相冲突或不合理要求，向用户说明具体冲突与影响；已有明确用户授权的可逆整理可直接实施并报告。涉及产品方向、Contract/ABI、依赖、验收或安全边界的改变仍由用户决定，不能借“项目经理判断”自行放宽。
