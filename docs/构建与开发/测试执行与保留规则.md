# 测试执行与保留规则

日常按本次修改选择测试。源码文件带 P/R 编号不代表过时；测试价值取决于它保护的实际行为。禁止为绿灯删除有效断言、修改失败预期或把未执行记作通过。

## 入口

从项目根目录运行：

```powershell
# 只构建解决方案，不执行测试（默认）。
.\scripts\verify.ps1 -Scope Build

# 小范围冒烟：Native 加载/ABI、封面时间边界、少量 CLI 参数拒绝。
# 只构建所需测试工程，不构建 GUI，不做真实媒体全矩阵或设备验收。
.\scripts\verify.ps1 -Scope Fast

# 正常开发：明确工程和相关类/方法过滤条件。
.\scripts\verify.ps1 -Scope Targeted -TestProject Core -TestFilter 'FullyQualifiedName~P6NeutralTimingConsumerTests'

# 需要时明确选择扩展检查，例如 >4GB 偏移回归。
.\scripts\verify.ps1 -Scope Targeted -TestProject Core -TestFilter 'Category=Extended'

# 仅在确实需要广泛回归时选择，不作为每个修改的默认命令。
.\scripts\verify.ps1 -Scope Full -AllowBroadTests
```

Targeted 的 TestProject 可为 Core、CLI、Both；Both 要求每个选中工程都匹配测试。遗漏过滤条件或匹配0项会失败，不把空跑当通过。已确认当前候选测试程序集构建完成时，Fast/Targeted 可加 `-NoBuild`；否则会使用旧程序集，不能据此验证新改动。

Fast/Targeted 的命令和 TRX 写入 `.ai-tmp/workspace/diagnostics/test-selection/run-N/`，每次保留独立记录。Fast 不是产品验收，不替代受改模块的真实行为验证。

Full/Release 先构建完整解决方案一次，再以 no-build 运行 Core/CLI；不重复构建 GUI/CLI 和额外运行同一 ABI smoke。Release 额外执行现有 split-only CLI 集成，不能冒充所有合成协议、编辑/修复或真机验收。普通CI仍为Build；标签Release显式选择广泛检查。CI没有私有样本，广泛检查排除 RealSamples、DerivedRealSamples 和 Extended；本机 Full/Release 仍包含这些类别，明确范围不同，不能代签完整本机验收。

Native CTest 回归不在 managed 测试中：影响对应 C++ 范围/校验/像素时，单独构建并选择相应注册项，不要用增加 C# 测试数量替代。ManualUI和性能基准按明确任务执行，均不由Fast启动。

## 哪些保留，何时执行

- 来源身份、范围/溢出、清理权限、Native ABI、目标结构、取消/回滚、覆盖及输出所有权：保留，修改相关链时选取。
- 图片/完整音视频解码、声音/同步/方向/封面：保留，媒体路径改变时验证真实成品；实现全部完成后按当前计划整体电脑验收。
- 大文件、压力、全来源转码、HDR/高位深、Strict完整证明、真实ACL/共享锁：按风险选取，不因一处UI文案或参数修改整套运行。Extended目前标记>4GB稀疏文件用例；不代表所有其他重型用例已统一分类。
- 纯源码字符串/布局写法断言：优先由行为保护替代后精简。反射/ABI权限边界检查仍有独立价值，不一概删除。
- 临时“不支持”能力的测试随功能实现更新；无authority的裸写入拒绝仍是安全边界。不能把两者混在一起删除。
- 旧副本程序、模拟旧实现但不调用当前产品的工具：退出正式验证并删除；本次移除两个旧压力工具，保留显式按需运行的 PathHelper 性能基准。
