### 已查清的关键疑点

1. **旧 vivo 孤立图不等于普通图/坏图。** Native 单文件分支约 5292–5299 明确拒绝带未解绑定尾部的 JPEG，返回 `Ambiguous/Pairing/VivoLegacyCapability`；失败时 C# 不拿部分 out_facts 当有效证据。保留这一拒绝。双文件必须 Native 成功确认 ID 一致才能使用。
2. **不能把全部 `Ambiguous/Pairing` 当“缺视频”。** Apple MakerNote owner 冲突、ID 不一致、未知 JPEG 尾部也可能落在同一类别/阶段。现有结果码不能无歧义区分这些原因；本方案使用“配对未确认/绑定存在歧义”的保守状态，**不解析英文异常字符串决定配对或权限，不新增 ABI**。明确缺少同名一端可直接报未配对；其他无法证明的情况不能伪装精确原因。
3. **NonLive 不足以证明可任意合成。** Native 双输入无 Apple/vivo ID 分支（3570–3596）可能提前返回 NonLive；单文件 Apple 成员也可带 PairingIdentifier 返回 NonLive。普通媒体请求还须检查成功的单文件事实、无来源绑定，再 Probe 视频；不能仅根据双输入 NonLive 或文件后缀接受。已有单文件实况+外部视频不能被当普通同名对，留步骤2定义转换关系。
4. **ID 比较不能由 C# 猜规范。** 当前 Native 双文件比较是精确字符串相等；路径比较可用 Windows OrdinalIgnoreCase，ID 候选分组应 Ordinal，不做大小写折叠、UUID 重写、trim 或截断。Native 双文件确认始终是最终条件。
5. **扫描失败行不能作为失败任务塞给 Runner。** Runner 会执行所有非 Success 行；GUI 还会传整个 `Tasks`。只有 confirmed/request-ready 项能成为任务，诊断须独立保存并显示。
6. **文件安全有整批边界。** `BatchInputProtection` 在任何 writer 前锁住所有队列原件，防止前一输出覆盖后一输入（包括硬链接/重解析别名）。不能为“逐项继续”删除此保护或 catch 后继续写；其失败应作为操作级“无法安全保护输入，未启动处理”报告，并保留队列/原因。普通单项扫描读取失败仍必须隔离。若要求这种安全保护失败后也继续其他写入，必须交高级模型另定原件保护方案，不能伪称已支持。
7. 共享服务还有 `EditViewModel` 和 `CoverInputResolver` 调用者。后者调用严格 Apple matcher，旧安全测试断言 Inspector/strict matcher 抛错；不能全局改变它们为静默返回空结果，更不能让 Edit/Cover 得到普通合成请求作为原厂配对。

## 2. 确定的模式与候选规则

### 2.1 输入与扫描会话

- GUI/CLI 显式传入不可变扫描选项：用途（Merge 请求/协议发现）、配对模式、递归、取消令牌、输入根或明确文件集合。Core 不再靠全局设置或 UI index 决定模式。一次扫描中途不随设置变化。
- 统一枚举/规范化/去重：支持图片 `.jpg/.jpeg/.heic/.heif`，视频 `.mov/.mp4`；后缀只是分流，不是有效性证明。未知后缀记录 unsupported/ignored 原因，不调用错误的媒体解析器。
- 同一完整路径在一次导入（文件夹+显式文件重叠也算）只发现一次；不同路径即使 hash 相同仍是不同候选，不能以 hash 去重消除身份冲突。不新增 Unicode/文件名模糊归一化。
- 递归逐目录枚举，不使用一个失败即丢弃其余目录的 `AllDirectories.ToList()`。选定根不可枚举是该根操作失败；不可访问子目录记录目录级诊断，继续可访问兄弟目录；不擅自追踪目录 junction/symlink 扩大范围或形成循环。多根导入中一个根失败不影响其他独立根，Native 不可加载等全局故障则停止整次操作。
- 目录扫描先完成候选集合，再决定唯一性；结果排序固定，改变枚举/拖拽顺序不能改变配对。增量进度不等于授权执行尚未完成冲突检查的候选。

### 2.2 三种互斥批量模式

| 模式 | 候选关系 | 可执行条件/冲突 |
|---|---|---|
| `name` / GUI index 0 | **同一规范化父目录 + 完整基本文件名（不含最后扩展名）**分组；Windows 路径/名称 OrdinalIgnoreCase | 恰好一张图片、一段视频；同组 `.jpg`+`.heic`、`.mp4`+`.mov` 等均冲突，不选第一项，不跨子目录。两端普通有效且无 live binding → 用户请求配对；Native 确认 Apple/旧 vivo → 真实协议配对。ID 缺失/不一致/来源歧义 → 拒绝该组，不能降级普通请求。 |
| `cid` / index 1 | 在本次明确输入范围中，从成功 Native 单文件事实取非空 ID，再检查候选；允许重命名和本次范围内跨目录 | 仅 Native 双输入确认 `AppleLivePhoto`、primary 存在、motion source_index=1、范围有效者可接受。无 ID 未配对；vivo 不成为 Apple；重复身份相关候选拒绝，不用 name/vivo 兜底。 |
| `vivo` / index 2 | 复用 Native 双输入候选确认，不在 C# 解析 JPEG JSON/MP4 uuid；当前无独立可用的孤立图 ID authority | 仅 `VivoLegacyDualFile` 完整确认；建立成功候选边（图↔视频），任何端度数>1的冲突连通分量全部拒绝；独立唯一组继续。无唯一确认则 unresolved/unmatched，不用 CID/name 兜底。 |

补充规则：

- ID 模式跨目录匹配只在用户本次实际选入的集合中进行，不额外搜全盘。目录+基本名限制专用于 name；不让不同目录同名文件互配。
- name 下普通合成记录 `PairingKind=FilenameCompositionRequest`、`DetectionMethod=FilenamePairing`、`Protocol=Unknown`、无伪造 PairingIdentifier。真正原厂配对记录 `NativeConfirmedSourcePair` 及 Native 协议/范围/ID。**请求关系不是检测事实，更不是清理权限。**
- 普通请求至少要求图片单文件 Inspector 成功、PrimaryImage 有效、Protocol=NonLive、无 PairingIdentifier/来源绑定/未解释尾部；视频单文件有效、无来源配对绑定，再双输入验证和现有 ProbeVideo 成功。HEIF/辅助资产仍由现有 Native 验证，不绕过 inventory gate。
- 合法原厂双文件仍必须完整 Inspector；Apple 单成员的单文件结构/owner冲突不能被双输入早返回掩盖。vivo 允许“单图未确认”的候选进入双输入确认，**不允许 Container/Metadata malformed 或无法读取的文件借此恢复为有效**。多 owner 不能通过先后顺序或普通分支获准；若现有 Native 对实际多 owner 输入无法安全判定，保留拒绝并交高级模型，不补 managed parser。
- vivo 候选矩阵先逐视频检查，把明确读取/容器失败项隔离；每条边边界处理异常、传递 ct，不因坏视频把所有尝试过它的好图标坏。所有拒绝尝试可在日志复核；不把 N×M 个正常 ID 不匹配变成 N×M 条红色错误。按文件/冲突组汇总最终诊断。复用一次扫描内已检查结果，不做无界并行、首命中提前停止或人为只试前 N 个。
- CID 重复判断针对本模式的有效身份候选，不把 generic PairingIdentifier 自动视为 Apple ownership。先保留每个候选的 Native 确认/拒绝信息，再做唯一性；坏文件不提供可用 ID 时只能报该文件失败，不从失败的 out_facts 恢复 ID。
- 不做日期/GPS、编号相近、去掉 `_E`/`_1`、最近时间、文件顺序 zip 等推断。
- **GUI name 拖入多组按同样分组处理；恰好1图1视频也不再用特例绕过不同文件名。** 这是纠正现有 name 模式行为，需文案/回归明确记录。CLI 原有显式二文件合成入口可继续作为 `ExplicitMediaSelection`（调用方已经明确指定两端），不是第四种扫描模式，也不证明原厂关系；同样不能绕过来源身份拒绝。不扩展 CLI positional 参数数量。
- `--include-live` 仅对成功检测为完整单文件 live 的未使用图片加入转换任务；普通孤立图、坏图、冲突/未确认来源不加入。只修过滤和诊断，不在此实现步骤2的转换缺口。
- 同次拖拽合并所有选入文件/目录再判唯一性，不能逐文件夹分别配完再掩盖跨根 ID 冲突。追加时对已有待执行输入重复导入不新增重复任务；已在队列中占用某一端却提出不同关系，报冲突，不自动修改旧关系。发现涉及同一身份的新冲突时阻止受影响待执行关系，要求重新完整扫描；已完成历史不反向改写。扫描/拖拽/执行互斥，防止运行中改队列。

## 3. 结果与异常边界（托管编排，不改 Native ABI）

复用现有 `LivePhotoScanResult` / `LivePhotoDiscoveryResult`，补共用诊断与完成状态，不另建媒体模型体系。新增小型托管类型可放 `LivePhotoDiscoveryModels.cs`（过大再独立文件）：

- 模式/请求种类：明确 `Name/Cid/Vivo`；区分 FilenameCompositionRequest / ExplicitMediaSelection / NativeConfirmedSourcePair。
- `ScanDiagnostic`：稳定诊断 code、严重度、阶段（Enumeration/Read/Container/Metadata/Pairing/Capability）、主要路径、相关路径、组标识、可本地化 reason key/参数、原始 category/stage/capability 和日志关联；不传递异常对象给 GUI。无法取得大小/日期使用 unknown，不填 0 冒充已读。
- 逐项结果至少区分：ready、ordinary/not-selected、unmatched、conflict/unresolved-binding、unsupported、malformed、read-failed。未配对/模式不适用是正常扫描结果，不向外逐个 throw；歧义/读取失败等不可执行项仍有可查看原因。
- 操作状态 Completed / Cancelled / Failed，另有 IsPartial（如子目录失败）。正常结果和诊断一起返回/汇总；已出现诊断即使 ready=0 也不能丢失。文件统计互斥去重，pair 数不等于文件数；不把失败又算普通孤立项。

边界要求：

1. strict Inspector / interop / mutation API 保持拒绝与异常；在发现服务的**单文件/候选组边界**只转换有依据的输入失败。Matcher 可抽共享候选检查 helper，新增 result-oriented 发现路径；旧 `MatchAsync/MatchVivo/DetectDualFileProtocolAsync` 严格入口及其安全含义保留，Cover 不受影响。禁止一个外围 catch 返回空集合。
2. `SourceInspectionException` 的 Malformed/Ambiguous/Unsupported/Io、单项 FileNotFound/Unauthorized/IOException 记录路径与原因；故障到底属于单文件还是候选关系必须按发生边界记录。一个边失败不能污染所有参与过的文件。
3. `OperationCanceledException` 且当前令牌已取消走取消；不是输入失败。不相关 OCE 或未知程序异常不能冒充用户取消。Native DLL/entry point/架构/必需能力初始化失败、内存等不可恢复资源故障按操作失败停止；不把整个运行库不可用报成目录里每个文件损坏。异常类型/明确 capability preflight 用于分类，不靠英文 message 猜原因。
4. 根枚举/全局环境失败经产品边界报告，应用仍可重新操作；未处理的实现错误不做“忽略继续”。保留日志/原始异常，UI 用安全本地化原因，不展示堆栈。
5. 取消或全局失败时保留**此前完整扫描的队列**；本次不完整发现可显示并标“不完整”，不能自动授权尚未完成唯一性验证的关系。已完成整组验证的部分结果若要保留为可执行，必须能证明冲突范围已完整枚举，否则只读显示。不可清空旧成功结果假装取消后没发生任何事。
6. 扫描 facts 只用于发现/展示。执行仍重新走 Inspector-issued plan → Extractor/Cleaner → Neutral → Writer/Validator → 安全发布；不把扫描缓存、文件名、诊断消失或路径列表当 cleanup authority。不修改 Native 拒绝、rollback、CleanupFailed、来源替换/TOCTOU/plan replay 处理。

## 4. GUI：复用红色状态与同一个 TeachingTip

选定做法：**诊断独立集合、在现有任务列表区域呈现同样样式的状态行；不伪造 MergeTask/SplitTask。**

- 两个 ViewModel 增加 `ScanDiagnostics`（可有轻量展示适配器）；成功候选仍转现有任务 `Tasks`。诊断行显示对应图片/视频/目录；孤立视频不能假填 ImagePath，冲突行详情列出所有相关路径。
- 原错误/冲突/未确认行复用 Failed 红色状态颜色/状态圆点；普通未配对/模式过滤显示中性“未配对/未选用”，同样可点开原因，不一律写“合成失败”。本地化覆盖 zh-Hans/en-US。
- `StatusTextBlock_Tapped` 同时适配现有任务和扫描诊断，继续打开本页 **原有 `ErrorDetailTip` / `ErrorDetailText`**，标题/目标圆点/开关与关闭清理沿用；任务仍读取 OutcomeSummary/Details，诊断读取安全的本地化摘要。不得另造 MessageDialog/错误窗口/平行错误面板。
- 诊断集合使用同一队列显示区的行布局/样式，不并入 `Tasks`。只有诊断时不显示遮住原因的“空队列”覆盖层；开始按钮仍以**可执行任务数**启用。扫描计数、处理计数、错误计数分开，不将诊断计入合成成功/完成数。
- 开始/重试/暂停/取消/全选/历史/完成后移动或回收/缩略图与预览只作用于真实可执行任务。`Tasks` 及 Runner 入参不得混入诊断。追加时相关旧关系失效必须明确阻止执行，不只改红色文字。
- UI 使用同一导入扫描会话，传递 token，工作在后台；完成或取消后一次在 UI Dispatcher 合并结果；旧扫描回调不可覆盖较新会话/目录。拖拽异常不能只写 `Drop CRASH` 日志，必须形成可见操作诊断；一个根失败继续其他独立根。
- 拆分本单元只接现有单文件发现/失败隔离/详情，不实现双文件拆分。协议过滤优先使用已成功的 Discovery facts，避免过滤时第二次读取失败丢整批。
- 启动前批量安全保护失败显示操作级安全原因、保留正常队列且不执行任何 writer；不得沿现有 fatal rethrow 变成普通用户未处理异常窗口。真正崩溃/内存损坏不承诺继续。
