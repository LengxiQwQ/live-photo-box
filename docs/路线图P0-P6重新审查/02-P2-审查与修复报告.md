## 5. Roadmap 评估与对 P7 的补充回归建议

### 5.1 Roadmap 合理性评估
- `03-P2-提取器可靠性.md` 与 `01-P2-独立审查与修复清单.md` 的设计边界清晰、契约严密，无需修改验收标准。
- P2 与 P1（`InspectedSource` / `ExtractionPlan`）、P3（`CleanupPlan.IssueFrom` + `CleanupSource` 精确文件身份移交）、P7-R2（`WorkspaceOwnershipRegistry` 精确对象创建与回滚收据）之间的跨阶段契约已完全对齐并闭环。

### 5.2 建议纳入 P7 的新对抗场景
（注：排除已被 `ExtractorAuthorityTests.ConcurrentAttempts_OnlyOnePlanClaimSucceeds` 覆盖的并发 Claim 场景，仅列出真正有增量价值的跨边界攻击面）
1. **Publish 后、`VerifyExtractionOutputs` 前的硬链接注入攻击（LinkCount > 1）**：
   在 `PostPublishBarrier` 回调中不对已发布产物做 `Move`，而是对其创建同卷硬链接（使 `NumberOfLinks == 2`），验证 `VerifyExtractionOutputs` 检测到 `link_count != 1` 后是否精确拒绝并回滚，防止攻击者通过硬链接保留未验证产物的残留副本。
2. **多辅助项（$\ge 3$ 个 Materialized Auxiliary）部分发布失败的级联回滚**：
   构造含多个可物化辅助项的容器，在第 3 个辅助项发布时注入故障，验证前序已发布的 Primary、Motion 及前两个 Auxiliary 是否全部通过各自 `rollback_handle` 完整回滚且在 `WorkspaceOwnershipRegistry` 中逐一核销。
