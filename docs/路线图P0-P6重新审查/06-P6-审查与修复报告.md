#### 【已确认缺陷】P6-F02：`NeutralMediaBundle.Timing` 暴露未检验源时间，下游产品代码直接旁路消费

- **位置：**
  - 模型定义：[ProtocolCleanModels.cs#L344](file:///d:/Projects/live-photo-box/LivePhotoBox.Core/Protocols/Cleaning/ProtocolCleanModels.cs#L344)

  - 生产消费：[LivePhotoMergeRunnerService.cs#L184](file:///d:/Projects/live-photo-box/LivePhotoBox.Core/Services/LivePhotoMergeRunnerService.cs#L184)
- **事实与代码链路：**

  ```csharp
  {
      ...
      Timing = facts.Timing, // facts 来自最初的 source inspection
      Semantics = semantics

  ```
  同时，在 `ProjectTiming`（第 1284–1311 行）中，严密设计了时间保真验证：
  ```csharp
  if (videoWasConverted)
  {
      if (videoConversionTruth?.Timing == ConversionComponentOutcome.Preserved)
          return TimingFromSource(sourceTiming, NeutralEvidenceState.VerifiedPreserved);
      ...

  ```
  然而在 `LivePhotoMergeRunnerService.cs` 第 184 行：
  ```csharp

      bundle.PrimaryImage.Path,
      bundle.MotionVideo.Path,
      finalOutputPath,
  ```

  1. 违反中性媒体契约 N8：“Timing has one semantic... cover/key timestamp, duration 等统一表达，Target Writer 不回头猜来源表示。”
  2. 违反 TASK 验收标准 P6-A8：“Bundle exposes one timing semantic. Source timing is retained only when final-media verification/converter truth proves applicability; never assume it survives transformation.”
  3. 违反 TASK 规则：“If a public compatibility/diagnostic member is retained, it must be explicitly non-authoritative and no Neutral/target correctness decision may read it.”

#### 【待验证疑点】P6-F03：独立双文件视频在图像降级时被标记为 `PartiallyPreserved`

- **位置：** [NeutralMediaService.cs#L150-L154](file:///d:/Projects/live-photo-box/LivePhotoBox.Core/Media/NeutralMediaService.cs#L150-L154)
- **事实与代码链路：**

  ```csharp
  PreservationOutcome videoOutcome = cleanResult.CleanedVideo == null
  ```

  在清理阶段，`cleanResult.PreservationOutcome` 来自 `MetadataPreservationVerifier.VerifyAgainstBaselineAsync`，它给出的是整个请求的总体评估 `OverallOutcome`。

  中性媒体契约 N5 要求：“Preservation must be truthful”。完全未做任何改动的视频资产被标记为“部分保真”，未能准确反映单个资产的保真真相。

## 4. 重点专项审查结果

### 4.1 最终产物对账（Manifest、哈希、长度、时间、朝向）
- **核对结果：**
  - 主图与视频的最终实际物理字节通过 `VerifyArtifactByteIdentityAsync` 在运行时被直接读取计算 SHA-256 与 `FileInfo.Length`，且要求与 `SourceMediaFacts` / 转换器签发的输出证据一致，无硬编码或伪造哈希。
  - 对于带有内嵌增益图（如 HEIC/JPEG）的样本，内嵌资产哈希仅对 Native 报告的精确切片范围计算，未误用整个主图哈希。
  - 朝向信息通过 Native 专用 C ABI `lpb_observe_image_orientation_v1` 进行观察，规范化为四方向顺时针旋转（0/90/180/270）与水平镜像。

### 4.2 GainMap / Auxiliary 的表示与 Owner 关系
- **核对结果：**
  - 严格区分了 `Embedded`、`Detached`、`Both` 三种表示：
    - `Embedded`：仅存在于主图内部，通过 `OwnerByteOffset` 记录偏移，不生成脱机伪文件；
    - `Detached`：独立工作文件，记录精确物理路径与哈希；
    - `Both`：在 JPEG 重新装配后出现，在 Manifest 中作为单个语义条目（`SemanticRepresentation = Both`），指向脱机产物路径同时记录主图内嵌偏移，避免了“同资产被当成两条并重复追加”的隐患（N11 契约闭环）。

### 4.3 失败、取消与 Unsupported 处理
- **核对结果：**
  - 小米 EXIF 异常样本（`P6-S02`）在朝向无法明确验证时，严格抛出 `NotSupportedException`，未伪造默认 0 度通过，且源文件保持未修改。
  - 发生任何中间异常时，`cleanupAuthority` 在方法退出时释放底层租约；临时产物注册于 `MediaWorkspace` 中，由调用者在 dispose 时严格回收。

### 4.4 来源厂商与 Backend 隐藏依赖审查
- **核对结果：**
  - `NeutralMediaService.cs` 与 `NeutralMediaSemantics.cs` 中未包含任何特定品牌名称（"Apple", "Huawei", "Xiaomi", "Samsung" 等）的分支逻辑。
  - 媒体检查完全基于容器类型（`ImageContainer.Jpeg`, `ImageContainer.Heic`）及编码标准。
  - 后端实现名称（如 `MediaFoundation`, `MinimalLibav`, `Wic`）仅存在于底层诊断数据中，未作为中性语义判定的依据（满足 N3, N4, N12, N13）。

## 5. 路线图与设计疑问

1. **公开属性收敛疑问（`NeutralMediaBundle.Timing` vs `Semantics`）：**
   在 P6 重构后，中性语义核心已全面迁移至 `NeutralMediaBundle.Semantics`。但根对象上仍保留了旧版的 `Timing`、`HdrGainMapBinding` 等字段。当前下游 `LivePhotoMergeRunnerService` 仍然直接消费根属性 `bundle.Timing`，存在脱离语义层验证的隐患。建议明确是否在 P6 或 P8 移除或废弃这些根属性，统一强制经由 `Semantics` 读取。
2. **多资产清理保真度细化疑问：**
   当前 `cleanResult.PreservationOutcome` 为单值汇聚状态，在多文件输入（双文件）场景下，无法区隔主图与伴随视频的各自独立保真状态。后续是否需要将 `ProtocolCleanResult` 扩展为分资产报告？

## 6. 初审结论与后续模型复核建议

1. **初审结论：**
   P6 生产代码的主体设计高度符合中性媒体宪法（N1–N14），在跨平台解耦、GainMap `Both` 表示、单语义朝向投影、以及真实样本直通管线上表现扎实。
   但由于 P4 重新审查加固引入了更严格的工作区子文件登记校验，导致既有回归套件中的 `NeutralMediaServiceTests.CreateNeutralBundle_FinalGainMapConsumeRejectsReplacementAfterPreservation` 出现回归红灯（**P6-F01**）；且下游生产消费链存在使用非权威 `bundle.Timing` 的绕过漏洞（**P6-F02**）。因此**当前状态不宜宣布 P6 完结**。
2. **待高级模型复核建议：**
   - 重点核对 **P6-F01** 的测试用例修改方案（是否仅调整测试中的输入样本位置，使之脱离工作区根目录而不触发未登记拦截）；
