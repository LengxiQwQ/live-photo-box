## 1. 项目概述

**Live Photo Box（实况照片工具箱）**是一款专为 Windows 打造的 Apple 实况照片 (Live Photos) 管理与修复桌面应用。基于 **WinUI 3 (Windows App SDK 1.8)** 构建，原生适配 Windows 11 Fluent Design 设计规范，支持 Mica / Acrylic 材质、深色/浅色主题自动切换。

v2.1 起托管代码拆分为 **三个工程**（见第 4 节目录树）：`LivePhotoBox.Core`（共享核心：协议、合成/拆分/修复服务、本地化）、`LivePhotoBox`（WinUI 3 主应用 GUI）、`LivePhotoBox.CLI`（命令行工具 `livephotobox`）。Native 重构从 v2.2.1 后开始增加正式的 Visual C++ 工程 `LivePhotoBox.Native`，与三个托管工程平级并生成独立的 `LivePhotoBox.Native.dll`。GUI 与 CLI 经 Core 的 Interop 层通过稳定 C ABI 调用 Native。

### 核心功能

| 功能 | 说明 |
|------|------|
| **🔗 实况照片合成 (Combo)** | 将任意静态图片 + 视频素材组合为标准实况照片。支持 `Google Micro Video (v1)` / `Google Motion Photo (v2)` / OPPO / vivo / Samsung / HUAWEI 等协议，自动写入完整 `EXIF` + `QuickTime` 元数据 |
| **📸 实况照片拆分 (Split)** | 拆分为独立静态图片（`JPG` / `HEIC`）+ 视频（`MOV` / `MP4`），或输出 **Apple / vivo 双文件实况照片**（写入配对元数据）。智能剥离实况 XMP 元数据，按 `JPEG` 段结构逐段重建 |
| **🛠️ 实况照片修复 (Repair)** | 深度修复 iPhone 实况照片导出到 Windows 后的显示异常（缩略图拉伸、前置旋转、HEIC 方向、UUID 丢失） |
| **🖼️ 封面修改 (Edit)** | 自由更换实况照片封面帧，支持视频时间轴帧选取 + 缩略图条 + 实时播放预览 |
| **💻 CLI (livephotobox)** | 与 GUI 共享 100% Core：`merge` / `split` / `repair` / `cover` / `protocols` / `backend` / `update`，支持批量、`--json`、`--dry-run`、命名模板 |
| **📂 自动整理相册** | 按拍摄设备、日期、实况照片类型自动扫描分类归档（功能开发中） |

## 3. 支持的实况照片协议

| 协议 | 来源 | 说明 |
|------|------|------|
| `Google Micro Video (v1)` | Google（已弃用，但老设备兼容性高） | `MP4` 视频附加在 `JPEG` 末尾，`GCamera:MicroVideoOffset` 记录偏移。旧版小米 MIUI / 旧版 Pixel 使用 |
| `Google Motion Photo (v2)` | Google | 现代标准，`Container:Directory` `XMP` 结构。Google Pixel / Xiaomi HyperOS 3+ 使用 |
| `O-Live Photo` | OPPO / OnePlus | 扩展 `Motion Photo (v2)`，增加 `OpCamera` 命名空间 + `EXIF` `UserComment`。OPPO ColorOS / OnePlus OxygenOS 使用 |
| `vivo Live Photo` | vivo | 扩展 Motion Photo (v2)，增加 `VCamera` 命名空间。vivo X300 系列及之后使用 |
| `Samsung Motion Photo` | Samsung | 扩展 Motion Photo (v2)，附加 `SEF` 尾部（`mpvd` / `sefd` box）。Samsung Galaxy 设备使用 |
| `HUAWEI Moving Photo` | 华为 / 荣耀 | `JPEG`/`HEIC` + `MP4` 视频尾部。支持 **HEIC + H.264** 与 **HEIC + H.265（HEVC）** 输出。华为 / 荣耀设备使用 |
| `Fusion` | 本项目自创 | V2 + OPPO + vivo + Samsung 混合（注册表 Id=0）。**已从 GUI/CLI 隐藏**，代码保留，还原见 `docs/Fusion-Removal-Backup.md` |

> ⚡ 目前任何协议合成的实况照片，均可在 Windows 11 上直接查看动态效果。协议实现位于 `LivePhotoBox.Core/Services/Protocols/`，兼容矩阵见 `ProtocolFormatMatrix`（GUI 与 CLI 唯一数据源）。
>
> **状态说明（2026-08-17 v2.2.0）**：Samsung 合成 🟡 测试中；vivo 合成 ≥X300 🟡 测试中、vivo 双文件拆分 ≤X200 🟡 测试中（作者暂无 vivo 手机，欢迎反馈）。

### Core / CLI 项目

- `LivePhotoBox.Core/LivePhotoBox.Core.csproj` — 共享核心库（`net9.0-windows10.0.19041.0`），被 GUI 与 CLI 共同引用；版本号同样由 `SyncVersionFromManifest` 从 `Package.appxmanifest` 同步
- `LivePhotoBox.CLI/LivePhotoBox.CLI.csproj` — 命令行工具（`AssemblyName=livephotobox-boot`，`net9.0-windows10.0.19041.0`，`PlatformTarget=x64`）；构建后为 4 个别名生成 Go shim 可执行文件（`livephotobox` / `livebox` / `lpb` / `livephoto`，v2.1.5 起移除 `lipbox` / `lpbx`，winget symlink 兼容）

### Native 工程 (`LivePhotoBox.Native`)

- 与 Core 平级的正式 Visual C++ 工程，Visual Studio 可直接浏览、编辑、构建和调试；使用 MSVC x64/C++20，公开接口仅为稳定 C ABI
- `.vcxproj` 直接从 `Package.appxmanifest` 读取版本号，并按已安装 Visual Studio 选择 v143/v145 工具集
- `scripts/native/build-native.ps1` 通过 `vswhere` 自动发现桌面 MSBuild；Core 的独立 `dotnet build` 也通过该脚本保证 Native DLL 已生成
- `LivePhotoBox.Core/Interop/` 使用 `LibraryImport` 加载 Native DLL并执行 ABI、版本和 capability 健康检查，同时封装已迁移的协议能力
- Phase 2 第一条完整链路为 `vivo-legacy`：Native 负责 JPG 私有尾部、MP4 vivo UUID 与 chunk offset 的字节改写；C# 保留业务参数、异步 I/O、日志和 Legacy 回退
- Native DLL/PDB 输出到 `artifacts/native/{Configuration}/win-x64/`；DLL随 GUI/CLI 发布，PDB 仅作为 CI 符号 Artifact 保存

### `App.xaml.cs` — 应用入口
- 继承 `Microsoft.UI.Xaml.Application`
- 职责: 全局初始化（抑制子进程崩溃对话框、语言设置、日志初始化、硬件检测、崩溃处理注册、构造激活 MainWindow）

- 配合 `WindowsAppSdkUndockedRegFreeWinRTInitialize=true`，解决非打包模式 WinRT 激活失败 (0xc000027b)

## 12. Protocols 层（实况照片协议）

> 协议实现位于 `LivePhotoBox.Core/Services/Protocols/`，注册表见 `LivePhotoProtocol.All` / `FromIndex()`。

```
LivePhotoProtocol (抽象基类 + 注册表)
├── MotionPhotoFusionProtocol   (Id=0) — Fusion（V2 + OPPO + vivo + Samsung 混合）
│     已从 GUI/CLI 隐藏（Visibility=Collapsed / 注释），代码保留，还原见 docs/Fusion-Removal-Backup.md
├── MicroVideoV1Protocol        (Id=1) — Google 已弃用格式
│     MP4 视频直接附加在 JPEG 图片末尾；XMP 通过 GCamera:MicroVideoOffset 记录偏移
│     使用者: 旧版小米 (MIUI)、旧版 Google Pixel
├── MotionPhotoV2Protocol       (Id=2) — 现代跨平台标准（CLI 默认协议）
│     使用 Container:Directory XMP 结构 + Item:Semantic="MotionPhoto"
│     使用者: Google Pixel、Samsung Galaxy、Xiaomi HyperOS 3+
├── OppoLivePhotoProtocol       (Id=3) — OPPO/OnePlus 专有
│     扩展 Motion Photo (v2)，增加 OpCamera 命名空间 + EXIF UserComment 标记
│     使用者: OPPO ColorOS、OnePlus OxygenOS
├── VivoLivePhotoProtocol       (Id=4) — vivo（扩展 Motion Photo (v2) + VCamera 命名空间）
│     使用者: vivo X300 系列及之后
├── SamsungMotionPhotoProtocol  (Id=5) — Samsung（扩展 Motion Photo (v2) + SEF 尾部）
│     BuildTrailer 写入 mpvd/sefd box；使用者: Samsung Galaxy
└── HuaweiMovingPhotoProtocol   (Id=6) — HUAWEI（JPEG/HEIC + MP4 尾部）
      支持 HEIC + MP4 (H.264) 与 HEIC + MP4 (H.265) 两种输出；使用者: 华为/荣耀
```

> **v2.2 新增协议相关能力**：Apple 双文件拆分（`AppleLivePhotoMebxWriter` / `AppleLivePhotoMovBuilderV2`，生成可被 iPhone 导入的 MOV）、vivo 双文件拆分（`VivoDualFileMetadataWriter`，≤X200 测试中）、HEIC 无损 CID 注入（`AppleMakerNoteWriter` / `HeifBoxParser`）、HDR 互转（`StandardHdrConversionService`：JPG Ultra HDR ↔ HEIC Apple hdrgainmap；`HdrGainMapCodec` / `UltraHdrJpegWriter` / `HeifAuxImageWriter`）。

## 18. 构建配置要点

1. **自包含发布**: 所有平台均为 `SelfContained=true`，无需用户安装 .NET 运行时
2. **WinAppSDK 自包含**: `WindowsAppSDKSelfContained=true`，无需单独安装 WinAppSDK 运行时
3. **语言裁剪**: 构建后自动删除非 zh-Hans/en-US 的附属资源文件夹
4. **平台**: 仅构建 x64 (win-x64)，不构建 Bundle
5. **ReadyToRun**: 所有配置均为 `false`（禁用预编译）
6. **剪裁**: `PublishTrimmed=false`（不剪裁）
7. **条件签名**: 仅当 `.pfx` 证书文件存在时才启用签名
