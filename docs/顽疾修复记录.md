## 1. WinUI 3 ListView 点击下压偏移动画

**日期**: 2026-07-06  
**影响范围**: `KeyPhotoPage` 文件列表  
**严重程度**: 高（视觉体验核心缺陷）

### 症状

点击 ListView 中的文件卡片时，卡片内容会往右下角偏移约 2-4 像素，像是被"按下去"了一样。松开鼠标后恢复原位。用户要求完全消除此效果，只保留选中态的颜色变化（边框+底色）。

### 试错过程

共尝试了 **7 种方案**，全部未能解决问题：

| # | 方案 | 结果 |
|---|------|------|
| 1 | `ListViewItem` 上设 `Transitions="{x:Null}"` | 无效。下压动画不走 Transitions 系统 |
| 2 | 覆盖 ControlTemplate 的 VisualState，把 `Pressed`/`PointerOverPressed` 设为空 | 无效。动画不在 VSM 状态里 |
| 3 | 换成 `ItemsControl` 替代 `ListView` | 动画消失了，但也失去了 `SelectionMode="Single"` 的内置选中逻辑，需要手动实现 |
| 4 | 用 `Border.Child` 的 `PointerPressed` + `e.Handled = true` 拦截事件 | 点击选中功能被吃掉了（事件被拦截未能路由到 ListViewItem） |
| 5 | `SelectionMode="None"` + 纯手动管理选中 | 过于复杂，不符合 WinUI 惯例 |
| 6 | 在 code-behind 里移除 `ListViewItem` 上的所有 `Transition` | 依然无效。`ListViewItemPresenter` 是 native C++/WinRT 类型，动画在 compositor 层执行，无法从托管代码触及 |
| 7 | 网上搜索 WinUI 社区方案 | WebSearch API 持续报错（`gemini-2.0-flash` 400），无法获取在线资料 |

### 根因定位

转折点：用户观察到点击前 `BorderThickness="0,0,0,0"`，点击后变成了 `"2,2,2,2"`。

**真正的根因不是动画系统，而是布局偏移。**

当 `BorderThickness` 从 0 变为 2 时：
- Border 控件在内容区域外围多出 2px 的边框空间
- 边框**向内侵占**内容区域（WinUI Border 的默认 box model）
- 内容实际可用空间减少 4px（左右各 2px、上下各 2px）
- 视觉上表现为：文字、缩略图等全部内容向右下偏移 2px

这和 WinUI 内置的 `PointerDownThemeAnimation` 效果非常相似（那个动画也是做轻微的 scale/offset），所以一直被误认为是动画问题。

### 最终方案

**双重修复**：

#### 第一层：剥离 ListViewItem 模板
```xml
<Setter Property="Template">
    <Setter.Value>
        <ControlTemplate TargetType="ListViewItem">
            <ContentPresenter x:Name="ContentPresenter"/>
        </ControlTemplate>
    </Setter.Value>
</Setter>
```
- 无 Grid、无 VSM、无 Transitions、无 ListViewItemPresenter
- `ListViewItem` 变成纯粹的透明容器，不再有任何内置动画能力

#### 第二层：BorderThickness 恒定 2px（核心修复）
```csharp
private void UpdateCardVisual(Border card, bool isSelected, bool hovered, bool pressed)
{
    // 边框厚度始终 2px，只改颜色——彻底消除布局偏移
    card.BorderThickness = new Thickness(2);
    card.BorderBrush = isSelected ? _selectedBorder : _transparent;
    // ...
}
```

关键理念：
- **不改变尺寸，只改变颜色**
- 未选中时：`BorderBrush = Transparent`（2px 透明边框，不可见但占据空间）
- 选中时：`BorderBrush = 强调色 88%`（2px 可见边框，空间不变）
- 任何时候 BorderThickness 都是 `Thickness(2)`，内容区域从不变化

### 经验教训

1. **布局偏移 vs 动画效果很难区分。** 当用户说"按下后有位移"，首先检查是否有尺寸/边距/边框厚度在状态切换时发生变化。
2. **WinUI 的 Border 向内侵占内容空间。** 这是 WPF/WinUI 的标准 box model，和 Web 的 `box-sizing: border-box` 不同。
3. **ListViewItemPresenter 是 native 层控件**，托管代码无法完全控制其动画行为。如果某些效果无论如何都关不掉，考虑剥离模板到裸 ContentPresenter。
4. **先检查数据，再怀疑框架。** 7 种方案都在假设"框架动画关不掉"，实际是自写代码里 BorderThickness 变了一下。

### 涉及文件

- `Views/KeyPhotoPage.xaml` — ItemContainerStyle 剥离模板 + DataTemplate 中的 Border 定义
- `Views/KeyPhotoPage.xaml.cs` — `UpdateCardVisual` 方法（核心修复）+ 指针事件处理 + 虚拟化生命周期管理

## 2. WinUI 3 ScrollBar 鼠标离开后自动缩为细条

**日期**: 2026-07-07  
**影响范围**: `KeyPhotoPage` 文件列表滚动条 + 时间轴滚动条  
**严重程度**: 中（视觉一致性缺陷，滚动条粗细闪烁影响操作手感）

### 症状

滚动条默认显示为细条（竖 8px / 横 8px），鼠标悬停时变粗（12px），移开后 167ms 内缩回细条。用户要求滚动条**始终保持粗态**，不要随着鼠标位置切换。

### 试错过程

| # | 方案 | 结果 |
|---|------|------|
| 1 | `ScrollViewer` 上设 `SmallScrollThumbScale=1` + `SmallScrollThumbOffset=0`（XAML 资源覆盖） | 无效。这两个资源键在 WinUI 3 模板中**根本不存在**，是 UWP 的遗留产物 |
| 2 | 代码里设 `ScrollBar.IndicatorMode = ScrollingIndicatorMode.TouchIndicator` | 无效。`TouchIndicator` 切换到的是 2px 细线触控指示器，比默认还细 |
| 3 | 运行时遍历可视树找 ScrollBar，反复设 `GoToState("Expanded")` | 无效。C++ 层会在鼠标事件触发时立刻切换回去，形成闪烁 |
| 4 | 覆盖 `ScrollBarVerticalThumbMinWidth` 等 ThemeResource | 部分有效但不足。元素的默认值用了 `ThemeResource`（可覆盖），但 **VisualState 的 Storyboard 动画关键帧里用了 `StaticResource`**，值已在模板加载时 baked in 为 8。动画执行后仍然缩回 8px |

### 根因定位

深入阅读 WinUI 3 SDK 的 `generic.xaml`（`Microsoft.WinUI\Themes\generic.xaml` 第 31071-31626 行），发现了 ScrollBar 的完整内部结构。

**ScrollBar 模板有两个 VisualStateGroup 控制视觉：**

| 组 | 作用 | 状态 | 谁在控制 |
|----|------|------|---------|
| `ScrollingIndicatorStates` | 选展示模式 | `MouseIndicator`(默认) / `TouchIndicator` / `NoIndicator` | `IndicatorMode` 属性 |
| **`ConsciousStates`** | **控制粗细** | **`Expanded`** ↔ **`Collapsed`** | **ScrollBar C++ native 层** |

默认资源值：
```
ScrollBarSize                    = 12   (展开态宽度)
ScrollBarVerticalThumbMinWidth   = 8    (收起态宽度)
ScrollBarThumbOffset             = 2    (收起态偏移)
ScrollBarContractDuration        = 0:0:0.167
```

**`ConsciousStates` 的状态切换完全由 C++ native 层控制**（鼠标进入→Expanded，离开→Collapsed），托管代码发出 `VisualStateManager.GoToState` 调用后会被 C++ 层立刻覆盖。

### 最终方案

**完全替换 ScrollBar 模板**——将 `ConsciousStates` 视觉状态组从模板中移除，同时把所有元素的默认属性值改为展开态。

核心原理：
```
ScrollBar C++ 层:
  mouse enter → GoToState("Expanded")   → 找不到 ConsciousStates 组 → 无操作
  mouse leave → GoToState("Collapsed")  → 找不到 ConsciousStates 组 → 无操作

元素始终使用 ControlTemplate 中的默认值（展开态），不响应任何状态切换。
```

**模板改动清单：**

| 修改项 | 旧值 | 新值 | 原因 |
|--------|------|------|------|
| `ConsciousStates` VSM 组 | 完整保留（3 状态 + 过渡动画） | **移除整个组** | C++ 层无法再切换粗细 |
| `VerticalThumb.Width` | `ScrollBarVerticalThumbMinWidth`(8) | `ScrollBarSize`(12) | 默认即粗 |
| `VerticalThumbTransform.X` | `ScrollBarThumbOffset`(2) | `0` | 居中而非偏置 |
| `HorizontalThumb.Height` | `ScrollBarHorizontalThumbMinHeight`(8) | `ScrollBarSize`(12) | 横向滚动条默认粗 |
| `HorizontalThumbTransform.Y` | `ScrollBarThumbOffset`(2) | `0` | 横向居中 |
| 所有 Track / Button `Opacity` | `0` | `1` | 轨道和滚动按钮始终可见 |
| Thumb `Opacity` | `0`(默认) / `1`(MouseIndicator 状态) | `1` | 无需等 MouseIndicator 状态设置 |

**实现方式：**
- 在 `Page.Resources` 中定义 `AlwaysThickScrollBarStyle`（`BasedOn="{StaticResource DefaultScrollBarStyle}"`）
- 添加隐式 `<Style TargetType="ScrollBar" BasedOn="{StaticResource AlwaysThickScrollBarStyle}" />` 使页面内所有 ScrollBar 自动应用
- `ForceScrollBarsAlwaysThick()` 简化——不再需要设置 `IndicatorMode`

### 经验教训

1. **`StaticResource` vs `ThemeResource` 是关键区别。** `StaticResource` 在模板加载时 baked in，运行时无法覆盖。如果 Storyboard 动画关键帧用了 `StaticResource`，覆盖 ThemeResource 定义是无效的。
2. **UWP 扩展资源 ≠ WinUI 3 扩展资源。** `SmallScrollThumbScale` 在 UWP 中存在，在 WinUI 3 中被移除。不要假设 UWP 的知识直接适用。
3. **GoToState 的访问权不等于控制权。** 可以通过 `VisualStateManager.GoToState` 调用 ScrollBar 的状态，但 native 层会立即切回。想控制就替换模板。
4. **阅读 SDK 源码是最可靠的手段。** 当官方文档和网络搜索都无法提供答案时，`C:\Users\<user>\.nuget\packages\microsoft.windowsappsdk.winui\<version>\...\generic.xaml` 里能找到一切。
5. **同一个项目里两次用到了"Remove VSM group"模式。** ListView 和 ScrollBar 都是因为 C++ native 层控制视觉状态无法覆盖，最终都通过移除/绕过框架控制的 VSM 组解决。这是 WinUI 3 设计的一个可预测模式：**native 层驱动状态机，托管代码无法介入 → 替换模板移除状态组**。

### 涉及文件

- `Views/KeyPhotoPage.xaml` `Page.Resources` — 完整的 `AlwaysThickScrollBarStyle` 自定义模板（~180 行）
- `Views/KeyPhotoPage.xaml.cs` — `ForceScrollBarsAlwaysThick()` 简化为仅设置 `ScrollBarVisibility`
